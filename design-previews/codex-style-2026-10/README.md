# 知识收集箱 · 两套 Codex 风格设计稿

本目录仅包含设计资产，未修改客户端或后台。内容、数量、日期、回答和引用均为示例；原型不连接真实数据，不执行采集、删除或模型调用。

参考：[OpenAI Codex app 官方介绍](https://openai.com/index/introducing-the-codex-app/)。借鉴其侧边导航、中央工作区和渐进展开的组织方式，不复制品牌标识。

## A · 安静阅读（推荐）

打开即进入资料。移除独立品牌图标栏，把采集、搜索、资料库、知识问答集中到一个侧栏。正文使用窄行宽和充足留白。顶部仅保留问答、证据面板和更多操作。适合目前以保存、检索、阅读为主的使用路径。

- 标题、日期、标签视图在列表上方用小图标切换，悬浮显示名称。
- 知识库切换与设置固定底部；更新仍使用绿色空心圆点。
- 文件、链接和笔记共用资料列表；笔记显示首段作为副标题。
- 字体、版本、重读、Markdown、删除等收进更多菜单，实际实现时按内容类型显示。
- 证据和笔记默认收起，打开时作为辅助面板。

浅灰 #F5F5F3、纸白 #FFFFFF、正文 #252624、次要文字 #8A8B86、边线 #E8E8E4、状态绿 #39725B。界面与正文使用系统中文无衬线，通过字重、字号区分角色；页码、快捷键可用等宽字。

## B · 知识对话

默认进入已有的知识库问答能力。会话列表位于左侧，回答在中央，引用按需打开原文。资料库保留独立入口，可完整阅读 PDF、网页和笔记。更贴近 Codex 的工作区形式，适合经常跨资料提问的用户。

- 左侧展示最近问答和少量最近资料，不长期展开完整知识树。
- 回答内引用序号与来源卡片对应，点击进入原文阅读面板。
- 输入框只用于提问；采集使用独立入口，避免输入意图混淆。
- 保留网关数据发送提示。当前后端每次独立检索，界面不能暗示已有多轮上下文推理。

墨黑 #1C1C1C、侧栏 #171717、正文 #E6E6E3、次要文字 #858581、边线 #30302E、强调绿 #9BCBB6。字体体系与 A 相同。配色不是方案的绑定条件，两套均可做明暗主题。

## 共用功能归位

| 现有能力 | 新位置 |
| --- | --- |
| 文件、链接、笔记采集及异步处理 | 采集弹层与资料行处理状态 |
| 标题、日期、标签浏览 | 资料列表顶部图标 |
| 全局 / 当前内容搜索 | 搜索入口、⌘F、Spotlight 弹层 |
| PDF 原件 / 文字、图片、Markdown | 阅读器按内容类型显示的操作 |
| 缓存更新、手动取新 | 资料行绿色空心圆点 |
| 版本、证据、补充笔记 | 按需展开的右侧面板 |
| AI 分析、知识库问答 | 问答入口及资料的二级操作 |
| 知识域、项目视图 | 知识库切换 / 资料库范围选择二级界面 |
| 标签管理、Agent、账户、备份、OCR、网页设置、回收站 | 底部设置 |

## 原型与验证

打开 scheme-a.html 或 scheme-b.html。支持演示搜索打开、500ms 后显示示例结果、Tab 切范围、回车展开、Esc 清空、采集弹层、更多菜单、引用面板。视图切换只演示选中状态，知识库切换、资料列表、设置子页面等为视觉占位，不代表业务已实现。

PNG 为 1440 × 960 逻辑尺寸、2 倍分辨率。render.cjs 用本机 Chrome + Playwright 导出并验证搜索切换、清空和页面溢出。阅读主视图与问答主视图为两套主稿，附搜索与引用展开两张状态稿。
