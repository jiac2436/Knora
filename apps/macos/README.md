## 独立本地构建（L2）

随包构建直接打开本地知识库，无需账号、开发 Python 或 Docker；旧开发数据不自动导入。本机接口凭证保存在用户私有应用状态文件，模型密钥及 Agent 凭证使用独立 Keychain 项，API/Worker 由应用启动，动态端口仅监听本机，退出后停止。数据位于 `~/Library/Application Support/local.pka.knowledge-inbox`，日志位于同标识的 Library/Logs 目录。

设置 `PKA_RUNTIME_PAYLOAD` 为固定输入构建的运行包，并提供 `PKA_RUNTIME_MANIFEST_SHA256`，执行 `scripts/build.sh`。当前随包版本支持 arm64，后端需 macOS 14.5；最低系统/清洁设备和发行签名、公证尚待验收。本地随包模式的草稿、未发送队列及原件可跨重启恢复；恢复后需手动发送。启动可取消，已连接服务异常退出时每分钟最多恢复 3 次，连续失败后手动重试。日志启动时达到 5 MiB 则轮换，保留 3 份历史记录。唤醒/激活后检查本机健康和身份；队列写入失败时拦截发送和原件删除，恢复写入条件后可重试。

实现与测试见 [L2 集成记录](../../docs/L2客户端服务集成记录.md)。客户端仅打开本地知识库，不提供账户登录、注册、密码找回或外置后台登录回退；开发时也需使用完整运行包。

## 知识域全量分析（2026-10-16）

最新完整客户端为 `dist/知识收集箱-v15-知识域全量分析.app`，已通过编译、严格签名与模拟网关随包验证，构建参数见 [BUILD.md](BUILD.md)。保存工作并退出旧客户端后再切换；首次使用会将旧 v14 库升级到 v15，旧版客户端不能重新打开升级后的库。

1. 切换到要处理的具体知识域，打开“知识库概览”，点击顶部 **全量分析…**。
2. 点击 **预览全量分析**，查看资料总数、**可复用**、**需分析**及具体文件清单。已有有效结果默认复用，缺失或过期的资料需要补做分析。若列出阻塞原因，先等待解析完成、处理超限资料等，再重新预览。
3. 核对发送范围和最大授权预留，点击 **开始全量分析**。正文、备注及相关上下文会按预览范围发送到已配置的 AI 网关；费用取决于服务商实际用量，预留上限不是账单。上次请求结果未知时还需明确确认可能重复产生用量。
4. 进度依次显示 **单篇资料→主题与知识域概览→检索索引**。已完成结果保留；可以关闭进度窗口继续浏览，只要客户端和服务仍在运行，任务就会继续。再次点击 **查看全量分析** 可回到同一任务，刷新进度不会重新调用模型。
5. 完成后回到三页查看：在 **概览** 读全域归纳和原文依据；在 **主题分类** 展开分类、打开文件；在 **知识域信息** 看有效分析数、标签及各层 RAG 状态。页面完成后会更新已有内容，无需重新创建一次任务。

**全量分析**会补单篇，普通 **更新概览…／生成概览…** 只使用已有有效摘要生成主题与域概览，不会补做缺失分析。全量分析是本次独立授权，不会替用户开启自动更新或改写原有策略；有效旧 v2 摘要也可以复用，因此不保证每篇旧资料都会补生成新版 AI 标签。手工标签保持可用。

分析期间修改资料、备注、人工标签或分类可能使本次计划停止。失败、结果未知或部分完成时，请先查看原因，再重新预览；新任务会复用仍有效的结果，系统不会自动重试未知调用。点击 **停止后续步骤…** 保留已完成结果；已发送请求可能继续产生用量，停止不等于撤销调用。退出整个客户端会停止本地服务；重启只恢复能够确认尚未发送的检查点，不重发未知请求。

更多边界见 [全量分析设计](../../docs/design/知识域全量分析-2026-10-16.md)。

## 知识域概览（三页）

三页界面在 v15 中继续保留，构建参数及可信运行包见 [BUILD.md](BUILD.md)。先切换到一个具体知识域，再打开“知识库概览”：

- **概览**：阅读当前知识域的简短归纳、要点及适用限制，打开原文依据核对结论；“更新概览”沿用预览、授权和显式确认流程。
- **主题分类**：展开主题与子分类，叶节点为文件；没有分类的资料放在“未分类”。同一文件可以出现在多个分类下，知识域文档总数按文件去重。点击分类行展开文件，点击该行右侧“概览”查看主题概览，点击文件阅读原文。
- **知识域信息**：查看文档、当前有效分析、主题分类、AI／人工标签及原文／摘要／主题／知识域各层检索索引状态。存储值是已知附件及当前逻辑数据量，不是进程内存或整个 SQLite 文件的精确物理占用；不包含的历史版本、倒排索引和共享文件等开销会明确提示。

三个页面独立保留已加载内容、滚动与树展开状态，读取成功后缓存有效期为 **20 秒**。有效期内快速来回切换复用缓存；过期后进入页面会在后台读取新状态，刷新过程中保留原内容，失败时保留已读结果并显示错误。相同在途读取会合并，分页按分支缓存与去重；手动刷新绕过新鲜度检查，仍不先清空页面。切换知识域、本地库或连接身份后隔离旧响应；授权失效时清除旧内容，避免显示其他范围的资料。

域内问答只检索当前知识域；主题问答检索当前主题及其子分类的文件，去重后与现有标签条件取交集。确认发送时显示实际范围，历史问答也按范围隔离。刷新目录、信息和原文依据不调用模型；确认全量分析、更新概览或发送问题才可能产生模型用量，空主题直接提示资料不足。预算、索引维护和加工节点放在次级入口。范围接口与旧数据兼容说明见 [知识域问答范围接口](../../docs/design/知识域问答范围接口-2026-10-15.md)。

## 飞书 CLI 采集

已接入本机 `lark-cli`（验证版本 1.0.97）。飞书 /wiki/、/docx/、/doc/ 链接通过 CLI 以用户身份读取整篇 Markdown；其他域名的网页仍使用原有网页设置，笔记和文件流程不变。飞书域名下的表格、多维表格等暂不支持，读取失败明确报错，不自动退回网页抓取。

1. 已安装并授权 CLI 的用户可直接粘贴文档链接，保存到知识库。若未授予图片下载权限，可在飞书设置中补充授权。
2. 设置 → 飞书连接：可检查连接、选择 CLI 可执行文件、指定已有配置名称、发起文档只读授权及断开连接。路径留空会查找常见安装位置和 nvm 安装；npm 安装会直接调用包内原生二进制，因此 App 不依赖终端的 Node PATH。首次应用配置仍需自行运行 `lark-cli config init`，App 不自动创建应用。
3. “连接 / 补充读取授权”申请 `docx:document:readonly` 和 `docs:document.media:download`，打开浏览器并自动等待授权结果。可取消本次等待。断开连接需要界面确认，因为它会退出指定配置下所有用户，使用同一配置的其他 Agent 也会受到影响。

凭证由 CLI 管理，App 不读取或上传 Token，也不记录 CLI 原始输出。文档正文会上传到当前 Know 后台。调用无 shell 拼接，设置超时、输出大小限制和可取消的授权等待；临时输出文件使用私有权限并在调用后删除。强制退出或系统崩溃可能留下系统临时目录文件。

保存 Markdown、原始链接、飞书文档 ID、文档版本号及 CLI 版本；正文进入现有关键词和异步语义索引。带选区的分享链接移除锚点并显式读取全文。CLI 返回降级提示时标记部分正文；附件、嵌入表格和评论暂不单独归档。阅读器支持查看飞书 Markdown；重新采集通过再次粘贴链接，暂不提供飞书原文刷新按钮。

图片：获取与正文相同飞书版本的 XML，从 `<img>` 中提取资源标识、段落 ID 和顺序，优先下载原件；CLI 明确返回文档图片无导出权限时，尝试官方 `+media-preview` 获取预览图。其他登录、网络、超时等错误不触发回退。两种方式均使用 macOS Vision 在本机提取 OCR 文字。Markdown 图片位置改为 `know-image://图片ID` 引用，不依赖临时飞书地址。正文保存后逐张上传原件；上传中断可在本次运行重试，幂等上传不重复存储。本地随包模式会恢复队列及缓存图片；未随包的开发模式重启后需要重新粘贴链接。图片获取失败会保留占位和原因，正文标为部分采集。OCR 失败不阻止保存有效图片。

阅读器顶部“图片（N）”可按原文顺序查看原件、原文段落 ID 和 OCR 文字，也可使用系统预览打开；正文图片引用显示为可点击的“查看图片”入口，直接打开对应图片；未保存的图片标明状态，可点击查看原因。长图片说明默认收起，搜索定位保留原正文偏移。已保存的图片直接在正文原位置显示，按阅读位置加载、离开视口释放解码图片；点击可打开图库查看大图。加载失败仍保留可点击的提示。OCR 以“图片 N / 原文块 / OCR 识别文字”标记后加入检索，不改变归档 Markdown。图片文字可能有识别错误，纯图形语义尚未使用视觉大模型理解。

飞书文档的阅读权限与图片导出权限不同：CLI 明确拒绝导出时不能保存原件，需要文档所有者开放下载/导出权限；重新登录无法解除该限制。官方预览接口可独立允许获取预览图片，此时保存来源标记 `retrieval_method=preview`，图库明确提示清晰度可能与原件不同。预览也失败时保留占位与原因。旧记录不会自动补图片，需要重新导入。

图片限制：每篇最多 200 张、单张最多 20 MB、每篇本机下载累计最多 200 MB、单张最多 3000 万像素，支持 PNG、JPEG、GIF 和 WebP；动图 OCR 仅识别第一帧。单张 OCR 最多 20000 字符，超限有明确提示。原件随正文保存到 Know；查看图片使用 Know 账户认证，删除资料时 Worker 清理图片。正常发送完成、移除条目或退出 App 会清理本机临时图片。

后台需要同时更新 API 与 Worker 并重启。飞书正文默认上限 100 万 Unicode 码点（可由 `PKA_MAX_FEISHU_CAPTURE_CHARS` 调整）；客户端上限固定 100 万，超限拒绝而不截断。普通采集仍保持原有上限。

以下命令专门用于**外置 API 的开发模式**，不是完整本地客户端构建流程。

## 使用

1. 打开完整 App 即自动打开本地知识库，无需账户、邮箱或密码。应用自行启动本机服务并准备访问凭证；缺少运行包时显示修复提示，不再回退到登录页。
2. 打开后默认进入阅读界面。左侧顶部的四个独立图标依次按标题、录入日期、自动标签浏览及搜索，悬浮可查看名称；贴底的知识库切换入口与阅读器底部状态栏等高，显示当前知识库。点击后可切换知识库，并同步更新阅读范围和新采集内容的默认知识域；“全部资料”只切换浏览范围。入口还保留项目筛选与创建操作，“管理知识库”按钮暂不可用。标题模式每次加载 50 条，可继续点击“加载更多”；日期和标签模式跨知识域加载全部资料后在本机分组，资料量很大时首次切换可能需要较长时间。点击放大镜或按 ⌘F 打开居中搜索框，Tab 切换全局/当前内容，输入停止 0.5 秒后检索，上下键与回车选择结果，Esc 关闭并清空。当前内容搜索完成后定位首个匹配，选择其他匹配会继续跳转；全局搜索选择结果后打开资料并定位命中段落。PDF 命中会切至文字视图，无法定位文字时回到原件页码。语义命中没有相同字词时定位到相关证据段落。搜索仍结合关键词与后台本地语义索引；语义索引由 Worker 异步建立。已打开资料的正文、笔记、版本列表及读过的证据在本次运行中缓存，切换标题不重复请求，最多保留最近 30 条。客户端约每 20 秒检查已缓存资料的版本元数据；发现后台版本较新时，标题右侧显示绿色空心圆点。点击标题仍使用缓存，点击圆点才读取最新内容。PDF 也可在阅读器中手动“刷新”。
3. PDF 原件使用 macOS PDFKit 纵向连续滚动，可在原件与提取的文字之间切换，支持上一页、下一页及证据页跳转。滚动时页码会同步更新；普通界面刷新不会重新定位 PDF。原件下载到本次运行的私有临时目录，在后台解析，最多缓存 4 份；同一份 PDF 的阅读视图和当前位置也在本次运行中复用，退出时清理。右侧证据与笔记默认收起，点击阅读器右上角按钮展开或收起；较窄窗口以面板显示证据。补充内容会生成新版本，旧证据仍可查看。Markdown 文件直接读取 UTF-8 源文，其他受支持的非 PDF 文档由 anydoc 在本地解析为可搜索文字。
4. 左侧窄栏的采集入口按笔记、链接、文件三类展示。粘贴的内容若为单独的 HTTP(S) 网址，在加入列表时识别为链接；保存后后台异步读取公开 HTML 网页，成功后以网页标题替换网址标题并显示可搜索正文。读取中的采集记录和阅读器显示转圈状态，失败时保留原始网址并可重试。其他文本识别为笔记，标题统一为“笔记”并保留正文预览；文件标题为原文件名。“选择文件”及粘贴文件支持 PDF、Word、PowerPoint、Excel、OpenDocument、RTF、EPUB、CSV 和 `.md`。选择知识域，可按需关联项目；知识域和项目均可在客户端创建。“保存到知识库”也会自动加入当前内容；⌘↩ 可发送。
5. 每条采集记录显示上传进度、识别、保存或失败状态；识别状态轮询逐步退避，约六分钟后仍未完成可手动刷新。再次发送只重试未成功的条目。首次发送后知识域固定，切换选择不改变失败条目的归属。切换本地知识库时，分别保存和恢复各库的采集队列。
6. 设置页提供备份、回收站、模型与 AI、Agent 接入、标签、网页及 PDF 等分类，左右区域可独立滚动。网页读取可选择轻量读取或 Crawl4AI 浏览器读取，并在 Crawl4AI 下开启通用清洗；仅对新保存或重新读取的网页生效。Crawl4AI 读取成功后，网页阅读器顶部可查看其生成的原始 Markdown；如果 Crawl4AI 未生成 Markdown、但已从它抓到的 HTML 提取正文，预览会显示由标题与正文整理的 Markdown，并明确标注来源。成功网页也可从阅读器顶部“重新读取”，按当前设置生成新版本。还可选择 PDF 解析引擎（现有 PDFium 或 pdf-inspector）与 OCR 模型（tiny / small / medium）。新上传的 PDF 自动排队识别；PDF 阅读器顶部的“重新扫描”在原件和文字视图都可使用。数字版 PDF 直接提取文字，扫描页使用本地 PaddleOCR；pdf-inspector 引擎会保留按页 Markdown 结构。

阅读空间的标题、日期和标签列表中，右键资料标题可选择删除。确认后后台立即隐藏该资料，客户端清除该资料的正文与 PDF 缓存；后台 Worker 后续清理文件、版本和索引。删除失败时资料仍保留，错误显示在阅读器底部。

采集列表会自动更新本次运行上传的 PDF 识别状态，也可点击“刷新文件状态”。已上传资料可在阅读空间的知识树和当前资料列表中查看；本地随包模式的采集列表跨应用重启保存，开发模式列表仅在本次运行中保留。

单独的 HTTP(S) URL 作为链接保存，包含文字和链接的混合内容按笔记完整保存。单个文件最大 50 MB，只支持普通文件，不接受目录、符号链接或直接粘贴的截图位图。文件名不作为服务器存储路径。

本机服务的访问凭证由应用自动生成和使用，不要求用户输入账户密码；仅监听本机的接口仍校验凭证。模型 API Key、Agent／浏览器插件凭证和飞书授权各自独立保留，不属于账户登录。旧版本的账户钥匙串条目和开发登录偏好不再读取，也不会主动删除。本机接口设备凭证的首次无交互迁移独立于账户登录；模型密钥需要授权时不再阻塞启动。已有本地知识库无需迁移；待发送列表及文件保存在用户数据目录的 capture-queue，重启后继续手动发送，移除条目时清理对应暂存原件。

## 后台扩展

- `POST /v1/captures` 的 `client.kind` 新增 `desktop`。
- 资料详情、列表和搜索结果新增 `content_type`（`file` / `link` / `note`），保留原有 `capture_type` 以兼容旧客户端。旧 `text` 和 `browser_selection` 映射为笔记，`url` 和 `browser_page` 映射为链接，文件映射为文件；列表中的笔记额外返回短正文 `preview`。无需数据库迁移，也不改写旧记录的存储标题；Mac 客户端按新规则展示旧记录。
- `POST /v1/file-captures?domain_id=...&filename=...`：请求体为原始二进制；需账户 Bearer Token 和 `Idempotency-Key`。首次返回 201，重复返回 200，相同键不同内容返回 409，超限返回 413。单请求单文件，批量逐条发送。
- `GET /v1/sources/{id}/file`：鉴权后以附件返回原始字节，仅所有者可访问，软删除后立即不可访问。
- 详情新增可空 `file` 字段：`filename`、`size_bytes`、`sha256`、`download_path`。
- `GET /v1/sources/{id}/revisions`：返回该资料的版本列表及各版本证据 ID，供 Mac 客户端浏览历史。沿用资料所有权与删除状态校验；证据正文仍通过既有 `GET /v1/evidence/{id}` 读取。
- `POST /v1/sources/versions`：接收最多 50 个资料 ID，仅返回当前正文版本和笔记版本；只查询登录账户未删除的资料，不返回正文或笔记，用于客户端的轻量更新检测。已有数据库无需迁移。
- 非 PDF 文档上传后进入 `document_jobs`，由本地 anydoc 转为 Markdown 并建立正文证据及检索索引；PDF 仍使用原 PDF 引擎，识别完成后产生按页证据。仅保存网址的新 URL 会生成 `web_read_jobs` 任务，状态由 `pending`、`processing` 转为 `usable` 或 `failed`；成功后写入新版本和正文证据，失败时原网址版本仍在。`POST /v1/sources/{id}/web-read` 可手动重试，旧链接也可从阅读器触发首次读取。

OCR 使用 `ocr_preferences` 与 `ocr_jobs` 表；双引擎升级会为两表添加默认值为 `pdfium` 的 `engine` 字段，旧任务继续使用原引擎。文档解析新增 `document_jobs` 表。升级前备份数据库和上传目录，停止旧 API/Worker 后启动新版本；旧 PDF 可在阅读器中手动重新扫描，旧的非 PDF 文件需重新上传才会进入 anydoc 队列。

网页读取增加 `web_read_jobs` 表；API/Worker 启动时由 `create_all` 新建，不修改旧表。升级前备份数据库并重启 API 与 Worker。只读取公开 HTTP/HTTPS 标准端口的网页正文与标题；配置本地 Crawl4AI 服务后，轻量读取无正文或正文少于 80 字时会用后台浏览器补抓。不读取登录页、图片、视频或附件。单页轻量 HTML 上限 8 MB、提取正文上限 20 万字符；网页不可访问或没有可读正文时显示失败并保留网址。部署方式见 [API 文档](../../services/api/README.md)。

Worker 必须在更新代码后重启，旧进程不会自动加载网页任务。若本机代理将公开域名解析到 `198.18.0.0/15` 虚拟地址，可仅在本地 Worker 显式启用 `PKA_WEB_ALLOW_FAKE_IP=1`；该开关只放行域名对应的 HTTPS 虚拟地址，直接 IP、本机及其他内网地址仍会被拒绝。普通网络和生产环境保持默认关闭。阅读器等待超过 2 分钟会提示检查 Worker，而不再无限显示转圈。

```bash
PKA_WEB_ALLOW_FAKE_IP=1 PYTHONPATH=services/api:. .venv/bin/python -m services.worker.main
```

自动标签增加 `source_tags` 和 `source_tag_state` 两张表；API 启动时 `create_all` 创建，并按当前正文为既有资料回填一次标签。新采集、PDF 识别完成及补充资料后，标签按关键词规则重算。规则只覆盖已列出的常见主题；无法判断的资料保持未标记，不调用外部模型。列表和详情新增 `tags: string[]`，旧客户端可忽略；无既有表字段变更。升级前先备份数据库，首次启动时大量历史资料的回填会增加启动耗时。

`PKA_UPLOAD_DIR` 默认 `services/api/uploads`，`PKA_MAX_FILE_BYTES` 默认 52428800。API 和 worker 必须使用同一持久化目录；Compose 已提供共享的 `pka-uploads` 卷。备份时需同时保留数据库和上传目录。软删除的物理文件由现有 worker 清理：

```bash
PYTHONPATH=services/api:. .venv/bin/python -m services.worker.main
```

上传采用有上限的流式写入，API 无新增 Python 依赖；Worker 单独安装 OCR 依赖。正常失败会清理临时文件；进程在写入或事务提交时被强制终止，可能留下未引用的文件，当前未实现自动孤儿文件回收。

## 验证

普通文档解析失败时，阅读器提供“重试解析”：使用已有原件重新排队，保留已有版本和用户补充，进行中的任务不能重复提交。PDF 继续使用“重新扫描”。本地 API 遇到空间不足会提示释放空间后手动重试，采集队列不会自动重发。损坏原件不会因重试自动修复。

本地界面冒烟使用独立测试应用，避免写入正式知识库：

```bash
bash apps/macos/scripts/build_ui_test.sh /绝对路径/已验证的运行包
```

## AI 分析（开发阶段）

阅读器点击“AI 分析”，一次生成简短概述、最多三条要点、最多五个 AI 标签，并自动更新本地知识检索。结果直接显示在阅读器；原文依据、模型、历史和分段结果在分析详情中。新分析不改变领域、项目、原文或人工标签。每库首次确认发送范围；长文需额外确认调用次数。设置中配置 AI 网关地址与访问凭据，凭据按库存入钥匙串；DeepSeek 密钥只在网关服务端配置。

先按 [网关说明](../../services/ai_gateway/README.md) 配置开发服务；模型名称显式指定，没有默认付费调用。该服务尚无会员/充值额度和生产持久幂等。超时或服务中断可能已产生供应商用量，不会自动重试；重新分析可能另行消耗用量。实现及兼容说明见 [A0 首批记录](../../docs/A0手动分析整理实施记录.md)。

## 简短总结与自动 AI 标签

新客户端显式使用分析契约 v3：中文概述和要点总计最多 300 字符，短笔记更短；英文预算 600 字符。模型输出超预算时明确失败，不自动追加付费调用来修复。AI 标签自动生效，无需逐条确认；主题和涉及对象可新建，内容类型复用已有标签。普通标签编辑器可添加人工标签或移除某个来源。重新分析只替换该资料的 AI 关联，保留人工关联；删除 AI 标签后，同一正文版本分析不恢复它。

旧 v1/v2 产物保持可读，默认仅显示简览。旧待确认候选仍在历史详情，不会自动接受。新流程无需数据库迁移。更新客户端后，在原网关终端停止旧进程，再使用原配置重新启动网关；不用重新填写现有凭证。详见 [AI 分析产品化记录](../../docs/A0AI分析产品化实施记录.md)。

模型结果保存后状态为“正在更新知识检索”，待当前总结及必要原文索引就绪才显示完成。失败时只需“重建本地索引”，不会重新调用大模型；原文检索保留。RAG/MCP 使用当前正式标签、总结和真实原文证据，不把总结当作原文。


## 长文分段总结

点击分析后后台生成冻结计划。已有首次授权的短文直接开始；长文展示证据覆盖、原资料采集范围和预计调用次数，确认后开始。短文仍为一次调用；长文最多 8 段，每段 24000 字符/80 个证据块，加一次最终汇总。超过范围明确为部分覆盖。

任务展示已完成调用进度，可停止后续分析。每个分段完成即保存本地产物，界面标记“非全文总结”，只有最终汇总自动发布标签，新分析不生成分类建议。未知或失败请求不自动重发；已完成最终调用但发布中断时，可从保存结果恢复，无新增模型调用。已完成分段进入备份/导出，任务检查点不进入恢复包，恢复后不自动发起付费任务。

本批 schema v6 新增 ai_job_steps，升级前备份；旧恢复包可升级。重启新版客户端及原网关进程后验证。详情见 [长文实施记录](../../docs/A0长文分段总结实施记录.md)。


## 总结与标准标签检索

全局搜索可按标准标签名称或别名筛选，多个标签 ID 按任意匹配。默认只使用人工关联、当前正文版本上已确认的 AI 关联；候选、拒绝和旧版本 AI 标签不进入筛选。搜索结果分别显示原文、总结、标签命中；总结片段单独作为查找线索，打开资料仍定位到原始真实证据。

总结关键词/本地向量索引选用当前有效的最新单次或最终汇总产物，排除分段产物和过期结果。当前沿用严格正文及上下文版本校验，应用分类/项目建议或编辑个人上下文会使同批总结过期，不再默认检索该总结；原文和有效正式标签检索继续可用。索引状态显示等待/失败，可点击“重建总结索引”，此操作只做本地索引，不调用云端大模型。向量模型不可用时保留关键词检索。

本批 schema v7 增加派生索引表，恢复包只保留知识，索引恢复后本地重建。新版客户端内含更新的 API/Worker；手动运行 API/Worker 的开发模式需重启相关进程。详见 [检索实施记录](../../docs/A0总结与标签检索实施记录.md)。
