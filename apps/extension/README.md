# 知径 · Knora 浏览器采集插件

Chrome / Edge Manifest V3 插件，支持用户主动保存当前页面正文或选中片段。插件会先把任务持久化到 `chrome.storage.local`，再上传到本机 App；App 关闭或切换知识库时，待上传任务继续按原知识库隔离。

## 构建与验证

```bash
cd apps/extension
npm test
npm run check
```

不需要安装第三方依赖。构建输出位于 `dist/`，在 Chrome 或 Edge 的扩展管理页选择“加载已解压的扩展程序”，然后选择该目录。

## 本地自动连接（当前方式）

2026-10-30随客户端更名统一品牌。旧桥接引用旧App路径时，重新运行下方安装命令即可更新到Knora；使用原扩展目录重新加载，无需删除扩展或清空待同步队列。

不再使用账号绑定、固定 API 端口或手填 Token。打开插件通过 Chrome/Edge Native Messaging 桥接读取客户端现有的活动库指针与 `agent-api.json`，每次请求动态发现端口。设备凭证仅在本机桥接进程中读取和使用，不交给浏览器，也不新增明文凭证副本。原手工账户记录和旧任务不会自动转换或写入其他知识库。

安装连接组件：`python3 scripts/install-native-bridge.py`（默认使用本项目正式 `apps/macos/dist/Knora.app`，可用 `--application` 指定已安装完整 App）。该操作只生成当前用户的 Chrome/Edge native host 注册与私有启动器，不改 App 安装包、知识库或登录信息。启动器使用现有 App 内置 Python，无需系统 Python；安装命令本身需要 Python 3。本机本轮已执行安装。

当前未打包的扩展沿用原目录派生 ID，不更换 ID、不删除原扩展存储。精确白名单限定当前扩展目录，移动目录后须重跑安装；后续商店发布需要配置正式扩展 ID。新增 `nativeMessaging` 权限，重新加载扩展时请接受浏览器提示。

更新文件后，Chrome 可能仍运行旧后台或旧权限。若启动按钮没有反应，先在 `chrome://extensions` 点击本插件的重新加载按钮，再重新打开插件。新版也会检测缺少连接权限或无效后台回复，显示“重新加载插件”按钮和具体原因；首次连接成功前保存保持禁用。无需删除插件或清空原有数据。

### App 未启动

- 已有连接：保留知识库标识和本库缓存的知识域，可采集并保存到插件本机队列；后台每分钟检查服务，App 启动后自动同步。
- 首次连接：桥接安装后可点击“启动本地 App 并连接”，连接由后台处理，即使 App 弹出使插件窗口关闭也会保留结果；重新打开插件即可使用。首次未知知识库和保存目录时不猜测目标、不提交。
- 没有安装本地桥接：浏览器不能直接枚举或启动任意本机程序，需先完成上面的连接组件安装。界面不会把此状态显示成连接成功。

连接按本地知识库 ID 隔离；App 切换库后不将旧库待同步资料写入新库。恢复后凭证或库身份变化会重新发现，资料保留待重试。不改变后台 Owner/Agent 访问控制，不会向网页暴露凭证。

## 网页缩影与采集提示

保存预览默认展示采集区域的静态网页缩影，保留常用排版、文字颜色、背景色、列表和表格。预览框支持上下滚动，也可切换“保存文字”核对本次文字上传内容。它不是原站的完整镜像：不运行原站脚本，不复制外部 CSS、网页字体、动画或伪元素；复杂定位与特殊渲染可能有差异。图片通过原地址加载，使用 `no-referrer`，需要登录或防盗链的图片可能无法显示。预览使用不授予脚本或同源权限的 sandbox iframe，并设置独立 CSP。

检测到 iframe、开放 Shadow DOM、疑似封闭组件、画布、音视频、未加载图片或采集超限时，预览下方显示感叹号。点击或使用键盘展开完整提示。此版本不采集 iframe 或 Shadow DOM 内部内容；封闭 Shadow DOM 无法可靠检测，只有识别到自定义组件时能提示可能遗漏。没有加载进当前 DOM 的正文和评论无法凭快照补齐。

## Crawl4AI 接入准备（尚未上传 HTML）

插件现在同时生成两份独立内容：

- `preview`：带常用计算样式的展示快照，只留在当前弹窗，不进入上传任务。
- `htmlSnapshot`：去掉脚本、表单、隐藏节点和事件属性的语义 HTML，附带 `schemaVersion=1`、`format=html`、原网址 `sourceUrl`、文档基准地址 `baseUrl`、采集时间 `capturedAt`、采集范围 `scope` 和 `warnings`。链接和图片地址转为绝对地址，保留标题、段落、列表、代码、表格等标签。`scope` 为 `article`、`body` 或 `selection`；它是采集区域快照，不保证整站或整页完整。

HTML 限制为 UTF-8 1 MB；超过上限时整份 HTML 不保存，避免截断产生损坏文件，仍可按现有流程保存文字。最多遍历 12,000 个节点、100 层嵌套，最多给 2,000 个节点复制样式；超限会提示。文字保持原有 100,000 字符上限，超过上限或存在可识别的内容遗漏时标记 `partial_text`。

`htmlSnapshot` 是本地队列条目的可选字段，失败重试和账户隔离继续保留它。文字同步成功后，最近记录最多保留 3 份 HTML，合计不超过 UTF-8 2 MB；其余仅保留同步元数据，因此它不是长期 HTML 归档。Chrome 本地存储总配额仍适用，离线队列较多时可能保存失败。

`POST /v1/captures` 提交文字及整页采集中的 HTTP(S) 图片链接（最多 200 张、按顺序去重），沿用 `content.image_urls`；本地 Worker 下载原件并复用既有图片表、阅读器与重试接口。无数据库迁移。HTML 仍未上传。旧队列没有 `htmlSnapshot` 时仍可正常同步。`core.ts` 的 `createCrawl4AIRequest()` 可将快照转换成现有 Crawl4AI `/crawl` 的 `raw://` 请求，但目前没有调用它。后续接入需增加 Knora 的 HTML 接收与持久化能力，Worker 再提交原始转换与清洗转换，分别保存 Markdown 和清洗结果。

## 浏览器回归验证

单元测试及权限、JavaScript 检查执行 `npm test` 和 `npm run check`。浏览器测试使用虚构账户，模拟现有 API，不访问真实账户或向后台保存数据：

```bash
cd apps/extension
python3 -m http.server 8766 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8766/tests/fixtures/popup.html`，核对缩影、滚动、文字切换和感叹号展开；选择“工作”后保存可验证 HTML 本地队列。页面的 `#browser-test-results` 输出采集回归结果，涵盖语义结构、相对链接、安全过滤、选区、遗漏提示和超限处理。该测试使用浏览器页面模拟插件 API，真实 Chrome / Edge 扩展弹窗仍需加载 `dist/` 后验证。

## 小红书详情采集

识别 `xiaohongshu.com` 及其子域名时，顶部显示本地小红书标识。读取正文限定在可见的帖子详情容器，移除评论、交互操作及推荐区域；支持弹窗和独立详情页。不识别列表为正文，未打开详情或页面结构不匹配时显示“请先点击帖子打开详情”提示并禁止保存，不退回整页或仅链接采集。详情外的选区也会被拒绝。

关闭详情后重新读取会清除旧预览；打开帖子后重新读取即可继续保存。其他网站沿用原正文识别。图片列表优先读取与当前笔记 ID 匹配的页面图片字段，失败时回退至详情媒体区域的 DOM 图片（包含隐藏轮播图）；不读取账号凭证、不增加扩展权限。

浏览器模拟验证（需要本机 Chrome，无第三方 Python 依赖）：`python3 scripts/test-browser.py`。使用独立临时浏览器配置，所有测试页面均映射至本机，不访问真实小红书或登录信息。可通过 `CHROME_BIN` 指定 Chrome 可执行文件。网站页面改版时需要更新详情容器适配规则；本地模拟验证不等同于真实网站实测。

## 小红书图片列表预览

“保存文字”后增加“图片列表”，仅在小红书详情中显示。一次展示一张，右上角显示当前位置/已读取张数；支持点击左右箭头、聚焦图片区域后的键盘左右键，长图上下滚动。首尾不循环，输入备注时方向键不受影响。未读取到图片时显示空状态，单张加载失败会保留位置和原因，允许继续切换。

页面数据提取仅使用 `MAIN` 环境读取当前 URL 对应笔记的图片 URL/总数，不执行页面脚本文本、不返回其他状态或授权信息；最多预览 200 张。如果读取张数少于页面数据中的总数，会明确提示。图片直接使用页面提供的地址，地址失效、防盗链等仍可能导致预览失败。这只是图片预览，没有增加下载归档或更改保存接口。

## 小红书文字分类

读取帖子全文时，单独识别标题、作者、正文、话题标签，以及当前 DOM 中已加载且可见的文字评论。评论保留作者标记、可确认的父评论 ID 和回复对象；没有明确依据时不猜测回复关系。不自动滚动、不展开折叠回复，不把页面总评论数当成已采集数量。

“保存文字”预览和上传采用同一份分区文字，依次显示标题、作者、正文、话题标签、评论区。评论不会拼入作者正文，而是标明来源和回复关系的独立区段。网页缩影仍只展示作者内容。既有文本 API 保持兼容，服务端保存的是带分类标记的文字，尚未新增独立的评论数据库表；浏览器提取结果的 `noteContent` 仅用于生成本次预览与文字载荷。

最多识别 200 条已加载评论，每条最多 2000 字，超限提示；全文保存上限仍为 100000 字符，合并后超限会明确截断并标记部分采集。已保存的旧资料不会自动更新，需重新读取保存。

## 按分类选择保存内容

小红书“保存文字”下方显示本次识别到的分类复选框（标题、作者、正文、标签、评论），每次重新读取默认全选，切换预览保留当前选择。每个分区有稳定 ID（`title/author/body/tags/comments`），对应预览节点的 `data-section` 与本次采集的 `selectedSections`；原始识别结果不修改。预览文字与上传文字使用同一个筛选器。

只把选中的分区序列化到现有文本 API；不新增数据库字段或迁移。取消标题时，资料名称使用“小红书笔记”，避免独立 title 字段继续提交被排除的标题。部分勾选时不保留包含未选内容的本地 HTML 快照；全部取消时禁止保存。其他来源和选中片段沿用原流程。

正文等分区仍保留原来的【标题】/【正文】格式。评论以 `|_` 树状文字展示回复，保留作者标记与回复对象，内部评论 ID 不再直接展示；源数据中的 ID 和父评论关系仍用于构建树。

评论预览中的用户名/回复对象行超过可用宽度时单行省略，鼠标悬停可查看完整名称；评论正文正常换行，保存载荷仍保留完整名称。

## 使用说明与图标

弹窗顶部及连接设置页均提供“使用说明”，打开随插件打包的 `help.html`，包含首次连接、普通网页／选区、小红书分类与图片、离线队列、常见故障及隐私边界。无需联网加载说明页。

插件沿用 App 当前品牌图标，扩展管理页与插件页面使用 16／32／48／128 像素 PNG；工具栏单独保留黑色圆角底，并把内部彩色标识放大至接近画布边缘，提供 16／24／32／48 像素版本，提高固定工具栏位置中的主体占比。资源位于 `static/icons`；macOS 下运行 `python3 scripts/generate-icons.py` 可从现有 AppIcon.png 重新导出；工具栏派生图使用随脚本附带的 Swift 渲染器（需 Xcode Command Line Tools），`--toolbar-only` 仅导出工具栏图，不修改 App 或通用图标。正常构建直接复制生成好的 PNG，无需额外依赖。

已移除开发用的“测试提交”按钮、回读面板和直连测试提交代码。用户保存统一进入已有持久化队列，仍沿用幂等键、失败重试和按知识库隔离的同步流程。更新后须在浏览器扩展管理页重新加载插件，不需要删除插件或清空存储。此变更不更新 App 安装包或新增浏览器权限。

## 图片归档范围与兼容

需要配套的浏览器图片版本 App 后台；仅更新插件而继续运行旧后台，会拒绝带图提交。更新 App 后须重启服务，并重新加载插件。本机桥接也需重跑安装脚本以更新回读字段。旧的纯文字队列与历史资料保持兼容；历史条目没有提交过图片，不会自动补图，需重新采集。

本轮归档公开 HTTP(S) 链接，不复制浏览器 Cookie，不从已解码的浏览器缓存导出图片，不支持 blob/data 或必须登录的图片；过期、防盗链及网络错误会保留失败状态，可在 App 图片界面重试。保留每张 20 MB、整篇 200 MB、3000 万像素、公共地址与跳转校验；正文先保存，图片随后下载。插件当前不上传 HTML，所以图片在正文末尾按采集顺序展示，不承诺原网页精确位置。
