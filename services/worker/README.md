# Knora Worker

Worker 执行本地采集、文件/PDF 解析、网页及图片读取、云端 AI 分析、知识库概览、问答、索引和删除清理。任务与 API 共用业务内核和数据库。

桌面 App 负责启动、就绪检查、父进程监测、停止和失败回收。用户直接打开 Knora 即可使用，不需要手动启动 Worker、Docker 或外部 AI 网关。

## 开发与验证

依赖与回归见[开发与验证](../../docs/开发与验证.md)；外置调试命令见[服务启动指南](../../docs/本地服务启动指南.md)。多个 Worker 不应同时处理日常知识库；测试使用临时目录与合成资料。

模型直接模式复用 `services/ai_gateway` 执行器，不增加常驻网关端口。真实分析需有效模型配置与用户确认；模拟测试不调用付费模型，也不代表真实回答质量验收。

语义检索、扫描 OCR 和复杂文档解析依赖各自的可选扩展；缺少能力时保留原件并提示安装。已有分析和文档不会因停用扩展而删除。详见[扩展说明](../../docs/轻量客户端与扩展使用说明.md)。

## 打包约定

API、Worker、共享模型执行器、Skill 和 macOS 系统辅助程序必须来自同一源码快照。修改后按 [macOS BUILD](../../apps/macos/BUILD.md) 重新组装，验证任务闭环、重启与备份恢复。平台能力边界见 [`app/platform_support`](../api/app/platform_support/README.md)。

网页正文、原图下载和模型视觉分析是不同步骤；保存图片不等于完成视觉分析。网络、权限、版本及未知结果的检查不能通过跳过校验或自动重放收费请求来绕过。
