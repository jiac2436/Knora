## 启动

在项目根目录使用现有 Python 环境。参考 `.env.example`，通过服务器环境变量安全配置 `PKA_AI_PROVIDER_KEY`、`PKA_AI_MODEL`、`PKA_AI_GATEWAY_TOKEN`；模型名由管理员从 DeepSeek 可用模型中选择，不设隐含默认值。示例文件不会被自动加载。真实密钥不要写进命令历史、仓库、客户端配置或日志。

```sh
PYTHONPATH=services/api:. .venv/bin/python -m uvicorn services.ai_gateway.main:create_app --factory --host 127.0.0.1 --port 8091 --workers 1
```

开发排查期间，可在同一终端使用下列命令自动加载网关源码修改：

```sh
PYTHONPATH=services/api:. .venv/bin/python -m uvicorn services.ai_gateway.main:create_app --factory --host 127.0.0.1 --port 8091 --reload --reload-dir services/ai_gateway
```

自动加载会重启服务子进程并清空内存请求缓存；修改代码前应完成当前请求诊断，不在重载后自动重发请求。此模式仅用于本地开发。

缺少密钥、模型或网关凭证时启动失败。客户端配置网关地址与网关访问凭证；DeepSeek 密钥只留在网关服务器。开发期间可使用回环地址；部署远程网关必须通过 HTTPS 和可靠身份认证访问，不能把上述本地启动命令直接暴露到公网。

## 调用与边界

新增 `POST /v1/answer`：使用相同网关访问凭证，契约位于 `services/api/app/rag_contract.py`。知识库问答最多 12 条真实原文证据、单条 3,000/总计 18,000 字符；资料不足需明确说明，引用只能指向输入的真实证据 ID。与分析缓存按路由区分，但共用容量。更新后重启网关才能使用新路由；客户端的 Provider Key 管理方式不变。

`POST /v1/analyze` 使用 `Authorization: Bearer <网关访问凭证>`。协议定义位于 `services/api/app/ai_contract.py`，支持单资料分析与整理建议，最多 80 条证据、共 48000 字符，请求最多 512 KiB，模型响应最多 256 KiB。调用使用 JSON mode，没有工具权限，不自动修改知识。内容作为不可信输入处理，但仍需评估提示注入和模型事实准确性。

采用单进程内存请求缓存，最多 256 个请求编号、同时最多 4 次模型调用。相同编号与相同快照复用处理中任务或已完成结果；不同快照返回冲突，缓存满拒绝新请求。失败也缓存，不自动重试可能收费的调用。超时、断线可能已经产生模型用量，须由用户明确发起新请求。缓存及证据在运行时占用内存，不写磁盘；进程停止、重启或多 worker 之间没有持久幂等保证，重启后重发可能再次产生费用。不要以此机制宣称生产环境恰好一次计费。

v3 仅支持统一分析，使用紧凑总结和标签协议，显式关闭 DeepSeek 思考模式。单篇及最终归纳输出预算为 2048 token，内部长文分段为 8192 token。短笔记提示包含实际字符上限，不超过 300 字符时不展开独立要点。针对实际观测到的格式变体，仅规范化可无损恢复的结构：字段不冲突的相邻完整对象、完整尾部字段对应的提前关闭边界、摘要的 text/citations 对象形态；之后仍严格校验全部字段、引用和长度。重复、冲突、未知字段和截断内容不接受。v1/v2 仍沿用原解析方式。

模型输出校验失败返回 `invalid_provider_result`，附安全的校验阶段、原因码和已知字段名，必要时包含解析位置和固定格式类别，不包含原文或模型响应正文。Worker 将明确的分析校验失败标记为失败，不发布产物、不自动再次调用；其他不确定的超时或断线保留结果未知状态。RAG 除引用列表校验外，还拒绝正文中的未知 UUID 引用或缩写 UUID 引用，不影响已有历史问答读取。接口和数据库格式无变化。

当前仅支持开发主流程验证，未提供用户账号隔离、充值额度、用量预留/结算、持久幂等账本或生产限流。不得作为付费服务上线。模拟测试不产生真实模型费用；`scripts/verify_ai_product_quality.py --real` 通过已配置的网关进行真实调用，会产生模型用量，首篇失败即停止后续调用。真实验收仅使用合成资料，报告保存失败任务的合成快照，不包含访问凭证。网关日志和上游错误响应不应记录资料正文或凭证。

## 知识域节点概览接口（A1开发中）

`POST /v1/summarize-node`使用独立多篇契约生成有原文引用的主题/域概览，认证方式与现有接口相同。共享契约位于`services/api/app/domain_contract.py`，提示词版本`domain-node-evidence-v1`。

该接口是真实模型发送接口，不能当健康检查使用。目前App未接入自动发送；开发验收使用模拟transport。任务持久化和多批合成尚未完成，网关内存缓存不能代替本地请求检查点。详细状态与输入/输出限制见[A1实施记录](../../docs/A1知识库视野实施记录.md)。


### A1层级合成引用预算

节点提示词`domain-node-evidence-v2`支持`max_cited_sources`、`max_cited_evidence`与`max_cited_characters`，默认分别20/80/18000；多批合成使用8/20/6000，保证两个子结果的引用原文能进入下一层的有界输入。网关校验输出的去重引用集合，违规响应失败且不自动重发。新API/Worker发送这些字段前，网关也需重新加载当前源码。模型输出仍需真实资料的语义验收，结构/引用校验不等于观点正确性。

### Mac 内置模型配置

Mac 客户端现支持在“模型与 AI”中直接配置 Chat Completions 兼容模型，无需单独启动网关。此模式下厂商 API Key 存入 macOS 钥匙串，客户端自带服务通过进程内网关调用模型；上述独立网关部署说明仍适用于外部网关模式。见 [Mac 模型配置](../../docs/Mac模型配置.md)。
