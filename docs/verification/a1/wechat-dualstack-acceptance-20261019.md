# 微信双栈 Fake-IP 修复验收

## 原因与范围

用户截图中的公开微信域名在本机同时解析为 `198.18.0.6` 和 `2001:2::10`。正在运行的客户端是已交付的“图文联合分析版”，保存的 Fake-IP 开关为开启；原检查只允许 IPv4 的 `198.18.0.0/15`，IPv6 虚拟地址仍被判为非公网，所以整组解析被拒绝。不是图片分析或模型网关错误。

本次仅修改 `services/worker/web_reader.py` 中的共享地址检查，并增加对应测试：同一显式开关下，允许 HTTPS 域名使用 `198.18.0.0/15` 或 `2001:2::/48`。仍拒绝直接IP链接、HTTP虚拟地址、环回、ULA、链路本地、其他保留范围，以及混有这些地址的解析。每次跳转沿用相同检查，微信正文和图片下载共用此检查。

`2001:2::/48` 是专用基准测试地址，并非普通公网；因此只在既有代理兼容开关开启时放行。范围依据：[IANA IPv6 专用地址登记](https://www.iana.org/assignments/iana-ipv6-special-registry)。这里认定本机代理正在使用该范围的依据是实际DNS结果，并非认定所有代理都使用相同范围。

## 验证

- 工作区网页读取与图片下载相关回归：**56 passed**，1个既有Starlette/AnyIO弃用警告。新增覆盖IPv6单独解析、IPv4/IPv6双栈、混合公网、开关关闭、HTTP及直接IP拒绝，和IPv6内网／保留地址混合拒绝。
- 使用修复后的读取器实际读取截图链接成功：标题“年化100万美金生意：帮别人网站加上登录和收款功能”，正文6075字符、Markdown8583字符、14张图片引用。只读取公开文章，不写用户库、不调用模型。
- 最终App包内独立Python／读取器通过10组双栈开关和内网拒绝验证，并实际成功读取同一公开微信文章，正文6075字符、14张图片引用。没有向用户库写入或触发AI。
- 完整包严格签名与19,932个运行文件／链接清单校验通过。与图文联合分析版对比，运行包仅有 `backend/services/worker/web_reader.py` 一份文件变化，原生可执行文件摘要相同。详见 [构建记录](runtime-wechat-dualstack-20261019.json)。

## 构建基线

完整修复包为 `apps/macos/dist/知识收集箱-v16-微信双栈修复.app`。以已交付的图文联合分析版及其固定运行包清单为基线，原生可执行文件逐字节保留；运行包只替换本次已核验的 `web_reader.py`，重新生成清单、完整封装并签名。工作区另有网关集成开发，构建脚本检查本次读取器相对基线仅有三处预期替换，其他工作区修改不属于此包。

```bash
.venv/bin/python -B apps/macos/scripts/build_wechat_dualstack_hotfix.py
```

命令从仓库根目录运行，要求原图文分析App及原运行包存在且通过固定摘要／签名校验，目标目录必须不存在，不覆盖旧App。脚本与清单一并冻结。此为后台范围受控的热修构建；包含新界面或网关集成的后续版本仍须走完整源码构建及其验收。

## 使用与兼容

等待当前任务完成，用⌘Q退出旧客户端，打开修复包，再点击失败文章的“重试读取”。原失败状态不会因升级自动重试。原有Fake-IP设置继续保存，不需更改代理、重启AI网关、更新插件或重新分析。数据库仍为schema16，插件1.0.5，无迁移或新依赖，图文联合分析能力保留。只支持本次两个明确虚拟地址范围；其他自定义代理范围仍可能被拒绝。
