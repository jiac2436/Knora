# 知识域全量分析交付与验收

日期：2026-10-16（Asia/Shanghai）。用户决策：复用有效结果，补齐未分析和过期资料，再更新主题、知识域概览及本地检索索引。

## 1. 用户操作

最新完整客户端：`apps/macos/dist/知识收集箱-v15-知识域全量分析.app`。

1. 保存工作并退出旧客户端，打开新版，选择一个具体知识域并进入概览。
2. 点击右上角 **全量分析…**，查看资料总数、复用数量、待分析数量及阻塞原因；可以展开具体资料名单和 AI 调用上限。
3. 确认范围后点击 **开始全量分析**。后端依次补齐单篇分析与标签、更新主题和域概览、核验本地索引；已有有效单篇结果不会重新调用模型。
4. 运行中查看阶段与逐篇状态，关闭窗口后任务继续。重新打开可找回同一任务；有任务运行时，普通“更新概览”入口被阻止并发执行。
5. 完成后返回 **概览、主题分类、知识域信息** 查看成果，相关缓存自动失效后后台刷新，已有内容不会先清空。

“更新概览”仍只加工已有有效摘要，不补单篇分析。全量分析不是强制重算全部文件，也不改变原文、人工标签和人工分类。原来的有效 v2 单篇结果仍可复用，因此不会为补 AI 标签而强制收费重算旧结果。

## 2. 执行与授权边界

- 全量任务持久化到独立 `DomainFullAnalysisJob`。冻结资料、备注、原文证据及人工分类等输入的哈希；本任务正常生成的摘要、AI 标签和自动分类不造成自我失效。用户修改输入时停止后续派发，保留已完成结果。
- 预览、最近任务、进度查询不调用模型。创建必须带明确确认、预览哈希和请求 UUID；响应丢失后沿用原 UUID 查询确认，不能自动另建任务。
- 单次授权覆盖待补单篇及后续分层加工，独立于既有自动更新策略和累计预算。不会启用自动分析，也不重置用户原有授权周期。
- 新单篇输出尚未知时，后续概览按现有最多 256 个节点保守预留；预留不是实际账单。实际输入 token 尚未汇总时返回 `null`，不以零冒充。
- 队列逐篇创建，不提前派发所有模型任务。每个子任务发送前重新检查任务状态和冻结范围；单篇或分层调用失败、结果未知即停止后续步骤。
- 停止任务保留已完成结果，不撤销已经发送的请求。已有在途请求时标为结果未知，并同步域状态；重新发起需要明确确认可能重复用量。跟随用户独立创建的分析任务时，停止全量任务不会擅自取消该独立任务。
- 重启后可继续已明确完成的长文检查点及未发送步骤，不重发未知调用。长文分段状态沿用既有枚举，取消父任务不损坏已完成或待执行的检查点。
- 最终索引阶段按当前原文重建一次本地关键词索引，并核验摘要、主题、域索引。语义关闭时保留实际关键词能力并显示 `disabled`；本地索引失败为 `partial`，不能冒称所有索引完成。

## 3. 加载与兼容

客户端独立保存全量任务读取与预览状态；相同读取合并，后台刷新保留旧结果；连接、凭证及知识域按身份隔离，并用读取代次阻止晚到响应。父页面并行读取概览与最新任务，窗口关闭后仍可只读轮询；授权失效时清除全量及概览缓存并显示重新连接。

本地 schema 从 14 升至 **15**，仅增加全量任务表及所属范围／输入不可修改／域删除清理触发器。首次打开已有库按原机制先备份再迁移；旧 v14 客户端不能打开 v15 库。导出恢复包时去掉所有可执行全量任务，保留原文和正式结果；恢复后不会自动重放收费任务。永久删除资料会清除包含其标题和范围的总任务元数据，并停止该任务尚未发送的子步骤。

API、Worker 必须同时更新；完整 App 已包含二者。独立 `ai_gateway` 没有源码或请求契约变更，本轮无需重启网关。
