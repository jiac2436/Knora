# Codex 文章链接兼容修复 — 2026-10-17

## 实际问题与修复范围

读取用户提供的新会话“查找回答数量第二的文章”确认，其最终回答的 Markdown 已包含正确的 `knowledge-inbox://library/…/source/…` 地址；用户截图却只显示普通文章标题。因此，旧会话上下文不能解释这次故障，模型也不是遗漏了链接。此前原生 URL 事件测试证明的是 macOS 打开能力，不能据此宣称 Codex 最终引用可点击。

本轮只修改文章引用通路：

- 保留原生 `app_url`。本机 MCP 桥接为六个读取接口的资料条目增加可选 `citation_url`，使用已经校验的回环 API 地址与规范化的原生文章路径。非文章 URI 不生成导航链接。
- `GET /open/library/{UUID}/source/{UUID}` 返回一个本机导航页面，尝试打开知识收集箱，并保留明确的打开按钮。浏览器可能要求确认或阻止自动打开，此时用户点击按钮继续。不是网页文章阅读器。
- 页面不返回资料标题、正文、凭证或存在性结果，不查数据库；只接受规范 UUID、local 环境及回环客户端/Host，拒绝查询参数，不是任意 URL 重定向。配置 no-store、no-referrer 和限制性的 CSP。
- 原生客户端继续检查当前本地库和文章访问权限；HTTP 页面不会授予 Agent 或网页读取资料的权限。
- Skill 优先使用 `citation_url`，无该字段时再使用原生或原网页链接；内部 ID 继续用于工具调用，不展示为来源。插件版本更新为 1.0.5，身份、授权与主动调用方式不变，不编辑 AGENTS.md 或宿主缓存。

当前 API 端口每次由客户端动态分配。HTTP 引用在本次客户端运行期间有效，客户端退出、重启或切换本地服务后可能失效；重新查询以获取新链接。本轮没有增加常驻固定端口服务或远端跳转站点，不承诺历史 HTTP 引用永久可打开。

数据库仍为 schema16，无迁移、依赖或网关变更，无重新分析资料的需要。
