# 网页读取代理网络设置 — 2026-10-17

## 原因与实现

用户的微信公众号链接被域名地址检查拦截。本机只读 DNS 验证 `mp.weixin.qq.com` 解析为 `198.18.0.6`，处于现有读取器识别的 Fake-IP 段。微信专用 UA 抓取代码在源码和前版完整 App 中均存在；失败发生在 HTTP 请求之前。

后端原有 `PKA_WEB_ALLOW_FAKE_IP=1` 兼容开关，但 App 使用显式子进程环境，不继承终端设置，且没有设置入口。

本轮只补齐这个配置通路：

- 「设置→网页读取」顶部新增“代理网络兼容”，在普通网页／飞书／微信标签外均可见。开关“兼容代理的虚拟 IP（Fake-IP）”默认关闭，按物理本地知识库独立自动保存到设备 UserDefaults。
- 本地服务启动时显式传入 `PKA_WEB_ALLOW_FAKE_IP=0/1`，Worker 通过原有环境继承接收设置。运行值与保存值分别记录；修改后提示用 ⌘Q 退出重开，不自动中断服务或重试任务。将开关改回运行值时，待重启提示消失。
- Fake-IP 被拦截时明确提示代理虚拟地址及设置入口；混有普通私网地址的 DNS 结果仍显示内网阻断，避免错误引导用户开启开关。
- 原规则保留：仅 HTTPS 域名可在明确开启后使用 `198.18.0.0/15`；直接 IP、普通内网、本机地址和非法重定向仍被拒绝。没有全局关闭地址检查，也没有改动微信 UA 或正文解析。

无数据库/API/备份格式迁移、新依赖或 AI 网关改动。设备网络设置不随知识库备份迁移；恢复到新物理库后默认关闭。外置开发 Worker 仍使用原启动环境变量，不使用客户端的本地设置。

## 使用

1. 退出旧客户端，打开 `apps/macos/dist/知识收集箱-v16-代理网络设置.app`。
2. 「设置→网页读取」顶部开启“兼容代理的虚拟 IP（Fake-IP）”。
3. 等待运行中的任务结束，用 ⌘Q 退出并重新打开客户端。
4. 回到失败的文章点击“重试读取”。关闭窗口不等于重启服务；保存开关不会自动重试文章。

无需重启 AI 网关或重新安装 Codex 插件。该开关在普通网络下保持关闭。
