# 微信图文归档 — 2026-10-17

## 交付范围

完整客户端：`apps/macos/dist/知识收集箱-v16-微信图文归档.app`。保留代理网络设置、文章引用导航与插件1.0.5，复用 schema16、SQLite、现有图片清单和原件存储，无新增依赖或数据库迁移。

- 微信正文先可读，图片按原文顺序独立排队。下载成功后使用本地原件在正文原位置显示，点击进入图片窗口。
- 状态显示已保存/总数；单张或批量重试失败图片。在途/已保存图片不会重复入队，单张失败不影响正文成功状态。
- 旧微信文章有原始 Markdown 与图片地址时，可直接“补齐文章图片”。只创建图片任务，不重抓正文、不改变正文版本、证据、已有 AI 分析与标签。
- 当前正文只显示同一基础版本的图片；个人补充沿用基础版本。新版本、删除、切页和切库后的迟到响应受到版本/连接/加载代次校验。
- 图片状态变化只更新已有页面的元数据及新增图像，不重新加载整篇 Markdown；已有图像和页面状态保留。
- 图片与元数据保存在本地，原件进入已有备份。备份快照将未完成的下载改为需手动重试；恢复校验拒绝活动图片下载任务，避免搬运执行状态。已保存原件可直接恢复读取。

## 技术与边界

`app.web_images` 负责从已保存 Markdown 提取版本绑定的图片引用、登记任务和生成本地阅读标记。`services.worker.web_images` 在网络等待前释放事务，逐张下载；使用微信 UA/Referer、既有公网及 Fake-IP 检查，并对每次重定向重新检查。下载后重新验证资料/基础版本，失效时丢弃内容。文件使用随机键、SHA-256及已有 Owner 下载接口。

微信原文 `extracted_text` 和检索证据保持不变；图片 ID 只用于阅读视图，不注入 RAG 原文。图片原件归档不等于理解图片：本轮不做微信图片 OCR、视觉模型分析或图片语义索引。飞书原有 OCR 流程保留。

支持 PNG/JPEG/GIF/WebP，默认单张20 MiB、3000万像素、每篇200张及累计200 MiB。GIF原件保留，阅读器使用静态预览。重复出现的图片按原文出现次数登记；本轮未做跨文章原件去重。超出上限、过期链接、访问验证及网络错误会明确失败，不能保证所有微信公众号均可读取。

仅微信专用 UA 路径新增此链路，普通网页/Crawl4AI图片归档不是本轮范围。已有文章必须保留可解析的图片地址才能补齐；旧地址失效时可手动重新读取文章，但重新读取会生成正文新版本，可能使旧分析过期。

## 使用与部署

1. 等当前任务结束，用 ⌘Q 退出旧客户端，打开上述完整 App。
2. 打开已有微信文章，点击工具栏“补齐文章图片”；新增文章会自动创建图片任务。
3. 阅读正文时查看“图片已保存 X / Y”，完成后在原文位置看图，点击放大。失败时单张或批量重试。
4. 若此前需要 Fake-IP兼容，沿用“设置→网页读取”的网络开关。图片遵守同一网络规则。

完整客户端内置的 API与Worker随包更新，不需再开开发服务；无需重启独立 AI 网关、重新安装 Codex插件或重新分析文档。外置开发模式则需一起重启API和Worker。构建参数见 [macOS BUILD](../../../apps/macos/BUILD.md)。
