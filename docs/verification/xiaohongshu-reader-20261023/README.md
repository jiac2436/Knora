# 小红书阅读方案 A

仅对 `capture_type=browser_page` 且来源为小红书帖子详情地址的资料启用。普通网页、微信、飞书、笔记、选中片段、附件均沿用原阅读布局。编辑、存储、后台与付费模型调用流程不变。

阅读布局：标题保留在现有顶部工具栏，不在正文重复；来源与作者为弱化元信息；正文和话题标签后按顺序显示图片缩略图；评论默认折叠，显示已采集和原帖计数，展开后用户名与回复采用缩进层级，长用户名省略。图片沿用原生鉴权下载、失败提示、大图查看和异步状态更新。

## AI 与数据兼容

- 不修改 `KnowledgeDetail.text`、`pkaRawMarkdown`、正文版本、存储内容、数据库、向量索引或 AI 输入。后台运行包摘要与上一正式版本完全相同，无迁移，无须重跑已有 AI 分析。
- 分区只在阅读 DOM 呈现，按原始 UTF-16 偏移标记文字；原有 SearchLocation 标量转换与重复词句定位保留。
- AI／搜索命中折叠评论时自动展开后定位；标题引用定位来源行，完整标题始终在工具栏。原采集分区标记的历史锚点映射到相应的可见区。
- 评论按字面文本展示；实体和反斜杠不会被误当成 Markdown 转义，防止证据偏移变化。
- 历史阅读位置保留原文签名，评论位置恢复会自动展开；切换到其他网站时重建正确布局，避免缓存串用。
- 旧格式出现重复分区、无法确认分区，或编辑／补充导致图片不再位于末尾时，回退原有阅读器，保留文字与图片，优先不丢内容。此类资料可能仍显示原有采集标记，本轮不强行猜测结构。

## 验证

使用真实 Swift WebReaderTemplate 生成合成样本，在独立浏览器验证标题与分区标记隐藏、作者与标签、图库入口、评论计数与折叠、重复短语定位、评论引用展开、字面实体映射、标题引用、旧锚点、原始文本不变、阅读恢复、跨站隔离以及异常旧格式回退。结果见 `browser-results.json`，截图是同版模板的合成内容，透明页面背景按 App 深色背景展示。

`run_native_tests.py` 使用生产 NativeWebTextReader 和真实 WKWebView，支持模块仅提供未使用的网络／系统打开边界，测试不读取用户库或调用模型。运行小红书评论引用与缓存跨站切换测试，以及现有 SearchPassageReaderTest：重复短语、格式、实体、表情、CRLF、列表、引用、表格、HTML、语义原文、失效偏移回归。

候选基于上一正式原生源码快照，逐文件摘要核对后只覆盖 5 个已有 Swift 文件并新增 XiaohongshuReader.swift；未纳入其他并行源码变动。完整优化构建、严格签名与相同后台运行包校验记录在 runtime-xiaohongshu-reader.json。发布遵循 publish_app.py，正式 App 运行中须先 ⌘Q 退出，不强制结束进程。

## 发布

用户确认退出 App 后，已通过 publish_app.py 发布到唯一正式入口，旧包自动归档，发布来源见 runtime-xiaohongshu-reader.json。只更新原生阅读展示，后台清单与上版相同，现有小红书帖子无需重新采集或重新运行 AI 分析。
