# M0 契约冻结

状态：2026-10-20冻结。为M1—M5提供实施约束；后续字段尚未实现时不能据此宣称功能完成。

## 已有业务契约

- 单篇：`AnalysisRequest` v1—v3，`GatewayResponse`，保留图文及segment/synthesis。
- 问答：`RAGRequest`／`RAGResponse`，证据与请求ID绑定。
- 概览：`DomainSummaryRequest` v1/v2，结果v1，保持导航汇总与原文合成的不同输入语义。
- 原有模型提示词、字符预算、图片校验、引用白名单、任务unknown及重启保护继续执行。
- schema16、插件1.0.5不因M1执行器抽取改变。新迁移须独立记录，不能改版本常量绕过旧数据验证。

## 模型执行边界（M1）

内置Worker与可选HTTP入口使用同一执行器实现。执行器绑定不可变配置，包含三个类型化执行入口、共用请求解析／大小限制及有界幂等缓存。状态归拥有它的事件循环，不能跨循环共享Task。

- 同入口、同配置、同request_id、同输入返回同一结果或同一安全错误，不再次调用供应商。
- 同ID不同输入返回 `request_id_conflict`（HTTP兼容映射409）。
- 容量满返回 `gateway_capacity`（503），不清除已发送/未知记录以放行重发。
- 超时／中断沿用 `provider_result_unknown`，校验失败沿用 `invalid_provider_result`；内置与HTTP安全错误一致。
- 单个等待者取消不取消已发送调用；活跃请求继续占容量。执行器关闭停止接收新任务，关闭中的调用按未知处理。
- 内存缓存不提供跨进程恢复保证；数据库持久任务和Worker中断恢复继续负责unknown阻断。
- Key、正文及图像数据不写执行器日志；完成后清理任务快照中的临时图片二进制。

## 配置与凭证边界（M2）

配置元数据具备 `profile_id`、`config_revision`、provider、base URL、文字/图片模型、能力、凭证引用和明确状态。旧配置按当前物理库隔离迁移，密钥本身不作标识，不进数据库/普通配置/备份/插件/日志。

Provider Key只给执行AI的Worker，私有启动信封有版本和大小限制；Host的本地Owner凭证与Provider Key分开处理。模型Key缺失/拒绝/暂不可用只影响AI能力，不绕过本地Owner认证。

配置保存是本地操作；有成本的连接测试单独触发。内核依据持久任务判断安全切换：已发送按旧配置完成、排队任务保持旧绑定、未知任务不重放；UI忙闲不作唯一依据。

## 宿主及平台边界（M3）

保留现有就绪事件、动态回环端口和Owner认证。后续新增元数据兼容旧事件，包含内核/契约/schema版本、平台/CPU、runtime身份和实际能力，禁止输出凭证。启动取消、双开拒绝、父进程退出回收行为保持。

最小平台接口：Paths/RuntimeLayout、PrivateFiles/Locks、OwnedProcesses、CredentialStore、ExternalCapabilities、DesktopIntegration。平台具体依赖只在实现内导入；缺失适配明确失败，不跳过权限或锁。本期只落实macOS。

## 采集与兼容边界（M4）

客户端拥有未提交草稿与视图状态；内核拥有已提交任务、幂等、原件暂存、归档和重试。迁移旧Swift队列必须保持条目身份与已上传图片记录，确认新状态持久化后再清理旧原件，重启或重复迁入不产生重复资料。

## 发布边界（M5）

全部批次通过后，同版Swift/API/Worker/执行器/平台实现与模型资源组成完整候选，沿用签名、清单与唯一正式 `知识收集箱.app`。免费测试与真实内置模型质量分开记录，M1代码通过不等于M0—M5全部交付。
