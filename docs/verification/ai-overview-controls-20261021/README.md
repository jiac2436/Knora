# AI 概览显隐与原生动画

本次只调整阅读器 AI 概览交互：

- 顶部按钮统一控制整个浮窗。已显示时关闭并清除详情展开状态；关闭后再次点击只显示标题。
- 详情仅由标题右侧的箭头展开、收起。分析中不提供详情箭头，顶部显隐不影响分析任务。
- 读取状态中、读取失败时，顶部同样直接控制可见性，不再先等待接口返回。
- 窗口显隐使用 SwiftUI 原生 `smooth` 过渡约 0.18 秒，详情约 0.22 秒；无弹跳，并遵循系统“减少动态效果”。
- 卡片保留在正文外层 overlay，详情与标题共用同一张卡片，避免两个不同层级的标题参与切换。

未分析资料和“重新分析”仍走原有确认流程。本次未改数据库、API 或运行包契约，无需迁移。

验证使用隔离的合成资料与 URLProtocol 接口替身，不读取用户资料、不调用真实模型。详细结果与范围在同目录验收 JSON 中记录。

## 实际交互验收

完整编译和隔离合成 App 执行均通过，退出码 `0`；完整标准输出及唯一测试桥接编译警告见 test-results.txt（历史产物已清理）。

测试在同一 `NSHostingView` 内按辅助功能标识 `ai-overview-toggle`、`ai-overview-details-toggle` 查找生产按钮，并实际执行 `accessibilityPerformPress()`，覆盖：

- 顶部关闭标题条、关闭已展开详情，重新打开后仅显示标题。
- 独立箭头展开、收起详情；处理中不暴露详情箭头。
- 读取中、读取失败时，顶部点击立即切换显隐，既不新增 GET/POST，也不改变读取状态。
- 处理中显示、隐藏窗口不改变任务 ID 或运行状态。
- 1100/600 点宽度下，隐藏、标题、详情各状态正文几何一致。
- 首次挂载从未知状态恢复已有结果；同一资料读取竞态与失败路径保持原有回归覆盖。

辅助功能桥接只在合成测试进程内启用，不更改系统偏好。实际按钮路径没有通过直接赋值 fixture 状态替代。
