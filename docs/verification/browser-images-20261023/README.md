# 浏览器图片提交与归档

原因：插件 `createCapturePayload` 固定提交空 `image_urls`，API 拒绝非空图片链接。旧能力仅预览。

本轮整页采集提交最多 200 个 HTTP(S) 图片链接，顺序去重；选区不附带整页图片。API 使用现有 `SourceImage` 和 `WebReadMarkdown`，标记 `browser-images-v1` 与 `browser_public`，免费 Worker 逐张下载。原始文字继续作为检索证据，不混入图片链接；阅读文本末尾按顺序生成 `know-image://` 引用。原有图片读取、权限隔离、失败重试、下载预算、重启恢复与备份恢复语义复用，App 对新增图片类型轮询进度。数据库 schema16，无依赖或迁移。

测试提交回读图片链接及 pending/saved/unavailable 状态，明确链接已提交不等于图片原件已保存。本机桥接只回传精简状态，不回传 Owner Token 或图片内容。

验证：95 项后台回归；冻结运行包代码 66 项回归；24 项扩展单测、构建和清单校验；浏览器 fixtures 全过，覆盖图集顺序进入提交载荷及待下载进度；候选包内置 Python 启动真实 local_host/Worker，临时空库中完成公开 PNG 下载、原件读取、正文引用、图片链接回读及幂等测试。当前网络使用虚拟 IP，真实网络测试仅在临时库显式启用已有代理兼容开关，未修改用户设置。初次未开此选项时按预期拒绝并给出配置提示。冻结代码初次测试误在导入后设置测试环境，产生的开发库和 pyc 仅位于隔离运行包，已清理；随后显式使用内存数据库、禁用语义模型与 `-B` 重跑通过，完整清单及签名重新校验。

仅包含 7 个后台文件与 1 个 Swift 文件。候选基于已发布完整运行包和原生源码快照，其他并行未发布改动未纳入。发布前发现正式 App 已新增阅读位置恢复，已重新基于该版原生快照构建，仅修改 LocalWebImages.swift；保留全部已发布阅读恢复功能，后台父清单保持相同。正式包使用 `publish_app.py` 发布；App 运行中时需先 ⌘Q 退出，禁止强制终止或手工覆盖 dist。

限制：没有复用浏览器 Cookie、缓存或解码图片；blob/data、须登录、防盗链或过期链接不保证成功。尚未验证用户截图中实际小红书 CDN 地址。保留单张20MB、整篇200MB、3000万像素、公共域名与每跳地址校验；默认不放开代理虚拟 IP。图片位于正文末尾，不还原网页精确插图位置。历史纯文字资料不自动补图，需要重新采集。旧 App 不支持消费新增的 `browser_public` 待下载任务，须使用配套版本；原文字资料与队列兼容。

验收清单：[runtime-browser-images.json](runtime-browser-images.json)。用户退出 App 后已通过 publish_app.py 发布到唯一正式入口，旧版本自动归档。最新正式版包含此前已发布的阅读位置恢复功能。
