## 实现与格式

设置中的“备份与导出”支持选择保存位置。客户端暂停自己启动的本地服务，等待宿主退出，再由后端取得数据目录排他锁，使用 SQLite Backup API 生成一致快照并复制数据库引用的原件。成功或失败后均尝试重新打开服务；退出客户端推进启动代次，导出回调不会重新启动服务。导出期间显示独立状态，相关操作禁用。

恢复包为 ZIP，扩展名 `.pka-backup`，含 `manifest.json`、`knowledge.db` 和 `assets/` 中被数据库引用的文件。清单 `format=pka-local-backup`、`version=1`，每个文件记录路径、字节数和 SHA-256。保留资料、版本、证据、用户补充及数据库中的既有分析记录；文件原件及已保存图片必须存在且摘要匹配，否则拒绝生成不完整恢复包。当前不提供通用 Markdown 导出。

包内不包含会话、密码摘要、账号令牌、Agent 凭证与授权、审计事件、幂等提交记录、删除任务及语义任务队列。快照使用 `secure_delete` 和 `VACUUM` 清除已删除凭证的旧页。普通文档、OCR 和网页任务中的 pending/running 改为 failed，任务错误替换为固定说明；恢复后需手动重试，不把旧任务直接重放。原数据库和服务任务状态不受快照清理影响。缓存、日志、草稿与未入库采集队列不进入包。

恢复包**未加密**，仍包含私人知识和原件；设置页已说明。排除系统凭证不代表移除用户正文中的敏感信息。临时目录与包使用私有权限。导出先验证暂存包，再以硬链接独占发布，拒绝覆盖已有文件。

## 恢复边界

`local_backup.py --action restore` 只接受尚不存在的新目录，恢复凭证经标准输入提供，不进入参数或环境。先在同一父目录暂存、验证数据库与文件，保留 owner/library/版本/证据 ID，生成新 device ID 和本地会话，再原子发布。macOS 使用 `renamex_np(RENAME_EXCL)`，Linux 使用支持的 `renameat2(RENAME_NOREPLACE)`；不支持安全发布的系统拒绝恢复。现有目录即使为空也不会被覆盖。

校验拒绝未知包版本、重复或未列明文件、路径穿越、链接/特殊文件、加密 ZIP、文件大小或摘要不符、缺失原件、未被数据库引用的包内原件、数据库完整性/外键错误、未知表/视图/触发器、身份关联不一致、凭证记录和活动任务。当前展开数据上限 8 GiB，清单上限 4 MiB，ZIP 项最多 50,000；这些是当前实现限制，不代表已完成上限规模验收。

客户端尚无恢复向导或活动库切换。新目录恢复由内部 CLI/Swift 工具提供，不能直接把示例恢复目录当作已接入的客户端活动库。没有覆盖当前用户库、迁移旧数据或切换真实库。

## 兼容与后续

无数据库结构迁移，现有库不被转换；新增包格式为 v1，未来升级需显式增加兼容验证。恢复会生成设备身份和本地会话，不携带原设备或 Agent 的访问授权。副本中暂停的任务与排除的队列不代表原设备任务被取消。
