# 本地服务启动指南

## 日常使用客户端

直接打开 Knora。App 自带 Python、API、Worker 和 SQLite，启动、退出、端口选择和凭证传递由客户端管理，不需要用户执行后台启动命令。直接模型模式也不需要单独的 AI 网关。

修改源码时，先按[开发与验证](开发与验证.md)准备依赖；完整 App 的组装流程见 [macOS BUILD](../apps/macos/BUILD.md)。修改后台后必须重建对应运行包，只编译 Swift 不会更新内置 Python 代码。

## 外置开发模式

以下命令只用于独立接口和 Worker 调试，使用开发数据库，不会自动连接已安装 App 的真实知识库。默认 SQLite 位于 `services/api/pka-dev.db`；上传目录和环境配置见 [`app/config.py`](../services/api/app/config.py)。不要让两个 Worker 处理同一数据库，也不要直接指定日常知识库进行实验。

从仓库根目录，在两个终端分别运行：

```bash
# 终端一：开发 API
PYTHONPATH=services/api:. .venv/bin/python -m uvicorn   app.main:app --host 127.0.0.1 --port 8000
```

```bash
# 终端二：使用相同环境的 Worker
PYTHONPATH=services/api:. .venv/bin/python -m services.worker.main
```

`GET http://127.0.0.1:8000/health` 可检查 API 是否启动；交互接口说明位于 `/docs`。健康响应不代表已取得 Owner/Agent 权限、已配置模型或已安装扩展。开发入口保留历史服务能力，桌面免登录流程由本地宿主管理，不能把裸 API 当作完整客户端。

配置通过进程环境读取，样例文件不会自动生效。启动前可设置 `PKA_DATABASE_URL`、`PKA_UPLOAD_DIR` 等开发选项；不要提交真实 `.env`、数据库、上传资料或密钥。普通桌面模式中的服务使用动态回环端口，不承诺固定为 8000。

## 可选外部 AI 网关

只有明确调试外部网关时才需要此步骤。按[网关开发说明](../services/ai_gateway/BUILD.md)准备必要环境变量，再运行：

```bash
bash services/ai_gateway/start.sh
```

默认监听 `127.0.0.1:8091`。API/Worker 需要配置对应的 `PKA_AI_GATEWAY_URL` 和访问凭证；这些终端变量不会自动改变已安装客户端的模型设置。真实模型调用可能收费，不以重复提交文章代替健康检查。

## 停止与其他部署方式

在各开发终端按 Ctrl+C 停止对应进程。日常客户端请正常退出 App，由宿主回收其 Worker。

`infra/` 中的 Docker/PostgreSQL 配置和 `apps/mobile/` 原型暂保留供独立开发参考，未纳入当前 macOS 桌面发行验收，也不是使用 Knora 的前提。容器配置的现状与边界见 [infra README](../infra/README.md)。
