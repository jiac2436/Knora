# A0 文档总结与 AI 打标实施记录

日期：2026-10-03。状态：第二批短文闭环已实现，长文归纳和检索整合未完成。

## 实现内容

- 新手动任务冻结 v2 契约、正文版本、个人上下文、领域/项目目录、标签标准名及别名、同版本拒绝记录。一次调用生成概述、摘要、关键要点、原文适用限制和至多 8 个标签建议。总结事实必须引用原文证据，个人补充只能影响打标及归类。
- AI 优先匹配已有标签 ID。新主题或涉及对象进入候选，确认时才创建或复用标准词条；内容类型仅选择目录已有词条。名称/别名采用规范化精确匹配，不自动进行语义合并。
- Worker 同一事务保存 AIArtifact 和 pending 候选。接受后关联来源保持 ai，不删除人工关联；重复接受不恢复用户后来移除的关联。拒绝及移除 AI 关联保留当前正文版本拒绝记录，同版本重分析抑制同名/同标签/别名建议。
- 可清除当前版本拒绝记录；历史候选仍为 rejected，需要用户重新分析才能获得新候选，不自动消费额度。
- 资料/上下文变更、删除、目录改名或合并、分析期间拒绝均有校验。目录在调用中改变时，无法安全绑定的候选不发布，产物保留输出和警告。
- Mac 展示新总结结构、证据、候选理由与确认状态；提供确认、拒绝、清除拒绝记录。读取请求有代次校验，切换资料/库后的旧响应不能覆盖当前视图。
- 总结、候选及拒绝记录进入本地备份、可读导出、变更日志和固定提交快照。永久删除资料同时清理这些记录。

## API 与本地数据兼容

本地 schema 4 → 5 新增 tag_suggestions、tag_rejections，无原文和已有正式关联改写。升级前生成数据库备份，校验原版本触发器，在事务内升级。支持 v1～v4 恢复包升级；旧客户端不能打开 v5 库。

AIArtifact 继续使用版本化 result_json，不增加旧结果的虚构总结或标签。v1 任务及历史产物保留兼容；新任务要求 v2 网关。候选不外键引用 AIArtifact，恢复包不恢复已执行的 AIJob；业务层校验候选所属产物、资料和 owner。

接口：

- POST /v1/ai/tag-suggestions/{id}/accept
- POST /v1/ai/tag-suggestions/{id}/reject
- DELETE /v1/sources/{id}/ai-tag-rejections（可按维度和名称限定）

产物 DTO 增加 tag_suggestions，元素包含 id、tag_id、name、dimension、reason、citations、status、stale。总结 result 增加 contract_version=2、overview、limitations，保留 summary、summary_citations、insights 和 organizing_suggestion。

## 使用与边界

升级客户端后，需要在原网关终端停止旧进程并用原配置重新启动网关，然后新建分析任务。已有凭证不需要更换。工程验证没有使用用户资料、真实 DeepSeek 密钥或真实付费请求；真实输出质量仍需要用户样本审查。

先接受所需标签，再应用分类/项目建议。分类应用改变上下文后，尚未接受的同批候选会过期，界面确认框已提示。

当前仍是最多 48000 字符、80 个证据块的单次分析，超过范围时保留原有截取警告；不能把截取结果视为全文总结。标签目录上限 500、每词别名上限 100、当前版本拒绝记录上限 500，超限任务创建明确拒绝。没有自动付费重试。长文多调用归纳及检查点、总结索引和标签过滤、Skill/RAG、生产会员额度均待后续批次。
