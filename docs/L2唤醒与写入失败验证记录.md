# L2 唤醒与写入失败验证记录

日期：2026-10-01。状态：连接检查与队列写入失败保护已接入；模拟和受控故障验证通过，物理休眠及实际满盘尚未验收。

## 实现

- Mac 唤醒或应用重新激活时，合并通知并等待 1 秒后检查本地连接。只检查已连接、未在发送/连接、未在自动恢复的本地实例；取消启动后不会因通知自动重新启动。
- 分别检查健康状态和当前本地身份，每次请求超时 8 秒。HTTP 错误保留状态码用于判断本地凭证过期；其余 API 调用仍默认 120 秒。
- 自己创建的进程已退出或本地会话返回 401 时，复用已有恢复预算停止/恢复本地服务。进程仍运行但健康检查失败时只提示暂未响应，避免打断可能正在执行的解析。
- 检查绑定启动代次，取消或新启动后旧检查结果不能覆盖当前状态。此检查仅做本机读取，不自动发送队列或执行云同步。
- 队列空间不足错误提供明确中文提示。持久化失败继续阻止请求和删除原件；内存中的新增内容保留，释放空间或恢复写权限后可重新保存。
- 队列原子写入函数提供可注入测试入口，正式默认行为仍为私有文件原子替换，格式和数据目录未改变。

## 验证证据

Swift 队列、模型及包内服务集成测试通过：

1. 模拟 `fileWriteOutOfSpace`：提示磁盘空间不足，原队列字节保持一致，删除条目失败时恢复内存条目、不清理原件。
2. 真实写权限失败：临时队列目录设为 0500，发送被拦截；后台仍为原来的两条资料，队列字节和原件保持一致。恢复 0700 后继续保存新增内容，后台资料数变为三条。
3. 健康服务的模拟唤醒检查：身份有效，服务地址不变，没有强制重启。
4. 过期会话的模拟唤醒检查：只将合成测试库的会话到期时间改为过去；检查发现 401 后恢复服务，原本三条资料仍在，本地身份和 Keychain 凭证继续可用。
5. 既有真实宿主强制退出自动恢复、文字/CSV 响应丢失幂等重试、草稿/文件/飞书状态恢复及损坏保护继续通过。

全部测试使用临时目录和随机 Keychain 测试项；没有迁移旧数据，没有修改实际用户知识库、设备睡眠配置或实际磁盘容量。
