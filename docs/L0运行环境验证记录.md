# L0 运行环境验证记录

日期：2026-09-30。状态：三轮实验完成，可重复构建运行包及本机离线功能验证通过，L0 发行门槛尚未全部通过；当前路线见[实施路线](./实施路线-本地优先-v0.2.md)。

## 实验范围

本机 arm64，开发环境为 Python 3.10.11。通过 uv 下载独立 Python 3.10.17 到临时目录，用已安装的 Python 3.10 依赖及现有 BAAI/bge-small-zh-v1.5 模型构建实验候选。没有复制虚拟环境启动器，没有迁移或启动业务数据库。此解释器版本用于兼容性实验，未冻结为发行版本。

依赖目录约 1.1 GB，现有模型缓存约 182 MB；候选 Python 目录按文件逻辑大小、不计符号链接约 994,921,112 字节，不含另存的模型。不同统计口径不能当作压缩安装包大小。包含开发测试和云端数据库相关依赖，后续须裁剪并建立可复现锁定制品。

## 已处理问题

首次组装直接合并独立 Python 的基础包和开发依赖，导致 setuptools 残留版本混用、OCR 导入缺少 more_itertools。准备脚本改为在候选目录完整替换 site-packages，重新验证通过；项目开发环境不变。探针 PATH 包含系统 sbin，满足 Paddle 查询系统信息的调用。

## 第一轮剩余门槛（历史记录）

1. Paddle 的 liblapack/libblas 引用 `/opt/homebrew/opt/gcc/lib/gcc/current/` 下的 libgfortran、libgomp、libquadmath。需验证随包提供兼容运行库及其传递依赖、修正加载路径和签名，或选择无该依赖的兼容构建；在无 Homebrew 的环境验收前不宣称独立运行。
2. OCR 模型下载、缓存路径、离线真实识别，以及 pdf-inspector/anydoc 实际处理样本仍需验证；不能用导入成功代替功能验收。
3. 冻结解释器与完整依赖制品、摘要和必要许可材料；当前开发依赖快照不是发行锁文件。OCR requirements 中仍有版本范围。
4. 明确 Crawl4AI、飞书 CLI 等外部程序的发行边界；当前实验未将其内置。
5. 本轮仅 arm64 当前主机；清洁 Mac、CPU 支持范围、原生库签名、公证及最终包体未验收。

第一轮后的验证已执行，结果及当前剩余门槛见下文。L1 的正式目录迁移及本地身份实现尚未开始。

## 第二轮：包内运行库与真实离线功能

本机三个 Homebrew GCC 引用路径不存在，第一轮只做简单 Paddle 运算，没有直接触发 BLAS/LAPACK，不能据此判定这些库能够独立加载。第二轮从 [Homebrew 官方 GCC 元数据](https://formulae.brew.sh/api/formula/gcc.json)选择 GCC 16.2.0 的 arm64_sonoma 制品，下载后核对 SHA-256，仅提取临时运行库。正式解释器、GCC 制品选择仍需发行兼容验收；本轮不安装系统 GCC。

候选中复制 libgfortran、libgomp、libquadmath、libgcc_s.1.1，修改相关库依赖为 `@loader_path`，逐个作临时签名并验证。原生扫描覆盖 306 个文件，绝对外部加载路径为空。候选 Python 目录约 993,840,360 字节，不含模型、不等于最终发行包大小。

OCR 使用官方 PP-OCRv6 small 检测及识别模型，约 31,481,281 字节，来源从当前安装 PaddleX 的官方模型下载配置核对。完整目录通过参数指定，使用方式参考 [PaddleOCR 本地模型文档](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html)。模型文件摘要已记录，未固化为正式发行资源。

将完整候选再次搬迁，在操作系统沙箱禁止网络及读取 `/opt/homebrew` 的条件下执行 10 项检查，全部通过。另以实际文件读取和 socket 连接验证沙箱拒绝生效，避免只靠 Python 网络钩子证明离线。

| 新增检查 | 实测结果 |
| --- | --- |
| BLAS/LAPACK | 直接加载动态库，矩阵乘法和线性方程解符合预期；GNU 库已加载，未从 Homebrew 加载库 |
| OCR | small 模型在临时 HOME 下识别合成图片中的 LOCAL KNOWLEDGE 2026；不下载其他模型 |
| DOCX/CSV | anydoc 转换合成有效文件，输出包含预期文本 |
| PDF 文本解析 | PDFium 与 pdf-inspector 对合成单页 PDF 提取预期文本及页序 |
| 已有六项冒烟 | 在第二次搬迁及系统隔离条件下继续通过 |
| 工具保护 | 拒绝修改开发虚拟环境；缺失运行库在修改前拒绝；不完整 OCR 模型参数拒绝 |

第二轮证据：[隔离功能结果](./verification/l0/runtime-functional-sandboxed.json)、[原生扫描](./verification/l0/native-inventory-vendored.json)、[GCC 来源](./verification/l0/gcc-source.json)、[运行库摘要与修改清单](./verification/l0/vendored-gcc.json)、[OCR 模型摘要](./verification/l0/ocr-model-manifest.json)。原始第一轮记录保留，不用新结果覆盖。

## 第三轮：固定制品与可重复离线构建

新增[运行包构建输入](../apps/macos/runtime/README.md)、[构建器](../apps/macos/scripts/runtime/build_runtime.py)和[完整性校验器](../apps/macos/scripts/runtime/verify_runtime.py)。根依赖复用已测版本，锁定 100 个运行依赖及制品摘要，排除 pytest 和云端 PostgreSQL 驱动。五个解释器/模型/GCC 归档固定 URL、大小和 SHA-256；构建阶段仅从已经校验的 uv 缓存离线安装，不复制开发虚拟环境。

最初 pip 下载遇到 TLS 连接失败，改用指定版本 uv 从同一官方 PyPI 来源安装并校验摘要；没有关闭 TLS 校验或更换到不明来源。离线缓存仍需预先准备，当前脚本不会自行下载缺失制品。

两次独立暂存目录构建得到字节相同的 manifest，覆盖 19,870 个文件及链接、权限、制品锁和脚本摘要。初次对比发现 bytecode 中的暂存路径及已删除 CLI 对应的 RECORD 摘要不同；构建器删除缓存和不使用的脚本、重新生成 RECORD 后通过对比。新包包含 23 个 API/Worker 源文件，持久数据、配置秘密及测试不入包。

最终产物再次搬迁，在禁止网络和 Homebrew 读取的系统沙箱中通过 11 项检查。新增真实后端检查启动包内 API，用内存数据库创建测试会话并加载空队列 Worker；不是正式身份或同步验收。随后产物压缩并重新解包，按交付摘要校验所有文件、权限及链接通过。原生扫描覆盖 282 个文件，无绝对外部加载路径。

| 交付项 | 结果 |
| --- | --- |
| 固定输入及离线安装 | 100 个带摘要依赖，5 个带摘要归档；两次离线构建内容一致 |
| 工具回归 | 8 项通过：归档路径/链接、篡改检测、输出保护、输入摘要和安装记录 |

| 包内服务及解析 | 11 项系统隔离检查通过，数据库仅使用内存 |

## 第三轮后的发行门槛

- 已固定本轮解释器、依赖及公开制品输入；升级和支持周期仍需在正式发行时冻结。当前只验证了同一宿主/工具链的两次构建。
- Paddle 核心库标注最低 macOS **14.5**，而现有 Swift 构建及 Info.plist 声明 14.0。尚未修改应用要求，也未宣称完整后端支持 14.0。需确定兼容构建或统一最低系统后，在相应清洁设备上验证。
- 完整 `.app` 还需 L1 的正式数据目录/身份、L2 的服务管理。清洁安装、签名、公证、第三方许可交付及全部公开支持格式的验收仍未完成。

当前可重复运行包构建已完成；L0 整体验收仍按上述发行门槛保持未完成，L1 尚未实施。
