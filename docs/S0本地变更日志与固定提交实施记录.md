# S0 本地变更日志与固定提交实施记录

日期：2026-10-01。本轮交付 S0 首批本地基础：业务写入与变更日志同事务、固定提交快照及确认逻辑。未开放云端同步入口，S0 尚未完成全部版本和关联改造。

## 数据与事务

本地数据库 schema 升至 **v2**，增加四张表：

| 表 | 用途 |
| --- | --- |
| `replica_state` | 本地库/设备绑定、协议版本及未来同步 epoch/应用游标 |
| `sync_entities` | domain/project/source 聚合的本地代次、已确认代次和基础云端版本 |
| `local_changes` | 单调递增日志序号、实体、代次、设备和变化类型 |
| `sync_operations` | 固定操作 UUID、代次、基础版本、JSON 载荷、SHA-256 和确认状态 |

SQLite 规范触发器记录当前绑定 owner 的知识域、项目、资料及其附属业务内容。版本、证据、原件、个人上下文、项目关联、实践记录、图片及网页/飞书产物聚合到 source。批量 SQL、API 和 Worker 写入均在同一数据库事务内记录；业务回滚时日志也回滚。新设备先记录当前实体基线，不改原有资料、版本或证据 ID。

凭证、连接授权、处理任务、模型缓存、关键词和向量索引、可重算的规则标签不进入日志。普通处理中轮询和 `updated_at` 更新不增加代次；永久删除状态变化会记录。附属记录更换 source 时记录旧、新两个聚合实体。日志当前保留，没有后台自动压缩或清除策略。

## 固定快照与确认

内部 `prepare_operation(db, entity_kind, entity_id)` 获取 SQLite 写锁并清空 ORM 旧缓存，读取完整业务快照，固定操作 ID、载荷、摘要、本地代次和基础版本。调用方负责提交事务。已经准备的同实体操作会原样返回，即使资料随后继续编辑，也不会改写旧载荷。数据库触发器同时禁止修改已固定的身份、载荷和版本字段。

Source 快照包含正文历史、证据及定位、补充、业务关联和资产元数据；整数展示编号明确序列化为 `origin_display_version`，revision UUID 仍是身份。原件字节没有放进提交 JSON，后续 S1 要通过独立资产确认流程发布。图片失败诊断清空，Source 端内处理/上传状态不进入知识载荷；凭证、任务和索引表不序列化。

知识域、关联项目和实践记录独立项目必须存在、归属一致，且已有云版本或已准备操作；依赖 ID/操作 ID 进入固定快照。该检查为后续有序提交提供基础，不等于本轮已经向云端发送或原子提交依赖组。已删除或物理移除的实体使用最小删除快照，不携带旧正文。

内部 `acknowledge_operation(db, operation_id, cloud_version, payload_sha256)` 验证设备/库、载荷摘要及基础版本递增，再确认该操作代次。旧操作确认只推进自己的已确认代次，后续编辑仍为 dirty；再次准备将使用新的基础版本及新代次。重复确认幂等，不能使已推进版本回退。未知操作、摘要错误、版本跳跃、错误设备或非法状态拒绝。

本轮回执测试使用**合成版本和摘要**，没有真实云端服务、账号权益或远端签名验证。`prepared` 是本地冻结起点，尚不代表操作已发送；S1/S2 需要追加派发、重试、冲突和远端变更应用。

## 升级与备份兼容

本地 v1 正式库启动准备时，先生成私有 SQLite 一致快照，再在事务内创建新表、安装触发器和建立已有实体基线。失败回滚，未知版本、缺失或被篡改的触发器拒绝启动。未导入旧开发库或操作真实用户库，本轮只用合成测试数据。

恢复包格式仍为 `pka-local-backup/v1`，内部数据库可为已支持的 schema v1 或 v2。旧 schema v1 包验证后在隔离恢复目录升级；v2 包严格核验触发器集合和规范 SQL。备份清除四张同步表和旧日志序列，避免携带原设备云绑定、游标或未确认操作。恢复使用新设备并重新建立基线，原库的记录保持不变。

开发模式纯 `create_all` 没有本地触发器，保持原模式行为。本地 API/Worker 启动仍要求显式准备完毕。schema v2 库不可用旧 v1 客户端继续打开；需要保留新版应用和升级前快照，不能直接降级运行。无新依赖，旧正文整数版本入口、资料 ID 和证据 ID 不变。

## 剩余路线

S0 下一批需实现跨端 revision UUID/内容摘要及本机展示号分配、同名知识域约束兼容、域/项目及关联的受控应用、回传自身提交与后续编辑保留。规则标签可重算；用户管理标签和未来新增 AI 类型需要显式数据契约，本轮没有假设现有规则标签就是用户标签。

尚无云端传输、资产上传确认、会员鉴权、同步界面、远端冲突或远端删除处理，不能据此宣告多端同步可用。大历史快照的分页/大小上限和日志压缩仍需后续方案与规模验收。此前清洁机器、图形、故障和发行门槛也仍保留。
