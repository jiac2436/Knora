# 轻量客户端与扩展使用说明

基础客户端自带本地知识库和必要运行环境，不需要 Python、Docker 或后台启动命令。云端 AI 分析仍内置，配置模型后使用，调用前仍需确认。

## 安装扩展

打开“设置 → 扩展功能”：

- 语义搜索、文字识别、文档解析均可点击“安装”，自动按清单逐项下载并校验，不需要配置地址或执行命令。
- 展开“下载清单”可查看组件名称、版本、大小及各自的下载状态；开始安装后清单会自动展开。OCR 本版本共 56 项，只需点击一次安装。
- 三项均保留离线导入作为备用。之前已安装的配套扩展继续有效，不需要重新下载。

| 扩展 | 用途 | 在线下载量／离线包 | 安装后逻辑大小 |
| --- | --- | --- | --- |
| 语义搜索 | 按含义检索、向量索引，知识库 AI 问答所需的检索能力 | 在线约134.9 MB；离线包95.0 MB | 239.4 MB |
| 文字识别 | 用本地 Small 模型识别扫描 PDF | 在线约408.3 MB；离线包239.4 MB | 781.2 MB |
| 文档解析 | Office 等现有文档格式转换、复杂 PDF 版面解析 | 在线约9.3 MB；离线包9.0 MB | 21.8 MB |

在线下载与离线包的压缩方式不同，因此大小不同；安装内容与既有扩展完全一致。大小按十进制 MB 统计，实际磁盘分配量会随文件系统变化。复杂扫描 PDF 使用高级解析引擎时可能同时需要文档解析和文字识别两个扩展。TXT、Markdown、基础数字 PDF 文字提取不需要这两个扩展。

**下载和安装期间不需要退出，可以继续使用客户端。安装成功后仍需等待任务结束，用 ⌘Q 正常退出并重新打开，扩展才会生效。** 启用、停用、卸载也在正常重启后生效；客户端不会强制中断现有任务。页面区分当前生效状态与等待重启状态。

没有扩展时可以保存原文件。需要相应能力的解析任务等待安装，不会删除原件，也不会阻塞其他资料。等待期间手动修改正文会停止该任务的自动解析；以后明确重试解析／重新扫描才会重新处理，历史版本保留。

## 下载机制

下载源已内置，普通用户无需填写服务器或镜像地址。

Python 依赖首选清华镜像，并配置阿里云同版本文件作为备用；向量模型从魔搭上内容一致的仓库下载。OCR 模型从 Paddle 官方国内存储下载，Mac 原生运行组件从清华 Homebrew 镜像下载、中科大镜像备用。客户端使用随 App 固定的版本、文件长度、SHA-256和目标文件清单，验证后安装到独立扩展目录；安装前还会以合成数据检查真实引擎能否运行，不会发送用户文章。

不执行 pip 在线解析、不编译源码、不依赖系统 Python、Homebrew 或 Xcode。文件未找到、校验失败、取消或自检失败时不会启用半成品，也不会改用未经验证的新版本。支持进度、取消及失败后重新下载，暂不支持断点续传。

OCR 的原生依赖由客户端自动完成固定版本兼容处理，处理前后均验证完整摘要，只取所需运行库，不安装整套 GCC、Homebrew 或 Xcode。安装结果与既有离线包逐文件一致；普通用户无需获取我们自制安装包。在线下载量包含上游原生组件归档，因此比裁剪后的离线包大。当前为本机 arm64 配套版本，下载来源、实际识别与安装验收见[OCR 依赖安装验收](verification/ocr-dependencies-20261027/README.md)，其它源核验见[下载源验收](verification/dependency-sources-20261024/README.md)。

## 停用、卸载与已有资料

停用保留程序文件，下次启动不加载。卸载删除扩展程序及专属模型；仍被进程使用时先标记等待卸载，退出后下次启动完成删除。

原文、图片、历史版本、AI 分析、标签、概览和已生成问答不会随扩展删除。已有结果可以继续查看；执行新的语义查询、扫描识别或复杂文档解析，需要重新安装对应扩展。云端单篇分析和知识库更新不强制要求语义搜索扩展，知识库 AI 问答需要语义检索能力。

此次不更改数据库 schema16，不清空文章或索引，也不增加账户登录。扩展程序保存在当前用户的应用支持目录，多个本地资料库共用；基础 App 内部文件保持不变。首次改用轻量客户端时，扩展由用户按需手动安装。在线安装保持原有扩展标识和文件清单，不改变已安装扩展、已有模型或向量索引，不需要数据迁移。

## 开发构建

分包工具只重组已经过验收的完整运行包，不在用户设备执行 pip。必须提供可信原运行包摘要和明确冻结的后端源码：

```bash
.venv/bin/python -B apps/macos/scripts/runtime/split_runtime.py \
  --source /absolute/path/to/verified-runtime \
  --manifest-sha256 <该运行包清单的可信SHA256> \
  --backend-source /absolute/path/to/frozen-backend \
  --output /absolute/path/to/new-output
```

输出包括 `base/`、三份 `.pkaext` 和 `split-result.json`。构建 App 时使用 `base/` 及其清单摘要；按 `apps/macos/RELEASE.md` 验收和发布。首版仅验收 macOS arm64；生产分发前还需完成 Developer ID 签名、公证、许可证检查及干净设备验证。


分包后需要嵌入已经过真实下载及内容一致性验证的依赖计划（当前仅适用于本次固定版本）：

```bash
.venv/bin/python -B apps/macos/scripts/runtime/prepare_dependency_downloads.py \
  --runtime /absolute/path/to/project/apps/macos/.build/new-output/base \
  --audit docs/verification/dependency-sources-20261024
```

准备工具会核对原离线包清单摘要，写入下载计划及原文件清单；不接受未验证的版本或模型。然后重建运行包 manifest、构建与签名，并完成随包验收再发布。

OCR 计划需在上述通用计划准备后生成：

```bash
.venv/bin/python -B apps/macos/scripts/runtime/prepare_ocr_downloads.py \
  --runtime /absolute/path/to/new-output/base \
  --source-audit docs/verification/dependency-sources-20261024 \
  --gcc-audit docs/verification/ocr-dependencies-20261027/gcc-source.json
```

构建期从已验收离线制品提取目标清单及固定兼容规则，发布给用户后不再下载该离线制品。源版本或目标运行库改变必须重新核验计划和兼容规则，不能直接追踪上游最新版。
