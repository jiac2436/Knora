# A0：AI 分析产品化实施记录

日期：2026-10-04。新流程工程实现完成；2026-10-05 完成 20 份合成资料的真实 DeepSeek 分批复验与 6 个原文问答核对。固定样本通过不代表真实资料全面质量保证。

## 用户流程

1. 设置中保存原有 AI 网关地址与访问凭证。
2. 打开资料，点击“AI 分析”。每个知识库首次确认发送范围；已授权的单次分析直接执行，长文确认覆盖范围与调用次数。
3. 阅读器显示简短概述、最多三条要点、当前 AI 标签和业务状态。原文依据、分析说明、历史、长文分段结果折叠。
4. 有效标签自动成为正式 AI 关联，无需逐条审批。通过普通标签编辑器添加人工标签或移除指定来源；同一标签可同时有 AI、人工来源。
5. 分析完成后自动更新本地总结及原文检索，索引就绪才显示完成。索引失败在分析详情重试本地检索更新，不再请求模型。

原文、领域和项目不由分析自动修改；人工标签不被重新分析覆盖。仅部分采集或部分分析时，默认显示范围提醒。

## 接口和发布

新 Swift 客户端显式发送 `contract_version=3`、`kind=analyze` 和预览 `plan_hash`。旧 API 默认 v2 保留兼容；v3 拒绝 organize。新协议不产生领域/项目建议。

中文阅读正文（概述与要点合计）最多 300 字符，英文 600 字符；小于 300 字符的短文不能扩张阅读正文。最多三条要点、五个有依据标签。内部总结另有相同长度上限；长文分段维持原检查点预算，最终结果才执行紧凑限制。超预算、非法引用或标签响应不发布，不静默截断，也不追加付费模型修复。

网关 v3 使用 `compact-knowledge-v3` 提示与 2048 输出 token 预算，显式关闭思考模式；分段保留既有较大预算。短笔记提示包含实际字符预算，不超过 300 字符时不生成展开要点。引用约束仍要求真实证据 ID，不能仅依据模型摘要作事实判断。

Worker 在同一事务保存最终产物、替换本资料 AI 关联、登记索引任务。长文仅最终汇总发布标签。发布前重新校验资料版本、上下文、取消状态和相关词条；晚到结果不能覆盖新资料。主题和涉及对象允许创建新规范词，内容类型复用已有词条；人工纠正和同版本拒绝记录优先。

同快照进行中的任务复用，重复请求标识在任务完成后仍保持幂等。复用别名只存本地任务快照，不发到网关；最多保存 256 个，超限提示查看现有任务，不创建新付费任务。用户主动重新分析可以创建新任务；未知请求不自动重发。

## 索引和状态

API 增加兼容性可选字段 `pipeline_status`、`index_state`、`index_retryable`。综合状态包括分析中、索引中、完成、索引失败、过期、失败、未知和取消。

完成需当前单篇或最终汇总产物有效，总结关键词及配置启用的本地向量数据完整；原文向量启用时也必须当前版本就绪。禁用向量不阻塞关键词完成。分段、旧版本和其他历史总结不能替代当前结果。

沿用现有原文窗口、总结索引、正式标签筛选和权限检查，无新向量库。重建会补排缺失、失败或不完整的总结/原文索引，只运行本地计算。摘要和标签提供召回线索，MCP/RAG 仍用当前原文证据支撑回答。

## 数据兼容

无需数据库迁移，schema 继续为 v8。旧 v1/v2 结果保持原契约可读，默认结果卡仅显示短预览；旧 pending 标签留在历史详情，不自动接受。旧确认/归类接口只保留历史兼容。

`tag_assignments.confirmed_at` 沿用现有非空字段。新 AI 关联该值表示系统发布生效时间，不代表人工审批；以 `origin=ai/manual` 判断来源。备份保留总结、AI/人工关联、拒绝记录；恢复不重启付费任务。可读导出保留 v3 结果及依据。

新版 app 已更新运行包。现有外部开发网关需使用当前源码重新启动以支持 v3；地址和密钥配置保持原值，不能将旧网关的拒绝错误误认为新版客户端流程通过。

## 已知质量边界

- 当前模型标签偏保守，多数短资料只有内容类型，主题标签存在少打。标签数量和精细程度仍需代表性用户文章评测，不能宣称系统性打标质量已全面达标。
- 所用资料为合成样本，多数为短文，加一份长文；不能代表真实用户文章、复杂 PDF/OCR 和专业领域资料的分布。
- 长文最终归纳有证据预算，明确展示部分覆盖。总结不包含全部细节，MCP/RAG 事实回答仍须检索原文。
- 问答对宽泛问题可能偏保守。事实与引用已人工对照当前固定样本，不承诺所有提问正确。
- 失败及未知请求不会自动重试。修复后分批复验通过不代表模型永不出现无效结果。
