# L2 本地服务可靠性记录

日期：2026-10-01。状态：启动取消、异常恢复和启动时日志轮换已实现并验证；完整 L2 可靠性验收仍未全部完成。

## 实现

- 将服务启动串行锁与进程状态锁分开。客户端停止/取消可立即关闭父进程管道并发出停止信号，不再等待整个就绪读取超时。每次启动有独立代次，已取消的启动和连接响应不能覆盖新启动状态。
- 客户端启动页和恢复页提供取消入口；取消保留知识库和采集队列。正常关闭先保存队列，再停止服务。
- 只对本次创建的宿主进程执行停止；若 8 秒后仍在运行，则结束该进程。宿主内部继续关闭 API、终止自己创建的 Worker。没有按名称或端口扫描并结束其他进程。
- Worker 通过专用 stdin 管道监测宿主存活。宿主被 `SIGKILL` 等方式结束，管道关闭后 Worker 向自身发送停止信号，补齐宿主无法执行 `finally` 的清理路径。启动握手文件描述符与存活管道分别使用。
- 服务停止通知携带所属服务实例，过期进程的通知不会影响新实例。客户端在已连接服务异常退出后，先等待正在失败收尾的采集请求，再尝试重连；首次启动失败仍显示错误和手动重试。
- 自动恢复每 60 秒最多 3 次，依次等待 1、2、4 秒，成功不会立即清空窗口内次数；连续失败后停止自动尝试。手动重试重新开始该窗口，取消会停止恢复任务。恢复仅启动本地服务，不发起云同步，不自动重新发送客户端采集队列。
- 日志在启动时达到 5 MiB 则轮换，保留 3 份历史归档；拒绝链接及异常归档路径，避免递归删除非日志目录。当前不执行持续运行期间的硬容量限制。

## 验证

1. Python 完整回归 **114 项通过**，包含新增宿主被强制结束后 Worker 回收、Worker 被强制结束后 API 停止及失败报告。已有 Starlette/AnyIO 弃用提示 1 项。
2. Swift 可靠性测试通过：静默子进程阻塞就绪读取时取消调用低于 0.5 秒、启动任务低于 3 秒结束；日志历史保留 3 份；每分钟恢复次数限制及窗口恢复。
3. Swift 实际包内服务集成通过：文字/CSV 重启幂等恢复、强制结束测试宿主后客户端自动恢复、原来两条资料保持且未重复创建。测试使用临时目录和独立随机 Keychain 项，结束后清理。
