# A1：知识库视野与分层检索实施计划

日期：2026-10-09。状态：P0共享规则/输入快照与P1状态、预算和本地候选主题已实现，源码schema为v13；Worker接入中断保护和本地结构更新，App端API支持主题目录与人工调整。P2已加入有界节点契约、网关调用、持久化单请求任务与产物、预览/授权/查询API和实际校验发布；多批检查点、有效叶批次复用和有界主题到域合成已接通；变更合并自动调度已接入（默认关闭，首次手动构建后、规模和累计预算内更新）；P3已接入域/显式主题概览的关键词与向量辅助召回并保持原有证据排序，已有Owner域/主题/原文导航API；虚拟处理中间层导航、客户端界面和真实质量验收尚未完成。进展见 [A1实施记录](./A1知识库视野实施记录.md)。本轮只建设用户创建的知识域的第二层知识组织能力。单篇分析继续按 [A0 AI分析产品化计划](./A0AI分析产品化实施计划.md) 工作。此计划不将已回滚的关联/演化代码视为可用基线。

## 1. 目标、范围与产品边界

第一层保存单篇资料的概览、要点、正式标签及原文引用。第二层以界面中用户创建的“知识库”为单位，形成简洁全库概览、主题结构、主题摘要及可回溯的资料/证据入口，支持浏览与多粒度检索。

代码范围是 `Domain` 和 `Source.domain_id`，不是本地数据库目录/备份容器 `Library`，也不是跨域项目。`全部资料`首期提供各域入口，不自动合成跨域知识。主题可以有多个资料成员，同一资料可以属于多个主题。

交付目标：用户快速了解一个域覆盖什么；按主题下钻到资料与原文；原文变更后第二层正确失效及更新；RAG整体问题得到相关跨资料背景，细节问题仍能直接找到原文。

本轮不实现自动收录分析、自动领域/项目绑定、冲突判断、知识图谱、主动通知、专题综述卡片、跨域合成、会员计费或多模态模型加工。图片OCR现有文字可继续参与索引，不宣称图形含义已被理解。

复用 Swift、Python API/Worker、SQLite、已有原文/摘要向量与AI网关，不引入GraphRAG框架、图数据库或第二套原文索引。

## 2. 已确认原则与本轮默认行为

- 第二层是由多个有界节点构成的组织索引，不是一篇随规模无限增长的总报告。
- 首页概览初始目标300～500中文字符；主题概览初始目标300～800字符。属于设计预算，需用真实资料校准；英文等语言定义独立预算。
- 先采用“知识域→主题→资料→原文”。主题足够大且内部异质时才增加子主题，首期主题最多两级，不能无限递归摘要。
- 标题、主题结构与摘要不能替代原文证据；摘要命中最终解析到当前可访问的原文。
- 主题和正式标签是不同概念：标签用于人工分类/筛选；主题用于跨资料组织。生成主题不会重写标签或移动资料。
- 基础资料目录、变更记录和本地索引更新自动执行，不调用收费模型。
- 库级AI加工默认关闭，用户主动开启并确认范围后首次构建；后续在该授权范围内合并变更、自动更新。关闭后停止未发送调用，已发送请求保留结果未知/取消处理规则。
- 自动更新必须有可配置的调用/输入预算及暂停入口，不能每次变更都立即全库收费重建。首次构建和较大范围重组需要展示预计批次和覆盖范围，取得具体授权；不能展示没有依据的金额。
- 用户主动重建或开启自动更新不等于授权系统自动重做所有单篇AI分析。未分析资料仍可被原文检索，第二层显示覆盖范围。

## 3. 第二层产物与引用契约

| 产物 | 内容 | 用途 |
| --- | --- | --- |
| 域概览 | 主要覆盖范围、主题入口、加工覆盖状态 | 首页浏览和整体问题的检索线索 |
| 主题节点 | 稳定ID、名称、说明、可选父主题、成员及人工固定状态 | 导航和相关资料范围组织 |
| 主题产物 | 简短摘要、有限的有来源要点、条件/分歧原样保留、覆盖范围 | 跨资料召回与下钻 |
| 成员/证据映射 | source/revision/artifact、证据ID、片段位置、来源类型 | 回到真实原文，检查当前有效性 |
| 版本与索引状态 | 输入指纹、发布代次、模型/提示/契约/嵌入版本 | 一致性、重建和成本诊断 |

所有生成事实都附可解析的证据引用。域概览可引用主题产物，但依赖图必须能继续落到原文；回答所用事实必须验证底层原文，不只引用父摘要。个人备注/实践经验与原文事实保留不同来源类型。没有事实依据时只提供确定性的目录与状态，不填固定“共识”“互补性”等结论。

主题层保留条件、时期、实体和不同说法的来源，不默认判断谁正确。关键数值和版本回原文读取；文档/主题数量由数据库计算，不能让模型估算。

禁止摘要自循环：单篇事实产物只依赖自身证据；主题产物可依赖多个单篇产物和原文；域概览依赖主题产物。未来若单篇参考库级背景，比较内容必须另外记录，不能当作本文原始事实再次回流。

资料有原文但没有当前有效单篇产物时，首期进入目录与原文检索，主题可用标题/标签/向量作候选归属，不据此生成内容事实。语义概览注明“已分析且纳入的资料/全部可用资料”；整体问答不能默默把未分析资料排除。需要扩展覆盖时提供明确操作，不悄悄调用单篇分析。

## 4. 数据设计与兼容

以下为需要冻结的数据职责，P0审计后确定最少表数、字段及约束；不提前创建空表。

| 数据职责 | 最低要求 |
| --- | --- |
| 域加工状态 | owner/domain、输入generation、当前发布版本、dirty原因、加工策略/预算 |
| 主题结构与成员 | 稳定节点ID、父级无环、同域约束、source成员、人工命名/归属固定 |
| 不可变库级产物与依赖 | scope、输入成员清单/指纹、各依赖版本、结构化结果、用量及覆盖 |
| 后台任务与检查点 | generation、phase、固定请求ID、状态、尝试和错误、段级完成结果 |
| 可重建索引 | 绑定节点/产物版本、嵌入模型、就绪状态；不影响原文索引 |

输入指纹必须涵盖原文版本、当前有效单篇产物、标题、域归属、有效标签、个人上下文/经验、删除/可见性、人工主题结构及生成规则版本。正文revision不能代替全部输入版本。

新增正式主题、人工纠正和已发布AI产物进入备份/恢复、可读导出、永久删除及本地变更记录。任务、运行锁及向量索引属于运行数据/缓存，备份中清理；恢复后只排本地索引，不自动重放付费模型请求。生成输出写入不得反向触发无限的输入dirty循环。

源码schema已升级为v13：v9增加域加工策略和输入状态，v10增加主题、成员和本地索引状态，v11增加概览任务和正式产物，v12增加有界加工计划及复用索引，v13增加可重建节点向量缓存与本地索引任务；旧完整App仍为v8固定快照。旧库升级前备份，恢复v8/v9包经迁移后可读。后续产物表使用后续显式迁移，不能回改已发布迁移以添加字段。新库不能被旧运行包假装兼容，也不自动数据库降级。云同步尚未完成；本轮只补齐新正式数据的本地日志/提交快照契约，不宣称云端同步已实现。

## 5. 权限与范围

App域概览仅包含该用户该域当前有效资料。不同域严格隔离；跨域移动同时使原域与目标域失效。首期不自动跨域推荐。

MCP不能直接复用包含`app_only`资料的App概览。维护或按需构建仅基于可分享资料的独立范围；生成的主题名称、成员统计和摘要同样受范围约束。撤权、改可见性或删除后立即排除受影响产物，不能等后台重算再停止泄露。

Agent的项目/标签等进一步筛选可能只允许主题的一部分成员。只有依赖成员全部落在当前可见检索范围的产物才能使用；否则下钻到允许的原文或禁用该产物，不能先读完整摘要再在结果端过滤。不得为每个Agent无界复制和自动收费重建全库摘要。

## 6. 构建、变更与增量更新机制

### 6.1 已确认的触发策略

- 首次由用户点击“构建知识概览”，确认本域输入范围、单篇覆盖率、预计批次和调用/输入预算，再创建首次任务。默认关闭；无授权预算不发送模型请求。
- 开启后，新资料、解析就绪、有效单篇摘要发布，以及正文、标题、标签、备注、实践经验、归属、删除/恢复、可见性和人工主题变化，在业务事务中立即登记dirty，按域合并后更新受影响节点。
- 初始合并等待30秒，连续变更最多等待300秒；这只是可配置的工程初值，后续根据实际操作节奏调整。等待时间自最新变更计算，最大等待自首个未处理变更计算。不会每次保存立即调用，也不会持续修改导致任务无限饥饿。
- 本地目录、统计、权限过滤、失效和已有产物的索引更新立即执行，不消耗模型额度；生成主题/域概览才进入受预算控制的AI队列。
- “立即更新”跳过合并等待，也允许在暂停自动更新时主动执行；仍须有开启授权和剩余预算。“暂停自动更新”阻止后续自动发送；不自动取消已发送请求或假定没有产生用量。
- 首次确认与“立即更新”不授权给未分析文章自动补做单篇AI。保留未分析资料的原文检索，并如实显示覆盖范围。
- 较大范围主题重组或预算扩展，重新展示具体处理范围并确认。预算用完保留待更新状态；失败需手动处理；结果未知不得自动重发，手动重试也要明确确认重复用量风险。
- 用量预算按一个明确授权周期累计，包含已预留的在途请求；在发送前同事务预留，不能让并发Worker重复消耗同一剩余额度。禁止自动重置预算周期。

### 6.2 流水线与一致性

流水线：确定范围/冻结清单 → 本地候选主题组织 → 有预算的主题生成 → 引用及字段校验 → 存储候选版本 → 本地索引 → 版本核验及原子发布。

冻结前本地整理标题、有效标签、章节、当前摘要和已有向量；使用确定性候选规则和向量分组，允许多主题归属及“待归类”资料。控制重复内容权重，不能用多数篇数推导事实可信。主题身份保持稳定，人工修改优先；不让每次新增都重命名整棵树。

主题生成按当前网关可承受的字符/字节及模型token预算分批，不能认为全部单篇摘要必然装得下。初始调用输入token预算按4k～8k实验校准，同时受现有48,000字符、512KiB等协议上限约束。若需扩展契约，必须先固定新契约，不能直接复用单篇字段伪装成多篇请求。

| 变更 | 本地立即动作 | 授权后的后台动作 |
| --- | --- | --- |
| 新增、解析完成、单篇分析发布 | 记录输入代次，更新目录/候选成员 | 更新相关主题，再判断域概览 |
| 正文、标题、上下文、经验更新 | 失效依赖结果，原文照常可用 | 使用有效输入重建受影响节点 |
| 标签增删/合并、人工主题调整 | 更新成员线索及输入代次 | 必要时调整归属，不覆盖人工固定 |
| 跨域移动 | 同时标记两域 | 分别更新成员与概览 |
| 删除/恢复/可见性变化 | 立即过滤引用及授权范围 | 重建受影响节点与统计 |
| 字号、阅读位置、任务进度 | 不改变知识输入代次 | 无模型调用 |

变更登记必须与业务写入同一事务，覆盖所有写入入口；不得仅靠一个界面回调或只在AI完成时入队。直接数据库写入的检测边界在P0冻结，SQLite采用可验证触发器或等价事务机制；开发与随包模式都必须有效。现有同步日志不能无条件当加工队列：它包含生成输出，需排除自触发。

按域合并连续修改，保留dirty集合及目标generation；具体延迟可配置。更改期间正在运行的快照可结束生成，但发布前核验generation和依赖；旧结果不能覆盖新状态。等待模型和向量计算期间不持有SQLite写锁。域版本及索引分阶段准备，单一发布指针原子切换，不混用新旧成员/摘要/向量。

局部更新不是保证只影响一个节点：成员跨主题、主题拆分或边界变化可能影响多个父节点。触及预算上限时保留“待更新/部分覆盖”，暂停并说明范围；不要循环全库重建。周期性一致性检查先执行本地检查，付费重组只在已授权预算内执行。

建议状态：`not_built / dirty / preparing / generating / indexing / ready / partial / failed / unknown`。具体字段在P0与既有状态统一。索引失败只重建索引；模型明确失败不发布；结果未知不自动重发。确认过期的主题内容可作为标注历史浏览，不能默认进入当前检索/问答。

## 7. RAG与MCP接入

查询首先执行owner/domain/项目/标签/可见性过滤；主题摘要、单篇摘要、关键词和原文向量多路召回，跨通道去重并保持证据多样性。主题树是辅助，不是唯一硬路由。

- 细节问题：保留原文关键词/向量通道，上层遗漏的事实仍可命中。
- 整体问题：召回多个相关主题，展开成员证据；回答说明覆盖范围。
- 需要全库穷举/全面对比的问题：不能把固定Top-K称作全覆盖。在授权预算内分批处理，或明确返回部分覆盖/资料不足。
- 无有效第二层、更新中或索引失败：回退原文检索；不得因此强制额外模型调用。
- 生成答案时上下文携来源及版本，事实引用落到当前原文；上层摘要只用于找资料和组织回答。

现有RAG每次最多12条证据、总18,000字符，首期在此预算内比较多路候选的有效性。扩大预算不是首选优化；必要调整必须协调网关、Worker、请求冻结及测试。MCP首期增加受范围控制的主题导航/概览读取或搜索命中类型，具体工具契约在P0冻结；不把整库概要塞进每次工具描述。

## 8. 客户端体验

切到具体知识域可打开“知识库概览”：短概览、主题入口、资料数、已分析/已纳入覆盖状态、更新时间与待更新状态。主题按需展开和分页，不默认铺开全库长摘要；小域允许零/少量主题，不为结构凑数量。

点击主题查看简短说明及资料，点击结论展开原文证据。提供首次“构建概览”、更新策略/暂停、明确重建、人工调整主题及历史查看。付费发送说明包含本域原文节选、摘要、标签和个人补充等实际输入范围。

页面中的概览字数预算约束展示；后台来源映射和索引增长是正常的存储开销。不把少数主题或尚未加工资料从目录中隐藏。当前没有相关资料只能表述为“收录内容未覆盖”，不能推断用户缺乏该知识。

| P4 客户端概览 | 首页/主题下钻、覆盖状态、开启/暂停、人工调整 | 一个域完整可用，窄窗口无溢出，状态与后台一致 |
| P5 规模与完整交付 | 真实质量及成本报告、备份兼容、完整运行包和App | 工程门槛通过，规模对照达标，用户可核验并明确局限 |

顺序P0→P1→P2→P3→P5。P4可在P0冻结后实现视图，动态接入等待后端；不把静态界面称为完成。首个纵向验收：一个域首次构建→主题下钻→原文问答→修改一篇→增量更新→删除后立即排除。

如用户后续授权并行，P0完成后可分为生成/发布、客户端、检索/评测；models/migrations/契约等共享文件由单一负责人维护。未经当次授权不主动启动子Agent。

## 10. 规模、质量与业务验收

20/100/300/1000篇，覆盖约10万/50万/100万中文字符的不同组合，篇数与总字数分别记录。短笔记、中长文、同主题、跨主题、重复、少数反例、版本冲突、OCR噪声和未分析资料均纳入；不为凑百万字机械重复同一段文本。token使用目标模型分词或网关实际用量记录，不能把字符数当token。

基础问题集在P0固定，增长实验保留已有问题和真实证据，加入无关、相似、相反资料测抗干扰；新增知识的问题另建扩展集，避免问题答案实际变化却被误判退化。

| 指标 | 验证方式 |
| --- | --- |
| 细节召回 | 当前原文答案是否进入候选及最终上下文；包含概览没有的稀有细节 |
| 整体理解 | 多主题覆盖、重复去除、条件和不同观点保留，由人工核对 |
| 引用与事实 | 引用存在且当前有效、原文支持结论；虚构与错位列严重问题 |
| 生命周期 | 新增/修改/移动/删除/撤权、重启和恢复后是否失效及正确更新 |
| 阅读价值 | 用户理解知识域、定位资料的用时与操作数，概览是否减少阅读负担 |
| 成本性能 | 首次/增量调用数、input/output token、索引耗时、查询P50/P95、冷/热启动、峰值内存 |
| 规模退化 | 同问题跨规模的召回/回答变化；分别记录细节与整体问题，不能只报一个总准确率 |

对照至少包括当前原文/单篇摘要混合检索、新增主题召回、主题+原文多路召回。在相同答案模型、候选/上下文预算下比较；分批全局处理额外成本单独记录。P0依基线预先冻结可接受退化区间、目标改善和成本预算，结果出来后不能改标准。

硬门槛：跨域/权限泄露、已删除内容进入当前回答、旧结果覆盖新版本、无依据结论、恢复重放收费请求均需修复。主题统计不得双来源重复计数。不能以ID合法代替语义事实正确。

优先使用获准真实或合成资料；真实模型费用授权与工程实现授权分开记录。模拟测试只证明工程路径。现有DeepSeek合成验收不能代表本轮规模和主题质量。

## 12. 研究依据与解释边界

- [RAPTOR](https://arxiv.org/html/2401.18059v1)：多层摘要与多粒度召回可改善特定任务；严格逐层路由并非必然最优。摘要仍可能含错误，不把论文收益外推到本项目。
- [GraphRAG](https://www.microsoft.com/en-us/research/publication/from-local-to-global-a-graph-rag-approach-to-query-focused-summarization/)：整体问题可受益于社区摘要，百万token实验不能当成本项目百万中文字的验收。
- [RULER](https://arxiv.org/abs/2404.06654)、[Lost in the Middle](https://arxiv.org/abs/2307.03172)：被测模型存在长上下文利用限制，不以标称窗口证明准确率。
- [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)：关键词与向量互补、具体片段上下文与排序需评测；不照搬其模型、数量和收益。
- [动态递归摘要维护](https://arxiv.org/abs/2410.01736)：新增/删除可能影响层级组织，增量维护需要设计和验证。

本计划采用上述思路的必要部分，不直接复制框架，也不承诺毫秒级全库处理或规模增大后准确率不变。
