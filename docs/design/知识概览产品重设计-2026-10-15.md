# 知识概览：产品与交互重设计

日期：2026-10-15。状态：第一批三页结构、加载缓存、原位阅读、信息契约与问答范围已实施并完成免费工程验收，见 [交付记录](../verification/a1/domain-tabs-acceptance-20261015.md)。后续统一授权加工编排仍待实施；主导航入口沿用现有概览弹窗。本文件保留完整目标设计，实施范围以交付记录为准。

本版依据用户对页面范围的修正：这是当前知识域的概览页，顶部固定为“概览、主题分类、知识域信息”三个入口。取消上一版左侧“全部资料”“按主题阅读”菜单；主题分类集中到分类树中呈现。

## 1. 产品任务

服务于收集、阅读和复用资料的个人知识工作者。这个页面要让用户迅速知道：这个知识域包含什么知识、有哪些值得使用的观点、原文依据在哪里，并能在当前范围内检索和提问。

主要使用路径：在“概览”了解当前知识域，在“主题分类”找到分类与文件，在“知识域信息”了解资料规模、分析覆盖和检索准备情况。概览及已有问答保留，具体结论仍可核对原文依据。

底层采用分层加工；用户看到的是清晰、有限的阅读层级。日常浏览不要求理解加工树、复用节点、向量或 token。

## 2. 当前问题及设计决定

| 当前问题 | 设计决定 |
| --- | --- |
| 成果、后台任务、预算、维护按钮出现在一个长滚动页 | 主页面呈现知识；更新记录、设置和诊断由“更多”进入 |
| 侧栏“全部资料”“按主题阅读”与知识域原有导航重复 | 取消这两个侧栏菜单，使用顶部“概览、主题分类、知识域信息”三个入口 |
| 首屏只有一句话，核心要点默认折叠 | 首屏呈现一段概览和最多 3 条核心要点，其余按需展开 |
| 主题只有平铺的名字和篇数，资料层级不清晰 | 主题分类用可展开的树呈现，分类为分支，文件为叶子；不再新增平行的“按主题阅读”菜单 |
| 点击资料会退出概览，无法就地核对结论 | 点击结论旁的“依据”打开原文侧栏；查看全文后可以原位返回 |
| 页面完成并不能解释本次覆盖了什么 | 显示已纳入篇数、未纳入原因、更新时间；不把纳入篇数等同全文或图片理解 |
| “索引可用”混淆阅读、检索与 Agent 状态 | 各状态分别记录；常态隐藏索引技术细节，异常时给出具体修复操作 |
| 用户需要手动刷新才能确认完成 | 页面可见且有活动任务时自动读取本地状态，完成后自动显示当前有效结果 |

## 3. 页面结构

将页面放在当前知识域的主工作区，保留应用原有知识域切换方式，避免用固定尺寸弹窗承载长期阅读。页面顶部只有“概览、主题分类、知识域信息”三个入口；不在页面左侧增加“全部资料”或“按主题阅读”。小窗口保留这三个入口，分类与原文按层级单列浏览。

### 顶栏

- 当前知识域名称；深入分类或原文时显示可返回的路径。
- 顶部三个入口：概览、主题分类、知识域信息。切换入口保留各自浏览位置。
- 内容状态与更新时间：与后台任务状态分开。
- 一个随状态变化的主操作：生成概览、更新概览、查看更新进度或检查问题。
- 更多：更新设置、更新记录、服务诊断。管理分类从“主题分类”的局部入口进入。

已有有效概览且资料未变化时，默认显示“已更新”；需要强制重新生成时从更多入口进入，并再次确认调用范围。读取结果不触发模型调用。

### 入口一：概览

保留已有概览的内容及阅读能力，本次不改变总结生成规则，也不为分类树另生成一套概述。

1. **整体理解**：一段简短概述，初始目标约 80–150 汉字，表达这个知识域涵盖的内容；生成质量规则另行验收。
2. **核心要点**：最多 3 条默认可见，每条一句、可点击原文依据。额外要点展开查看；无依据时不补造。
3. **适用条件**：会改变结论含义的条件紧邻对应结论展示；其余限制按需展开。界面不擅自推断哪些限制重要，缺少结构化绑定时先按原有顺序显示已有条件。
4. **覆盖与更新状态**：显示本次概览已纳入的资料范围和更新时间；未纳入资料可查看原因。详细规模统计在“知识域信息”中集中查看。
5. **当前范围内提问**：输入框说明实际范围；提问的授权、发送数据和用量提示沿用既有规则。

概览页不再附加完整资料清单或第二套主题导航；用户通过顶部“主题分类”浏览结构与文件。

### 入口二：主题分类

分类树表达用户真实的主题与文件归属，不把后台加工批次变成分类节点。第一批复用当前最多两级主题的约束，树为“一级分类 → 二级分类 → 文件”；没有子分类时文件直接挂在一级分类下。不在本次改动中承诺无限层级。

```text
当前知识域
├─ 独立开发
│  ├─ 需求发现
│  │  ├─ 文件 A
│  │  └─ 文件 B
│  └─ 文件 C（一级分类直属文件）
├─ SEO 与流量分析
│  ├─ 文件 A（同一文件的另一分类入口）
│  └─ 文件 D
└─ 未分类
   └─ 文件 E
```

- 分类是可展开、折叠的分支；文件始终是叶子。分类可同时有子分类与直属文件，现有直属关系不因呈现树形结构而改变。
- “未分类”是系统展示分支，收齐当前知识域中未归入任何有效主题的文件。无未分类文件时隐藏，不计入真实分类数量。
- 点击文件打开原文，返回后恢复展开状态、选中文件、滚动位置和顶部入口；切换到“概览”再返回也保持。
- 一份文件允许出现在多个分类下，均打开同一份文件。分类篇数显示本分支及其后代所含文件的去重数量；不能用直接成员数冒充子树数量，也不能把多个分类的篇数相加当知识域总数。
- 文件同属父分类和子分类时，保留两处实际归属入口；父分支去重篇数只计一次。单个分类的文件列表分页完整加载，不把当前已加载行数显示为总数。
- 分类的有效既有概览可按需查看，相关要点和原文依据仍可核对；分类树本身的浏览和展开不依赖先生成分类概览，不为填充树节点新增模型调用。
- 分类改名、归属调整等编辑保留在“管理分类”局部入口，不成为阅读前置步骤，不在本批引入自动移动文件或重写分类规则。

### 入口三：知识域信息

信息页回答当前知识域有多少资料、多少有效 AI 分析、占用多少本地存储，以及哪些检索能力已准备好。统计仅属于当前知识域与当前 App 范围，不拿整个账户或其他知识域的状态代替。

| 指标 | 产品口径 |
| --- | --- |
| 文档数量 | 当前知识域中未删除、未进入删除流程的去重资料数。链接、笔记、PDF 等均为资料，可按现有类型展示明细；同一资料多分类只计一次 |
| AI 分析数量 | 当前原文版本及当前分析上下文仍有效、输出契约通过的完整单篇产物数量；不数历史成功任务、重复分析或长文中间分段。可显示“当前有效 X / 总文档 Y”，另列未分析、需重新分析和进行中状态 |
| 概览覆盖 | 最新当前有效概览实际纳入的去重资料数及未纳入原因。与单篇 AI 分析数量分别展示；例如“AI 分析 4/4”不能自动推出“概览纳入 4/4” |
| 本地存储占用 | 使用磁盘存储口径，不叫“内存大小”，不表示 RAM。附件与已保存图片可按实际字节聚合；正文、AI 产物及本地索引需区分逻辑数据量与物理占用估算。共享 SQLite 文件不能直接按域均分后称精确值 |
| 标签数量 | 仅统计当前域资料关联的有效正式标签，按标签 ID 去重；同一标签同时来自人工和 AI 时总数只计一个。来源可以分别查看，两种来源有交集，不能相加当总数；不统计未确认建议与旧版本失效 AI 标签 |
| 分类数量 | 当前范围内实际呈现的有效主题节点数量，包含一级与二级节点，按节点 ID 去重；不包含文件叶子、加工节点和系统“未分类”分支 |
| RAG 情况 | 分层展示原文索引、单篇摘要索引、主题索引、知识域索引的当前可用量及待处理、失败、关闭或无有效产物状态；索引可用不等于答案准确，不能用一个模糊的“已接入 RAG”代替 |

存储明细必须说明是否含历史版本与可重建索引；不同口径不混合相加。首批没有准确归属的数据就标为“暂不可统计”或“估算”，不以 0 替代未知，也不把整个数据库文件大小显示为当前知识域占用。

RAG 按当前版本逐层判断：原文索引绑定当前资料版本；摘要索引绑定当前有效单篇分析；主题与知识域索引绑定当前有效概览及其依赖。资料改变、删除或移出知识域后，过期产物不计入当前可用量。未开启语义检索时明确显示“语义检索已关闭”，保留实际可用的关键词检索说明，不误报为索引成功或处理失败。

所有统计附更新时间并使用同一统计范围或快照；页面可见时支持本地刷新。查看信息、展开分类和读取原文均不调用模型。索引维护和技术诊断放在信息页的次级入口。

### 原文依据

- 点击某条结论的“依据”，展示该结论实际引用的资料和原文段落。
- 显示标题、版本、页码或文字位置；一条结论引用多篇时可以逐篇切换。
- 显示原文与概览的区别；个人备注及系统归纳有明确标识。
- 查看全文和返回均保留知识域、主题、结论及滚动位置。
- 每次读取核验当前权限、原文版本及删除状态；失效时说明原因并提供返回/更新操作。
- 列出某个主题所含的全部文章，不等同于证明某条具体结论。

## 4. 首次生成与更新流程

首次进入 → 显示资料范围和产出说明 → 点击“生成概览” → 审阅并确认 → 后台处理 → 自动显示结果。

已有结果 → 资料发生变化 → 显示待更新状态 → 点击“更新概览” → 确认本次范围 → 自动显示新结果。

确认界面只要求用户判断真实业务事项：

- 当前知识域或主题和纳入资料数；缺失、过期分析的资料数。
- 正文/备注/摘要/分类中实际会发送到已配置网关的内容类型。
- 是否消耗 AI 用量；如无法准确估价，不给出虚构金额。
- “开始更新”和“取消”；调用数、输入预留、步骤等技术明细放在展开区。

后续可增加同一次授权中的“补齐缺失单篇分析 → 更新主题 → 更新知识域 → 建立检索索引”编排。此能力目前需要新增实现，不能仅修改按钮文案就承诺已具备。第一批必须给出可执行的缺失资料入口。

自动更新默认关闭。设置入口表达“资料变化后自动更新”及累计用量上限；读取本地任务状态与自动发送 AI 请求分别处理。

## 5. 状态与失败路径

| 情况 | 页面呈现 | 用户下一步 |
| --- | --- | --- |
| 知识域没有资料 | 空态说明，收集资料入口 | 添加资料 |
| 有资料、尚无概览 | 范围说明及可得到的概览/主题内容 | 生成概览 |
| 更新进行中 | 显示已确认的真实阶段与已完成量；无法确定剩余时间就不估算 | 继续浏览，或查看进度 |
| 更新完成 | 自动切换到成果，显示更新时间、纳入范围 | 阅读主题、核对依据、提问 |
| 部分覆盖 | 概览显示“已纳入 3/4 篇”，展开缺失文章和具体原因；信息页分别列有效分析数与概览覆盖 | 打开资料完成分析，之后更新概览 |
| 原文或归属已变化 | 当前概览失效，显示变动待更新；主题分类树仍可用，知识域信息据当前范围刷新 | 更新概览；过期结论不进入当前检索 |
| 索引尚未完成 | 概览仍可读；说明检索正在准备及已有可用检索方式 | 等待；失败时修复本地检索 |
| 网关或凭证错误 | 可理解的连接/授权错误，不暴露敏感信息 | 打开 AI 设置检查；不自动重发付费请求 |
| 输出校验失败 | 明确本次概览未生成；展示仍有效的已有成果状态 | 查看原因后手动重试 |
| 请求结果未知 | 与明确失败区分，先恢复原请求状态 | 检查原任务，明确确认后才另建请求 |

任务失败与旧成果是否有效分别判断。旧成果依赖已变化时，不展示为当前有效内容。中途完成的节点不冒充全域完成。

## 6. 词语、阅读量与视觉

- 固定词汇：知识域、知识概览、主题分类、知识域信息、资料、原文依据、更新。
- 在日常页面移除“加工节点”“批次”“复用”“重建向量”等内部词汇。
- “已纳入 4/4 篇”附范围说明：依据单篇摘要和原文节选；不暗示全文和图片全部经过理解。
- 主题说明直接使用当前有效结果的短摘录，不为填充界面另调模型。
- 原生 macOS 字体、现有深浅色体系和暖棕强调色；选中层级和依据链接保持稳定视觉位置。
- 减少大面积圆角容器，使用标题、留白与细分隔线表达阅读结构。
- 主窗口可调整大小；窄窗口原文侧栏转为单独阅读页，具备明确返回入口。
- 时间按设备时区展示；键盘可达、焦点可见、动态字体、深浅色和小窗口均需验收。

## 7. 与现有实现的对应关系

| 设计内容 | 当前基础与实施边界 |
| --- | --- |
| 顶部三个入口、概览保留、加工记录移位、状态自动读取 | 基于已有导航、构建和调度接口重组客户端；不新增左侧全部资料或按主题阅读菜单 |
| 主题分类树与文件叶子 | `DomainTopic.parent_id`、主题目录及成员分页接口现成；当前主题限两级，各层可直接挂文件。需补全未分类文件入口、树状态保存和子树文件去重计数；不修改已有归属规则 |
| 分类概览与准确更新时间 | 概览结果已有时间，Swift 模型尚未接收；如展示分类概览状态，批量带出已有有效结果，避免逐节点查询或额外模型调用 |
| 知识域信息只读契约 | 目前没有统一域级统计接口。已有文档总数、主题数、未分类数；需聚合当前有效单篇分析、有效标签、存储明细与分层 RAG 状态，并返回范围及统计时间/版本 |
| 有效分析与标签统计 | 复用 `current_summary_artifact` 的当前版本、上下文及输出校验语义；正式标签沿用当前有效关联规则，并按标签 ID 去重，人工与 AI 来源可交叉，不另起不一致的有效性判断 |
| 本地存储统计 | 附件及图片有 `size_bytes` 可聚合；正文、AI 产物及共享数据库索引尚无准确的域级物理字节契约，先明确逻辑量/估算/未知，不用总库文件大小替代 |
| 当前域分层 RAG 状态 | 逐文原文及摘要索引、逐主题与域概览节点索引已有状态函数，需在当前范围聚合；`/v1/search` 返回的账户级索引状态不能直接用于本页 |
| 结论点击原文依据 | 结果含引用 ID，但导航接口缺少引用到当前原文位置的完整映射；需增加受权限与版本校验保护的解析契约 |
| 当前知识域问答 | RAG API 支持 domain_ids，但客户端请求尚未传入当前知识域；需贯通并验证 |
| 当前主题问答 | 需增加真实的主题资料范围过滤；只把主题名称写入问题不算实现 |
| 缺失单篇分析一键补齐 | 需要任务编排、范围快照和统一授权；首批不冒充已具备 |
| 原位阅读与返回 | 当前点击原文会 dismiss 概览，需调整导航和局部状态保存 |
| 更新变化说明 | 当前可显示时间与覆盖范围；精确“新增知识点”需要版本差异能力，暂不承诺 |
| MCP 生效状态 | app/shareable 范围独立；需真实检验共享产物和依赖权限，不能用 App 完成状态代替 |

本次设计不改变检索融合算法，不扩大数据发送范围，不增加自动分类、知识图谱或新的云服务。实施时保持人工标签、人工主题调整和原文数据的既有语义。

## 8. 推荐交付顺序与验收

### 第一批：三页结构与完整阅读闭环

顶部“概览、主题分类、知识域信息”三个入口；概览保留短概述、要点、条件、原文依据及已有问答；分类树展示两级主题、直属文件与未分类文件；结论依据原位阅读、结果/进度分离、自动本地状态读取、准确覆盖状态、当前知识域问答范围。原文依据映射和统一知识域信息只读契约均为本批交付必要条件。

信息契约的首批范围：文档去重总数、当前有效分析数量及状态、概览覆盖、分类数量、有效正式标签数量和来源交集、可明确归属的本地存储明细，以及当前域原文/摘要/主题/域四层检索准备状态。所有字段明确范围、分母、更新时间和未知状态；避免客户端逐篇串行请求和反复全域校验。

验收：未接受培训的用户能在 30 秒内说明知识域主要内容；从要点到对应原文不超过两次操作；从分类树找到并打开文件，返回后展开与滚动位置不丢失；未分类文件不遗漏，多归属文件不抬高域总数；信息页可区分当前有效分析、概览纳入及索引可用三种数量，且不出现其他域数据或虚构存储值；无需接触加工节点完成“了解 → 查找 → 核对 → 提问”。检查可用性任务，不以截图美观代替验收。

### 第二批：一次授权完成更新

缺失/过期的单篇分析接续、分层更新及索引准备统一编排；真实失败与未知请求不能盲目重放；自动更新设置产品化。

验收：部分资料未分析时，用户只确认一次范围和用量，系统能完成可追踪的端到端流程；任意阶段失败有准确恢复方式。

### 第三批：检索和 Agent 的可核验反馈

问答提供资料依据及实际范围；进阶详情可见概览参与的检索溯源；Agent 接入处明确共享范围和可用状态。

验收：App 私有概览不会流入 MCP；授权范围内的产物可正确召回；过期、删除及撤销访问后的引用均受约束。

原型中的文案和问答使用示例数据，所有交互仅演示目标体验，不调用模型、不修改实际知识库。
