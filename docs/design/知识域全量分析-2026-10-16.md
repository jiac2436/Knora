# 知识域全量分析

日期：2026-10-16。实现以 `services/api/app/domain_full_analysis.py`、`domain_full_runtime.py` 和 `services/worker/domain_full_analysis.py` 为准；本轮复用现有单篇分析、主题、分层概览、SQLite 和本地索引设施，没有增加运行依赖。

## 1. 用户操作与范围

当前知识域概览 → **全量分析…** → 自动读取预览，核对复用／待补分析／阻塞文件和授权上限 → **开始全量分析** → 查看阶段进度 → 回到概览、主题分类与知识域信息三页查看结果。预览读取失败或需要重新检查时，可手动重新预览。

默认复用有效结果，只补齐未分析和已过期的资料，然后更新主题与知识域概览，最后确认本地检索索引状态。普通“更新概览”及既有自动合并更新只加工已有有效摘要，不负责补单篇。全量分析需要用户明确发起，没有新增入库即收费或自动全量加工策略。

本次仅支持当前所有者的单个知识域、`app` 范围，包括该范围中的私有资料；Agent 凭证不能调用全量接口，不能据此扩大 MCP 的授权范围。正文、备注和分类等会按现有单篇／节点契约发送到已配置的 AI 网关，结果存回本地。预览和查询本身不调用模型。

## 2. 处理链路

```text
冻结整域输入、生成预览
  → 明确确认，持久化一次授权总任务
  → 逐篇检查：有效结果复用；缺失／过期结果创建单篇检查点
  → 等待当前摘要检索数据就绪，维护本地候选主题
  → 按实际结果冻结 DomainBuild，生成主题／域概览
  → 检查当前原文、摘要、主题、域的关键词／向量状态
  → completed；失败或未知则停止后续，索引失败为 partial
```

总任务使用独立 `DomainFullAnalysisJob`，不把 `DomainBuild` 当作整条流程的占位表。Worker 每次只登记一篇，单篇长文沿用既有分段与合成检查点；等待时让其他任务及免费本地索引继续运行，不一次性排队所有收费子任务。已有兼容单篇任务可以等待复用，取消总任务不会擅自取消独立任务。

复用依据为当前有效摘要及其真实原文引用，不依据旧任务的 `completed` 字段直接判断。标题、正文版本、个人上下文或原文引用失效时不能复用。有效旧 v2 分析也可复用，所以全量完成不代表每篇旧资料都补齐新版 AI 标签；新补做的分析采用统一 v3 管线，手工标签不受替换。

## 3. API 契约

统一前缀：`/v1/domains/{domain_id}/analysis/full`。均要求 App 身份及该知识域所有权；`scope` 只能为 `app`，额外字段按严格模型校验。

| 方法与路径 | 请求 | 响应与行为 |
| --- | --- | --- |
| `POST /preview` | `{"scope":"app"}` | 返回当前预览；不建任务、不调用模型 |
| `POST /jobs` | `request_id`、`preview_hash`、`confirmed:true`、`confirmed_unknown:false`、可选 `scope` | `202`，返回总任务；相同请求返回同一任务 |
| `GET /latest` | 无 | `{"job":null}` 或 `{"job":{...}}` |
| `GET /jobs/{job_id}` | 无 | 返回该总任务当前状态 |
| `POST /jobs/{job_id}/cancel` | `{"scope":"app"}` | 停止后续步骤，保留正式结果；在途请求保留未知提示 |

`request_id` 为 UUID，同一编号不得更换预览、范围或未知确认。客户端保存尚未确认结果的原编号和预览哈希；请求超时或丢失响应时，用原编号确认，不凭空创建第二个收费总任务。

预览主要字段：

- `preview_hash`、`total_sources`、`reused_sources`、`analyze_sources`。
- `documents:[{source_id,title,status}]`，状态为 `reused`、`analyze` 或 `blocked`，可审阅具体文件。
- `blocked_sources:[{source_id,title,reason,code}]`；域级阻断的 `source_id` 可为 `null`。存在阻塞时禁止启动，不偷偷跳过后宣称全量成功。
- `calls`、`input_token_reservation`、`budget_basis`，以及 `configured`。
- `requires_unknown_confirmation` 与 `unknown_sources`。历史当前输入的未知任务或域未知状态需要额外明确确认。

任务主要字段：`id`（同 `request_id`）、`status`、`phase`、总数／复用数／已分析数／完成数、`current_source_title`、`build_id`、`last_error`、带 UTC 时区的起止时间、`budget`、`documents` 和可选 `indexing`。文档行保留 `source_id`、标题、状态及可选子任务 ID、产物 ID、错误。

## 4. 一次授权与预算

一次确认同时覆盖待补单篇及后续主题／域加工，不覆盖原有 `DomainProcessingPreference`、自动更新开关或累计用量。域内已有全量或概览任务时阻止创建相冲突的新任务；普通手动及自动概览入口也不能穿过正在运行的全量任务。

没有待补单篇时，预览使用当前 `prepare_plan` 的实际节点预算，计入可复用批次。有待补单篇时，其输出和未来自动分类尚未知，后续不能伪装成精确计划：预览按既有 **最多 256 个节点、每节点最多 100,000 输入 token 的保守预留**授权。每篇先预检既有长文调用次数、请求字节上限及分段覆盖；单篇每次按 `512 KiB + 8192` 的保守输入预留计算。预留采用 UTF-8 字节等安全上界，**不是服务商分词器测量值，也不是实际账单**。

单篇入队时登记整篇多次调用的预留，概览节点在发送前逐次预留；重复读取或同一检查点恢复不重复登记。`used_calls`／`used_input_tokens` 表示已登记的预留，不能当作实际 HTTP 次数或实际费用。`actual_input_tokens` 本轮返回 `null`，表示未汇总实际计费用量，不能显示为实际输入零。后续实际概览计划若超过授权、存在排除项或覆盖不足，则停止，不追加隐式授权。

## 5. 输入一致性与失败处理

冻结资料集合、正文版本与原文哈希、标题、采集覆盖、可见范围、个人备注和项目上下文、人工标签含义／别名、拒绝记录、实践结果、人工主题结构与成员。整域依赖批量读取，每次派发和必要发布检查时重验；不会对每篇重复执行逐项 N+1 查询。

AI 新生成的摘要、标签及自动候选主题不纳入这份人工输入指纹，避免正常加工被误判为用户修改。原有分层节点仍继续校验实际摘要、主题、输入代次与证据。读取任务状态不创建替代任务；界面关闭后只要客户端服务仍运行，原任务可继续。

| 状态／阶段 | 含义与后续 |
| --- | --- |
| `pending`／`running` | 当前总任务有效，阶段为 `documents`、`overview` 或 `indexing` |
| `completed` | 当前所需正式结果和已启用的本地索引检查完成，阶段为 `completed` |
| `partial` | 正式结果保留，但部分本地索引失败；不能显示为全量检索完成 |
| `failed`／`stale` | 失败或输入变化，停止后续；处理原因后重新预览，复用仍有效产物 |
| `unknown` | 在途调用结果无法确认，可能已产生用量；不重放，后续新任务需额外确认 |
| `cancelled` | 已停止尚未发送的后续步骤；已完成正式结果保留 |

取消在途请求时，总任务和域状态显示未知，保留原请求记录；父单篇任务停止，阻止长文下一段，已完成的分段检查点保持原状态。没有扩大旧分段状态枚举。重启仅继续能证明尚未发送的检查点；中断的在途调用不能因重启再次发送。

## 6. 规模与能力限制

- 最多纳入 **5000 篇资料**，实际分层加工还受 **256 节点**约束；已有人工分类与资料规模必然超限时，在预览阶段阻止启动。5000 是输入硬上限，不表示所有 5000 篇组合都能完成。
- 单篇最多沿用现有 8 段加最终合成；若因工程上限导致 `analysis_plan.coverage=partial`，阻止全量启动，不能悄悄截断。原始采集本身为部分正文时，仍保留原采集覆盖提示；“全量”表示纳入当前可处理资料，不保证找回未采集原文、纯图片语义或原件缺失内容。
- 复用摘要及引用必须能进入既有有界概览；单篇尚未解析、无可读证据，或已有摘要／引用超限时列明阻塞。新输出无法满足后续节点边界时停止，不把部分覆盖发布为全域完成。
- `PKA_SEMANTIC_ENABLED=0` 时建立并确认关键词检索，向量层显示停用，不能宣称向量就绪；启用向量时需等待当前原文、摘要及节点向量实际就绪。
- 不新增跨域合成、云同步、会员计费、视觉大模型或自动付费触发。MCP 继续按原有授权与当前证据检索，App 全量完成不会自动扩大分享范围。
