# M4：已提交采集任务与旧队列交接

本文件细化已确认方案B2，不改变M0—M5顺序。客户端保留草稿、未提交条目、文件选择及展示；本地Owner确认提交后，内核负责接收、持久任务、原件、幂等、飞书加工与重试。

## 持久化与兼容

- 使用设备执行目录 `data/jobs/capture-queue-v1/`，每个稳定UUID一份v1任务元数据；飞书正文/图片检查点与原件分别保存。通过平台私密I/O、队列锁、原子写发布，不增加SQLite表或更改schema16。
- 此目录不属于可移植知识数据，不进入备份、同步或可读导出。成功归档的资料/图片仍用原SQLite、assets、版本及幂等表。恢复知识库不自动恢复待执行的设备任务、CLI路径或授权。
- 提交契约只接收当前本地库客户端暂存区中的相对原件标识和摘要，不接受任意绝对文件路径、其他库路径或符号链接。CLI路径/profile是显式设备选项，不包含访问凭证。
- 接收时先复制并校验原件，再原子发布任务和接收回执。客户端保存回执后才清理旧暂存。网络响应丢失或客户端写盘失败时保留原件，可按相同条目ID查询/重交接；不同输入不能覆盖同一ID。
- Worker创建资料继续使用原客户端条目ID作为幂等键，保留旧UUID字符串大小写。SQLite提交后即使执行检查点没写完，恢复也通过原幂等记录找到资料，不重复创建。图片逐张以稳定ID和SHA校验，已保存的图片跳过。
- 任务状态：`queued → running → completed/failed`。Worker中断后从检查点恢复未完成的采集任务；这些是本地归档/只读CLI工作，不创建模型任务。失败仅显式重试。移除终态任务保留幂等回执，清理其暂存；运行中不允许直接删除。

## 旧Swift队列

旧 `capture-queue/queue.json` v1继续可读。仅迁移已设置提交目标的条目，校验目标属于当前Owner；未提交条目与草稿留客户端。保留条目ID、冻结领域/项目、已生成飞书正文/版本、图片ID和已上传记录。存在sourceID时核对当前Owner与幂等记录；不能把其他资料绑定进任务。

迁移按条目发布回执，中断可重复执行；已接收条目先查询内核状态，不能重复读取或重新建资料。客户端成功保存对应任务引用后清理旧原件；迁移错误、损坏格式、未知版本均保留旧文件。

## 飞书与平台边界

共享内核负责链接/正文/XML版本校验、图片清单、下载/官方预览回退、总量限制、Markdown替换、归档与恢复检查点。外部CLI执行与系统OCR通过平台能力接口；macOS原生辅助程序复用M3受限命令与Vision实现，只返回类型化结果。父进程退出、超时、取消会回收辅助程序及其CLI，输出和临时文件有界，不记录授权或正文。

客户端保留CLI授权/连接交互、路径选择和状态展示。既有 `/v1/captures`、文件/图片接口继续兼容；本地队列接口仅允许当前安装的Owner，不向只读MCP开放。M5同版运行包必须包含原生辅助程序与内核新模块。

过渡兼容：明确选择外置开发API时仍使用旧Swift采集路径；正式本地App走共享内核。本阶段保留这些旧方法，不把它们误写成已删除。移除失败任务会结束其未归档图片的等待状态；永久删除资料联动清除设备执行原件，留下防重放回执。

验收重点：提交响应丢失、接收后客户端落盘失败、旧队列迁移中断、原件篡改/越界、正文已入库图片部分上传、Worker重启、重复提交、失败保留与终态清理、草稿保留、跨库响应隔离及无真实模型调用。

实施和实际测试结果见 [M4阶段记录](../verification/kernel-refactor-20261020/M4.md)。
