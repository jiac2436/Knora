# 文章图文联合分析

## 产品行为

仍使用文章内的一个“AI 分析”按钮。预览确认范围包括正文、个人补充和已归档图片；模型综合成原有的精简概览、总结与标签，不增加逐图报告。结果注明结合的原图数量，图片结论的依据可以打开对应原图。只打开文章、刷新或下载图片不会调用模型。

本轮使用当前正文基础版本对应的 `SourceImage`，主要覆盖微信与飞书文章。未保存成功的图片会阻止图文分析，提示先补齐或重试；不会悄悄只分析正文。旧微信文章有图片地址但没有归档记录时，先执行“补齐文章图片”。

## 处理过程

1. `ai.freeze_snapshot` 冻结当前正文与图片指纹。`ai_images.bind_images` 给每张图增加独立的虚拟证据引用，保留原文证据与位置；微信按图片占位顺序匹配，飞书优先按本地图片标记定位。
2. 计划中只保存图片 ID、顺序、摘要、尺寸、格式及随机文件键，不保存 Base64。计划哈希包含图文输入，确认后发生变化需重新预览。
3. Worker 发送前读取本地原件、核验大小和 SHA-256，再临时生成内联图片数据。路径不能逃逸原件目录或使用符号链接。
4. 网关再次校验真实格式、尺寸与摘要，通过 Chat Completions 混合文字／图片输入发送。需要支持视觉的模型，未配置时明确失败，不能退回只读正文。
5. 超出单次限制时复用现有分段检查点。每段联合理解相邻正文与图片；最后只汇总已审阅的分段结果，不重复上传图片，也不声称重新看过原图。
6. 发布前再次核对输入版本。图片结论保存在分析产物，并进入现有摘要检索索引；不把识图结果冒充原文或写回原文证据。

## 长图与批量限制

| 项目 | 当前限制 |
| --- | --- |
| 原图 | 每篇最多 200 张，单张最多 20 MiB、3000 万像素 |
| 单批 | 最多 14 张原图、64 个图块，原件累计预算 22 MiB |
| 长图 | 4096 像素图块、步长 4000，保留 96 像素重叠和原图坐标；不整体缩小 |
| 传输 | 图文请求最多 32 MiB；切图后的 PNG 体积也检查，超限拒绝 |
| 调用 | 最多 8 个分段与 1 次合成；预算内一次完成 |
| 动图 | 只理解提供的静态帧，不能声称读完动画 |

超限要求拆分文章或图片，不能静默丢图。分段调用可能重复携带该段正文，以便图片保持上下文；实际调用数在预览计划中显示。失败、结果未知和中断检查点沿用既有阻断规则，不自动重发付费请求。

## 配置与兼容

- 数据库仍为 schema16，无新依赖或备份迁移；使用既有图片原件、产物与检查点结构。
- 分析请求保留 v3，增加可选 `images` 与证据 `image_id`；旧纯文请求、旧产物和旧客户端 DTO 可读。
- 客户端授权命名空间更新为 `v4-images`，旧纯文授权不能自动扩展为上传图片。
- 全域分析规则更新为 `domain-full-v2-images`；旧总任务不能扩大授权继续，需重新预览。已有图片但只有纯文分析的资料，在新的全域计划中需要补分析。
- API、Worker 与客户端一起重新构建；独立网关加载同一契约及 `vision.py`，配置 `PKA_AI_VISION_MODEL=deepseek-flash` 后在原终端重启。主模型已经是 `deepseek-flash` 时可复用。样例配置不含密钥。
- 历史纯文产物保留并明确注明未包含原图，不自动重新调用。历史备份可恢复；使用新版创建的图文产物应由同版客户端/API/Worker读取，不承诺旧程序理解新增图像引用。

## 尚未覆盖

普通网页、PDF 内嵌图片若未归档为 `SourceImage`，不会因为此次升级自动被提取。现有 RAG 回答仍使用原文文字证据；本轮让图像结论参与摘要召回，并未完成整个问答与 MCP 的多模态证据复核。结构校验不能证明图表语义正确，真实模型质量需单独验收。

DeepSeek 视觉输入依据：[官方文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)。工程验收及真实测试状态见 [本轮记录](../verification/a1/joint-images-acceptance-20261017.md)。
