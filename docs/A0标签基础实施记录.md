# A0 第一批：标准标签与标注来源

日期：2026-10-03。范围：标签基础、人工标注与本地保存。AI 标签候选生成、结构化文档总结和检索整合在后续批次实施。

## 已实现

- 标准标签分主题、内容类型、涉及对象三维度；主题支持两级关系，拒绝环路及跨维度层级。
- 稳定标签 UUID、标准名称与别名；NFKC/空白/大小写规范化，同一 owner/维度名称和别名统一解析，不重复创建词条。
- 词条创建、改名、别名增删、主题父级调整、同维度合并；合并前客户端明确确认，转移所有文档关联、保留来源、原词条名称成为别名。
- 文档—标签关联按 source/tag/origin 存储；origin 仅 ai 或 manual。用户添加的来源由服务端固定为 manual，客户端不能伪造 AI 来源。
- 同一标签可保留两种来源，界面去重并人工优先显示；移除只处理选定来源，不误删另一来源。AI 依据绑定正文版本，过期单独标识；人工关联不因正文重解析消失。
- 旧关键词规则标签独立展示为历史规则，不转换成 AI/人工来源。旧 tags 名称数组保留展示兼容，新增 tag_details 与 legacy_rule_tags。
- Mac 设置增加“标签管理”；阅读器增加“标签”入口，支持人工关联及按来源移除。库/服务/资料代次及读取代次保护晚到响应；标签写入与备份、切库、AI 配置重启、回收站操作互斥。

## 数据与兼容

Schema v3 → v4，新增 knowledge_tags、knowledge_tag_aliases、tag_assignments。升级前受控备份，按版本校验 journal 触发器；v1/v2/v3 备份继续验证和恢复升级，旧客户端不能打开 v4。

标签词条和别名按 tag 聚合记本地变更，文档关联按 source 聚合记变更；固定提交增加 tag 实体、父标签依赖与 source.tag_assignments 及标签依赖。本批没有远端同步服务；接收端须在后续阶段冻结新增契约。

完整备份保留标签目录、别名及双来源关联；可读导出 metadata 新增 knowledge_tags，文档新增 tag_assignments/legacy_rule_tags 与正式标签段落，区分来源和旧版本依据。永久清理资料删除关联，但保留共享标签目录；恢复及重建关键词不会消耗模型或改写人工标签。

## 使用与后续

退出旧客户端并打开新构建，设置 → 标签管理创建词条/别名，在资料阅读器 → 标签添加人工关联。合并不能直接撤销，确认前检查目标标签；如网络中断，刷新目录确认操作结果，不把缺失旧词条误当作仍未合并。

本批提供 AI 来源的数据结构和显示兼容，没有让当前分析接口生成新的正式 AI 标签；也没有实施新总结契约、标签筛选或总结检索。下一批连接 DeepSeek 生成文档总结及 AI 标签候选，用户确认后创建 ai 关联，并补接受/拒绝与同版本抑制。
