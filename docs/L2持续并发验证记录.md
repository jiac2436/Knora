# L2 持续并发验证记录

日期：2026-10-01。范围：单台 Mac 的 5 分钟有限并发冒烟，以及一次 10 秒检索契约短测。

## 场景与隔离

新增 `apps/macos/scripts/local_load_test.py`，用已验证的独立 Python 运行包直接启动本地宿主与 Worker。环境变量按客户端模式显式配置，仅使用临时 home、数据库、资产、缓存和日志目录；随机本地凭证通过 stdin 交付，不写入 argv、环境变量、输出记录或 Keychain。结束后关闭父管道、检查退出与锁释放，临时目录自动清理。

测试保持默认语义能力开启，使用随包 embedding 模型。四个并发客户端分别为两个写入循环和两个读取循环：

- 写入循环每约 4 秒创建合成笔记并重复相同幂等键，核对返回同一个资料 ID；每十轮创建并重试一个小 CSV，下载核对原始字节。
- 读取循环每约 1 秒交替请求健康、身份、资料列表和检索。
- 每约 5 秒读取测试宿主和 Worker 的 RSS，任务完成后核对数据库中的资料集合和后台任务，最多等待 120 秒排空。

没有使用正式客户端知识库，没有迁移旧数据，也没有改变服务或数据库的生产实现。本轮运行包清单再次验证 **19,875** 个文件/链接通过，摘要为 `735d2d0f85c061265661d8639fc1c4a48b60dff91daf41ec650f76a130bf3d56`。

## 5 分钟实测

机器为当前 arm64 Mac，系统 26.2。原始结果见 [load-smoke.json](./verification/l2/load-smoke.json)。

| 指标 | 结果 |
| --- | --- |
| 请求持续窗口 | 301.67 秒，目标 300 秒 |
| 统计请求数 | 929，全部成功完成 |
| 保存资料 | 164：148 条笔记、16 个 CSV |
| 幂等重复提交 | 均返回原资料 ID，数据库资料集合与新建集合完全一致 |
| CSV 解析任务 | 16 个全部 completed |
| 语义索引任务 | 164 个全部 completed |
| SQLite 完整性 | `ok` |
| 混合请求 P95 | 66.85 毫秒 |
| 宿主采样峰值 RSS | 307.00 MiB |
| Worker 采样峰值 RSS | 296.48 MiB |
| 内存采样次数 | 60 |
| 退出 | 宿主返回 0；本地端口关闭；实例锁、服务锁均释放 |

检索为真实本地 API 调用，后台索引为随包模型推理。此次持续测试未在每次检索中额外断言语义降级状态，因此不能仅凭 HTTP 成功声称每次检索都使用了语义结果。

## 检索契约短测

随后增加结束后的“有命中且 `semantic_index == ready`”检查，用新临时库运行更新后的脚本 10 秒。结果见 [load-contract-smoke.json](./verification/l2/load-contract-smoke.json)：8 条资料、2 个 CSV 解析任务、8 个语义索引任务全部完成，最终检索命中且状态为 `ready`，退出清理通过。

该次统计的 39 个请求覆盖设置、持续循环及文件核对；结束后检索契约检查另计，不包含在请求数与 P95 中。5 分钟结果来自新增最终检查之前的脚本，不把短测结果套用于此前每个请求。

脚本编译检查、无效时长在启动前拒绝及 `git diff --check` 均通过。没有修改正式 Sources 或随包后端，因此本轮没有重建客户端或重复全部后端单测。

## 复验

先通过既有运行包完整性检查，再运行：

```bash
python3 apps/macos/scripts/local_load_test.py /绝对路径/已验证的运行包 \
  --duration 300 --output /绝对路径/验收结果.json
```

时长限定为 10～1800 秒；输出位置需可写。在限制本机监听或进程指标读取的沙箱中，需要允许这两项测试能力。本轮已获准在默认沙箱外执行，仅测试合成资料与自身启动的进程。

## 验证边界

本轮是有限并发冒烟，不能证明全天稳定性、高负载容量、无内存泄漏或任意硬件上的性能。RSS 是每 5 秒采样得到的观察峰值，不是进程所有时间点的最大值；P95 混合了不同接口，不能作为单接口性能承诺。

未测试大文件、OCR 重负载、外网网页/飞书读取、满盘、物理休眠或大型数据库升级中断。L2 仍保留这些可靠性和发行门槛，不因本轮通过而标记全部完成。
