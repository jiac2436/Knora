# Codex 本地插件接入

## 实现范围

Codex 接入以每个连接独立的本地插件提供只读 MCP 和自动参考 Skill。新接入不向 `AGENTS.md` 添加规则。Claude Code、Workbuddy 的接入方式保持原有行为。

- 插件身份为 `pka-knowledge-<连接 UUID>`，同一有效授权复用连接；不同连接的凭证与领域权限相互独立。
- 插件含 `plugin.json`、`mcp.json`、兼容清单与 `skills/knowledge/SKILL.md`。本机 Codex 对插件与 Skill 组合名称存在长度限制，因此内部 Skill 使用短名 `knowledge`，命名空间长度为 60。
- 源目录位于 `~/.codex/pka-knowledge-plugins/`，本机凭证、启动器、所有备份与受管文件摘要在同级 `pka-knowledge-plugins-credentials/`，文件权限为 0600。插件包内无凭证和知识资料；连接依赖本机启动器与应用运行环境，不能直接作为跨设备通用包。
- 本机市场注册位于 `~/.agents/plugins/marketplace.json`，合并原市场条目。插件开关位于 Codex `config.toml` 的独立受管块，遵循 `CODEX_HOME`。
- 创建先验证 MCP 工具发现和只读检索，再发布本机配置；这一步不等于 Codex 已安装。用户须在 Codex 官方插件页安装一次，客户端通过只读缓存检查确认当前版本的 5 个文件与源插件完全一致，再执行实际缓存入口的 MCP 检查。客户端不调用官方暂不建议生产使用的 plugin/install 等实验接口。检查不调用模型；启停与移除不需要读取钥匙串。
- 用户在 Codex 中只切换受管插件的 enabled 布尔值时，客户端按实际状态显示并支持后续卸载。修改其余受管结构、插件文件、凭证文件或出现路径/权限问题时拒绝覆盖，并提示手动处理。

## 旧接入迁移

创建插件时保留旧接入。用户在 Codex 安装并启用后，回到客户端点击“完成接入”。客户端先检查旧 Skill/指令与 MCP 的受管归属及正式宿主缓存，只有检查成功后才移除同一连接的旧独立 Skill、精确匹配的指令块和旧 MCP 注册，保留用户原有指令及其他服务。迁移失败时，新插件停用或移除，并明确告知需刷新检查实际状态。

这些步骤跨多个文件，不能保证断电情况下整体原子。普通失败采取条件回退；检测到并发修改或不完整状态时停止，不覆盖用户更改。原配置私有备份保留在插件包外。

## 使用边界

- 客户端须持续运行；插件通过 endpoint 文件发现本知识库的新端口。
- Agent 自行决定是否选择 Skill，不保证每轮检索；总结与候选不能替代原文证据。
- 尚未提供通用公开发布、跨设备安装包或 Claude 插件格式。客户端断开后凭证失效，本应用受管源插件与连接文件移除；Codex 的缓存插件须在其插件页卸载，客户端不修改宿主缓存。
- 数据库 schema 和业务 API 不变；新增操作仅用于本机接入工具。
