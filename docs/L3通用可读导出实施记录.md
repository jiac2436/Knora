# L3 通用可读导出实施记录

日期：2026-10-01。承接本地备份、客户端恢复和活动库切换，本轮新增免费版通用可读导出。L3 的回收站和清理策略仍待实施。

## 用户流程与格式

设置“备份与恢复”新增“导出 Markdown 与原件…”。选择 ZIP 保存位置后暂停所属 API/Worker，取得停服数据锁并生成一致快照；导出完成或失败均尝试重连。输出不覆盖已有文件。草稿及未入库采集队列留在当前库。

输出是独立格式 `pka-readable-export`，版本 1，不能作为 `.pka-backup` 恢复包使用。解压后从 `index.md` 阅读目录，每条资料有当前正文、原始输入、网址、用户补充和原件链接；历史正文按版本保存。正文使用 Markdown 缩进代码块，保留文字并避免自动执行用户提供的 HTML 或链接，原始字段在 JSON 中完整保留。

| 内容 | 路径和规则 |
| --- | --- |
| 目录 | `index.md` |
| 资料 | `sources/000001.md` 等安全编号 |
| 历史版本 | `versions/000001-v000001.md` 等编号；实际版本号及 ID 另行记录 |
| 原件与图片 | `assets/`，安全编号及白名单扩展名；原名保存在元数据 |
| 业务元数据 | `metadata.json`，含资料、版本、证据与定位、个人补充、使用经验、域、项目、标签及原件/图片映射 |
| 完整性清单 | `manifest.json`，逐文件记录路径、字节数及 SHA-256 |

仅导出本地绑定 owner 的未软删除资料；关联域、项目和使用经验也按 owner 过滤。未引用原件、其他账号数据、SQLite、认证凭证、任务队列、缓存及日志不进入最终包。图片失败诊断在导出元数据中置空，状态、说明及 OCR 正文保留。已删除或其他 owner 的原件缺失不阻塞本次可读导出；选中资料的原件缺失、链接、大小或摘要不符则拒绝生成不完整包。

文件名不使用用户标题、原名或资料 ID，避免路径穿越和名称冲突。常见文档/图片后缀保留并归一化；`.command`、`.html` 等未在白名单中的原名不变成导出文件的后缀。原件字节保持不变。包仍包含私人知识，未加密；客户端明确提示该包不能用于恢复。

## 一致性与兼容

证据定位以对应版本元数据中的原始 `extracted_text` 为基准；Markdown 增加标题和缩进，定位数值不能直接用作 Markdown 文件偏移。

后端复用停服锁、SQLite Backup API、数据库校验和凭证清理基础工具，仅在临时快照筛选原件记录，不修改原数据库或原件。复制所选原件期间持有排他锁，后续渲染基于独立快照。先校验 ZIP 文件集合、类型、大小及摘要，再用独占硬链接发布。

当前限制为展开文件合计 8 GiB、清单 4 MiB、归档最多 50,000 项；不代表已完成该规模性能验收。暂存 SQLite 及渲染副本会额外占用磁盘空间；输出限额不是峰值内存或临时空间承诺。

新增 CLI `local_backup.py --action readable`，沿用显式绝对 `--package`、`--data-dir`、`--cache-dir`、`--log-dir` 和单 JSON 返回。原 `export`、`verify`、`restore` 契约不变；恢复校验拒绝可读格式。无数据库迁移，无新依赖，也未改动真实用户的活动库指针。
