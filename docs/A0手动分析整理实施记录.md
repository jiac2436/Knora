# A0 首批：DeepSeek 手动分析与整理

日期：2026-10-02。范围：单资料手动分析与整理开发闭环；尚未通过真实模型质量验收，也不是付费服务上线。

## 计划调整

按用户确认，优先次序改为手动分析整理 → 多资料分析/带出处问答 → 真实 Agent 读取。S0 已实现的变更日志和固定提交保留，后续同步、账户及会员工作暂缓。定时云端分析仍依赖已同步的云端版本，手动分析通过本地冻结快照调用网关，不依赖完整云端库。

## 实现

- Mac 设置 AI 网关地址和访问凭据；访问凭据存钥匙串并按知识库隔离，供应商密钥只配置于网关服务器。客户端包内不启动或包含 DeepSeek 密钥配置。
- 阅读器手动分析当前资料或生成整理建议。请求包含正文证据、个人上下文及现有分类/项目候选；最大 80 条证据、48000 字符，截取会明确提示，不宣称全文分析。
- 本地任务冻结正文版本与上下文；Worker 先持久化 running，再单次请求网关。任务固定请求 ID，重复创建同一请求返回原任务，改变意图使用同 ID 返回冲突。
- 网关使用 DeepSeek 兼容接口及 JSON mode；模型名称显式配置。返回摘要、洞察、证据引用、已有分类/项目建议、提醒和用量。结构、引用及候选 ID 均校验，但引用存在不能证明结论正确。
- 分析结果保存到本地，后续正文/上下文变更动态标记过期。用户确认后才应用分类及项目关联，不重写原文；重复应用不会覆盖用户后续编辑。删除资料不展示结果，永久清理一并清除任务及产物；晚到响应不能重新发布已删除资料。
- 超时、连接中断及 Worker 中断保留未知结果，不自动再次调用模型。用户重新分析可能产生额外供应商费用。

## 持久化与兼容

Schema 从 v2 升至 v3，新增 `ai_jobs` 和 `ai_artifacts`。受控升级前备份；旧 v1/v2 备份按对应触发器版本验证并升级，未知/被修改触发器拒绝。新库及恢复库仍使用正式本地身份。

AI 产物是知识数据，纳入本地变更日志、源资料的固定提交快照、完整恢复包与可读导出。任务是设备运行状态，不进入恢复包；恢复不会自动再次消费模型。恢复包不包含网关地址或钥匙串凭据，恢复库需要重新配置网关。可读导出的分析记录按生成时版本保留，明确可能过期。

固定提交新增 `ai_artifacts` 字段；远端同步尚未上线，后续接收端须冻结并验证该新增字段。没有把任务状态或供应商密钥纳入同步。旧客户端不支持 schema v3，须使用支持 v3 的版本打开新库/新备份。
