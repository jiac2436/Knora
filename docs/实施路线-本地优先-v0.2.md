# 实施路线：本地优先 v0.2

日期：2026-09-30。状态：已纳入架构复核修订，阶段契约与验收细节继续按门槛冻结，以下新增阶段尚未实现。本文是当前工作安排和进度的唯一入口；旧计划与验收记录仅保留历史依据。依据[架构决策](./架构决策-本地优先与云端增值服务.md)和[实施设计](./实施设计-本地服务同步与AI-v0.2.md)。本文按现有工程安排增量交付，不预设云资源、支付渠道、模型账号或发行证书已具备。

## 1. 统筹原则

2026-10-03 功能细化：A0 按“标签基础 → AI 文档总结与系统打标 → 检索整合 → 真实 Agent / 问答”推进。新标签来源区分 AI 大模型与人工，标签与总结为 Skill/RAG 的共同数据基础；具体交付、兼容及验收见 [标签总结与知识检索计划](./A0标签总结与知识检索实施计划.md)。本条细化替代上一轮 A0 直接进入多资料问答的安排，原有发布门槛保留。

- 独立本地客户端和免费数据控制之后，优先跑通手动 AI 分析整理、用户确认应用和真实 Agent 读取，再继续多端同步与会员服务。AI 额度按独立依赖推进。
- 在本地数据改造阶段预留稳定库、设备、版本身份及变更记录；不提前实现全部云端模块。
- 每个阶段以可重复的业务场景验收，不以接口存在、模拟支付或单机协议测试代表产品完成。
- 工程设计中的拟新增契约可细化；已确认的手动同步、数据保留和本地基础能力边界按架构决策执行。

## 2. 当前工程基线

| 区域 | 当前实现与需要处理的差距 |
| --- | --- |
| Mac 构建 | `apps/macos/scripts/build.sh` 构建 Swift 并作本机临时签名；未封装后端运行环境及服务管理 |
| 数据路径 | `services/api/app/config.py` 默认使用源码目录内数据库、上传和模型目录；发行版须使用用户数据目录 |
| 本地身份 | `LocalDevSession.swift` 与 `Model.swift` 复用开发邮箱和 Token；须增加独立本地身份，与云端登录分离 |
| 迁移 | `database.py` 使用 `create_all` 和启动加列；须改为受控版本迁移，并迁入既有数据 |
| 资料与证据 | 已有 UUID、正文版本、证据、个人上下文、文件与图片对象；需增加库及同步版本身份，保留既有引用 |
| Worker | 已有文档、PDF、网页、向量和删除任务，按单 Worker 启动恢复；须管理进程生命周期和资源边界 |
| MCP | stdio 进程直接读取数据库并在启动初始化；须改为受控本地服务适配器，另建云端连接 |
| 同步和计费 | 尚无同步会话、变更游标、冲突记录、AI 任务、额度及支付账本 |
| 免费数据控制 | 尚无本次设计要求的完整导出、恢复与回收站产品链路 |
| 外部工具 | Crawl4AI 浏览器服务和飞书 CLI 有独立运行要求；逐项核对打包覆盖，不能宣称都已内置 |

以上为源代码梳理，不是本轮运行测试结果；原 M1 验收记录保留其当时范围。

## 4. 首轮具体工作

1. 固定构建输入及依赖清单，检查原生库、模型缓存和外部程序；在临时目录生成可搬迁运行环境验证报告，不改写用户资料。
2. 设计并实现用户目录解析、运行模式及一致性备份迁移入口。新本地模式使用正式本地身份，开发模式保持显式。
3. 引入本地库与设备元数据；为既有版本和证据建立兼容映射，不重新生成原证据 ID。在 L1 冻结整数编号兼容契约，实体同步版本和关联约束的数据库改动在 S0 实施。
4. 实现 Mac 服务管理器、就绪检查与持久采集恢复，连接发现解决端口冲突；恢复操作仅处理自己启动的进程。
5. 完成本地业务回归与无开发环境安装验收，再推进导出恢复和本地 MCP。

拟主要改动位置：`apps/macos/scripts/build.sh`、新增运行包构建与验证脚本、Mac 服务管理及本地身份文件、`config.py`、`database.py` 与迁移目录、`models.py`、`main.py`、`mcp_server.py`、`services/worker/main.py`。共享逻辑沿用现有服务层，新增模块按职责建立。
