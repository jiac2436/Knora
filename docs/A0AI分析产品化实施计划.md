# A0：AI 分析产品化实施计划

日期：2026-10-04。状态：P0～P4 工程实现及合成闭环验收已完成；2026-10-05 完成 P5 固定合成样本的真实 DeepSeek 分批复验与 RAG 问答核对，质量边界见验收记录。实施与兼容细节见《A0AI分析产品化实施记录》。

2026-10-09后续方向：[A1知识库视野与分层检索实施计划](./A1知识库视野与分层检索实施计划.md) 增加知识域级组织层。本计划继续约束单篇分析；新增库级加工、增量维护和规模评测属于A1，尚未实现，不能以A0验收代替。

## 1. 目标与决策优先级

用户目标：帮助用户更高效管理知识；一次主动分析自动完成简短总结、AI 打标和本地检索更新。标签服务于知识库检索，总结与原文检索数据服务于 RAG 和 MCP。

本计划取代《A0标签总结与知识检索实施计划》中“新 AI 标签必须逐项确认”“两个分析入口”“分析中提供归类应用”的相关产品决策。旧计划保留为历史，不视为当前新功能契约。原文证据、权限、本地存储、来源区分及未知付费请求不自动重发的要求继续有效。

首轮范围：单资料手动分析、自动打标、紧凑阅读结果、索引自动更新、失败恢复及真实检索评测。不开展全库自动分析、批量、会员计费、云同步、自动领域/项目调整、跨资料研究或标签语义自动合并。

## 2. 现有代码与复用边界

| 部分 | 当前实现 | 本轮调整 |
| --- | --- | --- |
| 客户端 | LocalAI.swift：设置、计划预览、任务、长篇结果、标签候选确认和归类应用 | 单入口、简短结果、统一进度、普通标签编辑、详情折叠 |
| API | ai.py：快照、版本、任务和历史产物 | 新任务契约、综合业务状态、重复请求控制 |
| 网关 | ai_contract.py、services/ai_gateway/main.py | 简短阅读输出、标签约束、新旧契约兼容 |
| 发布 | services/worker/ai_analysis.py、ai_long_analysis.py | 短文/长文最终产物统一自动发布标签，保留长文检查点 |
| 标签 | knowledge_tags.py、ai_tag_suggestions.py | 抽取可复用的事务逻辑，保留旧候选操作；新任务无需逐项确认 |
| 检索 | summary_index.py、summary_retrieval.py、现有原文窗口及本地向量 | 按分析版本自动更新，索引失败独立恢复，原文定位不变 |
| 持久化 | SQLite、变更记录、备份与恢复、可读导出 | 覆盖新契约/发布状态，旧产物可读，不恢复付费任务执行 |

复用现有 Python API、Worker、SQLite、Swift 客户端、DeepSeek 网关和本地向量模型。不引入第二套原文索引、额外 Agent 框架或新向量数据库。

## 3. 需在编码前冻结的契约

### 3.1 用户交互

- 阅读器只有一个“AI 分析”主要操作；已有有效结果时显示状态，重新分析放在次要操作中。
- 点击正在进行的分析只查看状态，不创建重复任务；并发创建由后端按资料及输入快照约束，客户端禁用不能代替幂等。
- 每个知识库首次说明模型发送范围并取得确认；已有授权下的普通单次分析直接执行。长文多次调用保留范围与次数确认。暂无真实余额与金额预估，不显示虚构费用。
- 后台仍先生成冻结计划并验证 plan_hash；减少弹窗不等于移除快照、范围及授权检查。用户取消预览不调用模型。
- 原文、资料所属领域和项目不被自动修改；新分析不产生可应用的领域/项目建议。
- 新分析自动保存有效 AI 标签；手动标签和人工编辑入口继续可用。

### 3.2 内容与显示

- 用户结果：简短概述、最多三条不重复要点、标签、业务状态。
- 普通中文文章默认阅读内容目标为 150～250 字符；短笔记更短，允许零要点；英文单独定义长度预算。首批以样本校准长度与信息保留，不统一用中文字符预算约束所有语言。
- 服务端约束字段长度和条目数；超预算结果不能作为合格简短输出发布，不静默截断结论或证据。网关使用对应输出预算；校验失败给出可理解状态，不自动额外调用模型修复。
- 概述与要点避免重复，不默认复述全部数值、案例、优惠和页面导航；重要限制可显示一条提示，其余在详情中。
- 长文默认仍显示紧凑概览；分段摘要、依据、模型/用量、历史与诊断信息折叠，历史不混入当前结果。
- 每条事实仍保留引用。缺乏支持的事实不能因为短文本目标而放宽校验。

### 3.3 自动标签

- 推荐 3～5 个有区分度标签，服务端设置最大 5 个有效 AI 标签，不为凑数打标；主题、内容类型、涉及对象不强制填满。
- 优先复用规范名与别名；只有主题和涉及对象允许创建新词，内容类型复用已有目录。
- 新词使用规范化精确去重；不在首轮实施语义自动合并。
- 校验候选 ID、所属用户、维度、证据、拒绝记录与并发目录变更。模型自报置信度不作为自动生效依据。
- 同一资料同一标签的 manual/ai 来源保留，界面去重展示。重新分析只替换该流程维护的 AI 关联，保留 manual 关联。
- 有效分析允许不打标签；省略无依据标签，不强制用户审批。
- 删除 AI 标签沿用当前正文版本抑制记录；相同正文重分析不得恢复它，正文更新后可重新评估。跨正文版本持续排除属于后续明确产品决策。
- 历史人工确认的 AI 关联保留记录；新分析生效时仅处理本资料当前 AI 关联，不删除其他资料标签词条和历史产物。

### 3.4 总结、标签、索引的一致性

- 校验成功后，在同一个本地事务保存新产物、更新 AI 标签关联、登记该版本待建索引状态。
- 向量/关键词索引在事务外构建；不能为等待计算持有 SQLite 写锁。
- 查询只使用与当前正文及分析版本匹配的有效数据；构建中不可拼接新旧索引。具体版本字段和切换方式先审计现有表后确定，采用最少必要的持久化调整。
- “完成”必须同时满足结果发布与必要索引就绪；模型请求成功不是完整业务完成。
- 索引失败时显示“分析已保存，检索更新失败”，只重试本地索引，不重新发送付费请求。
- 重新分析失败时，不删除仍有效的旧结果；正文已改变的旧数据不能继续作为当前知识。原文检索保持可用。
- 手动打标也更新相应检索元数据，不需要购买或调用 AI。

## 4. 实施批次及依赖

### P0：冻结共享契约与回归基线

交付：新分析契约、DTO、任务/发布/索引状态、旧数据处理矩阵、紧凑结果示意及测试样本规范。

工作：审计现有标签关联、AI 任务、索引及备份表；明确新增字段与是否迁移；记录现有原文/MCP 召回基线；确认首次授权与长文确认行为。新旧契约分别处理，不直接改旧结果含义。

验收：API、Worker、网关、Swift 的字段、版本、状态和错误行为一致；迁移清单和文件归属确定。P0 完成后才能并行修改消费者。

### P1：精简生成输出并兼容旧产物

交付：新契约输出简短总结、最多三要点和最多五标签，无归类应用建议；短文及长文最终汇总统一处理。

工作：更新提示和结构约束、网关路由与结果校验，保留原文引用；长文分段仍作为内部检查点，最终显示不逐段铺开。

验收：短笔记不膨胀，普通文章不逐句复述，长文最终概览保持简短；旧产物和旧任务按旧契约读取，不伪造新字段；不自动追加付费修复调用。

### P2：自动打标与本地发布闭环

交付：新分析无需确认即可生效标签；重分析替换 AI 关联；人工标签和用户纠正受到保护。

工作：抽取现有接受候选的事务规则，统一短文及长文最终发布；校验版本及目录变更；处理并发删除、同标签双来源和拒绝记录；记录当前结果及索引更新需求。

验收：一次分析自动出现正式 AI 标签；同名/别名不重复创建；不改原文、人工标签和领域/项目；过期或取消任务的晚到结果不能覆盖当前状态。

依赖：P1 契约固定；P2 与 P3 需要共同维护发布/索引接口。

### P3：索引状态与恢复

交付：结果发布后自动进入检索，明确“分析中／更新知识检索／完成／部分失败”；只重试失败的本地索引。

工作：复用现有索引调度和重建流程，绑定产物版本；修复任务状态与综合业务状态脱节；确保原文、摘要、正式标签按权限与版本召回。此批不新增所有片段的额外大模型调用。

验收：完成后客户端与 MCP 能检索到当前资料；索引故障恢复不增加模型请求；构建中、过期、删除、撤权数据不作为当前有效增强结果；手动标签流程同样生效。

### P4：阅读器产品化

交付：一个按钮、紧凑结果卡片、自动标签展示、统一进度与可理解错误、折叠历史与证据。

工作：修改 LocalAI.swift 及阅读器入口；移除新流程中的整理建议、候选审批和拒绝记录清除按钮；使用现有标签编辑入口；首次发送说明与长文确认；切库/切资料/重连时保持响应代次校验。

验收：普通流程一次主动操作后即可完成，无额外应用按钮；结果状态与后台一致；窄窗口和长标签不溢出，短资料不展示长报告；可编辑 AI/人工标签、查看证据、停止长文及打开历史。

依赖：P0 固定后可先开发静态视图和 DTO，动态闭环等待 P2/P3；单独交付新界面不算功能完成。

### P5：兼容、完整交付及真实质量验收

交付：新版随包客户端、迁移与备份说明、回归记录、样本质量及 RAG/MCP 对照结果。

工作：迁移前备份，覆盖变更记录/可读导出/恢复/永久删除；恢复不重放 AIJob；检查真实网关与客户端兼容。若新契约需网关升级，说明先升级网关再使用新任务，不将旧网关拒绝解释为资料失败。

冻结约 20 份自有、合成或可合法使用的资料，覆盖短笔记、中英文文章、PDF、长文、噪声、部分采集和无充分依据；每份 2～3 个问题，包含摘要中未出现而原文有答案的细节。记录当前基线与新版本对照，人工审查事实/引用/标签/检索。真实模型请求使用已配置的测试网关，不从聊天获取密钥；记录范围、调用数及用量。

验收：工程门槛全部通过；真实质量结果不由模拟测试替代。总体召回/引用质量不能因缩短显示而回退；发现退化时修复具体原因。准确率百分比在固定样本基线后确定，不提前编造目标或达成结论。

### 后续 P6：有证据再增强检索

如细节召回、指代或章节边界评测确有缺口，再加入选择性片段上下文，并与原文基线对照成本/延迟/召回。首次产品化可利用现有原文窗口、摘要与标签检索完成，不将额外片段生成作为所有资料的强制步骤。

批量、后台自动分析和会员预算管理在上述闭环验收后另行规划。

## 5. 核心验收清单

1. 普通资料一次点击分析，自动保存总结、打标并更新索引；无第二个付费操作或应用步骤。
2. 默认展示只有概述、至多三要点、标签及状态；短文可只概述；依据和历史按需展开。
3. AI 与人工来源保持准确；AI 标签不清除人工关联；用户当前版本排除不会被同正文重分析恢复。
4. 同资料并发点击、重连和重复请求不重复创建模型调用；允许明确的手动重分析。
5. 正文或上下文变更、删除、撤权、取消及晚到结果均遵守快照和权限规则。
6. 模型成功但索引失败可单独恢复；网络结果未知不自动重发；长文已完成段不重发。
7. 不改变资料领域/项目，不将摘要或标签当作原文证据；没有答案时不猜测。
8. 通过标签、摘要找资料，也能通过原文找到摘要未覆盖的细节；事实引用落在当前原文。
9. 旧资料/标签/AI 产物可读，旧 pending 候选不被静默自动接受；新分析才使用自动打标。
10. 新增业务数据进入备份、导出及删除流程；恢复不自动执行付费任务。

## 6. 协作与交付方式

P0 由统筹者负责共享 schema、契约、迁移、备份兼容与 API/Swift DTO。冻结后如用户授权并行，可划分：生成与发布后端、客户端视图、独立检索与评测。共享文件由单一负责人修改，不让多个代理同时编辑 models.py、ai_contract.py、main.py、Model.swift 等。

每批记录已实现与未验证部分；P1～P4 合并验收后再交付可使用的产品闭环。优先推进 P0 → P1/P2 → P3/P4 → P5，不用界面修改代替业务闭环。计划不承诺精确工期或进度百分比。
