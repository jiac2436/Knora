# 开发与验证

桌面 App 自带本地服务。以下命令用于修改源码和运行测试，普通使用者不需要执行。

## 准备开发依赖

请在 macOS 上使用独立的源码副本进行完整 API 回归，其中包括 macOS 进程与文件能力测试。使用 Python 3.12；生产运行包固定为 3.12.16。不要复用旧 Python 3.10 虚拟环境或用户的扩展安装目录。

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r services/api/requirements.txt \
  -c apps/macos/runtime/constraints-tested.txt
.venv/bin/python -m pip check
```

基本 API、Worker 和云端 AI 的开发依赖在 `services/api/requirements.txt`。需要开发 OCR、Office 或复杂 PDF 解析时，再安装 `services/api/requirements-ocr.txt`，同时使用上述约束文件。这些开发依赖不直接复制进发行 App。

## 免费回归

```bash
.venv/bin/python -B scripts/test_api.py
cd apps/extension
npm test
npm run check
```

API 测试脚本按 Git 忽略规则导出源码到临时目录，使用临时 HOME、内存数据库和合成资料；完成后清除临时源码及测试资料。部分测试需要监听本机回环端口，受限沙箱应允许这些本机连接。不要把端口权限失败当作业务断言失败。

运行特定测试可向脚本传入相对路径。例如：

```bash
.venv/bin/python -B scripts/test_api.py services/api/tests/test_runtime_extensions.py
```

不使用真实模型 API Key。共享内核测试使用模拟模型传输，验证确认、任务、持久化与失败处理；不能据此声称真实模型回答质量已经验收。

根目录 `make test` 还包含移动端类型检查与 Docker Compose 配置检查，需另装对应开发工具；macOS 产品贡献通常从上面的 API 与浏览器插件检查开始。GitHub Actions 在 macOS 上运行 API 回归，在 Linux 上运行浏览器插件检查；原生界面、WKWebView、PDFKit 和独立运行包仍须另行验收。

## 安全与构建输入

```bash
.venv/bin/python -B apps/macos/scripts/runtime/audit_dependencies.py \
  --lock apps/macos/runtime/requirements-macos-arm64.lock \
  --output /tmp/knora-osv-result.json
```

该命令只向 OSV 提交公开包名和版本。匹配结果需要人工核对；没有匹配结果也不等于不存在未知漏洞。

构建输入和发行步骤见 [macOS BUILD](../apps/macos/BUILD.md)。数据库、上传资料、模型、个人配置、签名材料、构建缓存和生成的 App/DMG 不应提交 Git。
