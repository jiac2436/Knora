# L2 采集队列持久化记录

日期：2026-10-01。状态：本地随包客户端队列持久化及重启幂等恢复已实现；完整 L2 可靠性验收尚未结束。

## 实现

- 新增 `CaptureQueueStore`，在正式数据目录的 `capture-queue/queue.json` 保存版本化队列，在 `capture-queue/files` 保存私有原件。目录权限 0700、文件权限 0600；JSON 使用原子替换，最多 32 MiB。
- 本地随包模式自动恢复未加入列表的草稿、采集条目及文件、已发送状态、选定知识域/项目、固定目标、资料 ID 和幂等键。开发/远端模式继续使用原有本次运行列表。
- 草稿变化即保存；发送前先保存固定的条目 ID、知识域、项目和目标，保存失败则停止请求并显示原因。原件复制到持久暂存目录，退出只清理阅读缓存和临时工作目录，不清除队列原件。
- 本地目标采用绑定用户的稳定身份，不采用动态服务端口。重启分配新端口后仍可向同一知识库重试。
- 已返回的资料 ID 立即记录；后续恢复通过该 ID 获取资料并继续图片上传或项目关联。若后台已提交而响应未保存，则继续使用原条目 ID 作为幂等键发送相同请求。
- 普通文件保存 SHA-256；发送前检测暂存文件变更，拒绝改变同一幂等请求的原件。文件删除操作先提交队列变更，再清理该条目拥有的原件。已发送条目的暂存原件保留至用户移除条目。
- 飞书正文、版本元数据、图片 ID、OCR/下载状态及已上传图片 ID 保存在队列；图片复制到持久暂存目录。重试复用冻结的缓存正文，不重新生成图片 ID。复制及队列保存成功后清理本次获取的临时图片目录。
- 拒绝队列中的外部文件路径、符号链接原件目录、链接队列文件、重复或无效条目 ID。缺失普通文件保留记录并提示重新添加；损坏或未知版本的队列保留原文件，阻止模型用空队列覆盖。
- 新增可注入的队列、运行环境和本地服务实例，测试使用临时目录及独立 Keychain 命名空间；正式客户端继续使用默认用户目录和共享服务实例。

## 兼容及恢复边界

1. 队列格式版本为 1。原来的内存队列没有历史文件可迁移，本轮不导入旧数据。数据库版本及业务 API 契约没有改变。
2. 不保存本地服务凭证或账号凭证；飞书资源标识是采集元数据，登录凭证仍由 CLI/Keychain 管理。
3. 恢复队列不自动发送；用户打开采集页，确认内容后点击保存/重试。本地请求不触发云端同步。
4. 队列内部包含当前设备的绝对暂存路径；数据目录搬迁、导出和跨设备恢复时需由 L3 转换并校验，不能直接把原 JSON 当作跨端导出包。
5. 已发送列表及其暂存原件当前由用户手动移除，不设自动保留天数。写入失败后，本次新增内容可能只在内存中，界面明确提示尚未安全保存；应修复错误后重试保存再退出。
6. 损坏或不支持的队列保留在原路径，暂无修复/隔离的图形入口；诊断与恢复入口仍需补齐。不承诺原子替换足以应对所有磁盘损坏或突然断电。
