## 1. 目标和范围

用户确认两个目标：根据内容生成系统化标签及文档总结；为知识库 Skill 和 RAG 提供可检索、可引用的数据。新标签的标注来源仅有 `ai`（大模型）和 `manual`（用户人工添加），记录在文档与标签的关联上，不记录在标签词条上。用户确认 AI 标签不改变来源。

继续使用现有 Mac、Python API、Worker、SQLite、本地向量模型及 DeepSeek 网关。知识和生成结果本地保存；模型输入经过明确手动操作发送到网关。首轮不自动消费额度、不实施定时云端分析或充值会员功能。用户已经反馈首个真实调用可用，系统性质量评测仍需补齐。

## 2. 当前代码基线

- `tags.py` 根据固定关键词规则生成最多四个标签；`SourceTag` 只有资料 ID 和名称。更新正文会删除并重建这些标签，所以人工/AI 标签不能直接复用这个重建逻辑。
- AI 已有单资料任务、版本及上下文快照、摘要/洞察、分类项目建议、产物本地保存和用户确认应用；新版本可扩展契约，但旧 AI 产物须继续可读。
- 原文已有关键词检索、证据切块后的本地向量窗口及混合排序，不新建另一套原文向量系统。现有窗口与原证据 ID/偏移的映射继续保留。
- 已有 MCP 检索/取证据原型，但还需受控服务适配与至少一个真实 Agent 验收，不能当作目标客户端已接入。

## 3. 功能契约

### 3.1 标准标签

新增本地标准标签目录：稳定 ID、维度、标准名称、规范化名称、可选主题父级、别名。初期使用主题、内容类型、涉及对象三个维度。内容类型从小型固定集合选择；主题首轮仅允许一层父子关系，并检查环路。领域和项目继续作为独立归属。

AI 优先返回已有标签 ID；新词返回候选名称/维度/依据，用户接受时才创建标准词条。同名与别名精确规范化命中自动复用已有 ID；语义上相近的词仅提示合并，不自动把整个标签目录交给模型改写。初期每篇推荐 3～8 个标签是提示与质量目标，证据不足允许少于三项，不为凑数编造标签。

### 3.2 来源、确认与人工优先

正式标签关联保存：source_id、tag_id、origin、原文版本、生成产物 ID（AI 时）、引用依据、创建及确认时间。AI 候选状态与正式关联分开，状态为 pending/accepted/rejected。

规则：

1. 人工添加立即生效；AI 标签需要用户确认后生效，首轮不启用自动接受。
2. 确认 AI 标签后 origin 仍为 ai；人工修改则形成明确的人工关联，不覆盖原 AI 来源历史。
3. 同一资料/标签允许 AI 和人工两种关联，界面按标签 ID 去重；人工优先展示，详情可查看两种来源。
4. 移除 AI 关联不影响同标签的人工关联；移除人工关联时，如果 AI 关联仍有效，界面明确展示保留情况，不暗中删除另一来源。
5. AI 重分析只创建新候选，不删除人工标签或用户已确认的关联。
6. 用户拒绝/移除 AI 标签，在同一正文版本的再次分析中抑制重复建议；原文改变后允许重新评估。提供撤销拒绝入口。
7. 原文改变后，AI 关联依据标记为旧版本；人工关联保留。默认检索不使用过期 AI 标签，但用户可以重新确认保留。单纯更改个人上下文会使相关分析建议过期，须核验其快照后再接受。
8. 标签合并由用户触发，关联和别名在一个事务中更新、去重，保留来源与拒绝历史。

### 3.3 文档总结

新总结契约：一句话概述、文档摘要、关键要点及各自的原文证据引用、可选适用条件/限制。正文事实和个人补充分开：文档总结以原文为依据，个人上下文可以影响标签/归类建议，但不能伪装成原文结论。

产物记录 source/revision、覆盖范围、分析/提示版本、模型、用量及生成时间。首轮手动按钮一次调用同时生成总结和标签候选；总结校验后本地保存，标签仍需确认。已有分类项目建议继续保持独立确认，不与确认标签捆绑。

长文档按现有证据/章节切分做局部归纳，再合成全文总结；每个合成要点必须能回溯到原始证据。每个子调用有固定请求 ID，完成后持久保存检查点；未知调用禁止自动重发，取消后保留已完成部分并明确费用。调用前展示本次范围与预计调用次数，不把费用估计当作账户额度保证。无法覆盖全文时标记 partial 并展示覆盖/缺失范围，不能静默把截取分析称作全文总结。

首次只提供手动分析与手动重分析。原文更新后标记旧总结并提示重新生成，保留历史；不自动发起付费请求。

### 3.4 检索数据与行为

复用原文向量窗口，增加当前有效总结的关键词/向量索引和标准标签过滤；别名解析到稳定标签 ID。检索结果记录命中的是原文、总结还是标签。

流程：领域/项目/标签和权限过滤 → 原文及总结混合召回 → 文档排序 → 展开原文证据。标签只是筛选与召回线索；总结只辅助找到文档，最终回答的事实引用必须落到原文证据。

人工标签及已确认、未过期 AI 标签进入默认检索；候选/拒绝/过期标签不参与。新原文尚未重新总结时，原文检索照常工作，过期总结不参与默认召回。索引状态区分正文索引和总结索引，失败允许本地重建，不触发模型调用。

Agent 的所有读取路径，包括总结、标签列表与统计，必须复用授权领域、app_only、删除、撤销及版本过滤，不能在召回后才过滤。

### 3.5 客户端与 Agent

Mac：标签来源标识、人工增删、AI 候选接受/拒绝、标签维度浏览/筛选、标准词条和别名管理、总结主视图、历史/过期/覆盖提示、引用展开、索引状态。

MCP：扩展 search_knowledge 的标签过滤和命中类型；增加受权限控制的总结/标签读取；复用 get_evidence。Agent 通过本地服务访问，不暴露数据库凭据。

Skill：说明检索时机、筛选方式、总结与原文证据的区别、引用格式和证据不足处理。先选至少一个真实目标 Agent 验证搜索→总结→证据→回答闭环，再增加其他客户端配置模板。客户端 RAG 问答复用同一检索路径，不另建重复知识库。

## 4. 数据、API 与兼容

拟新增对象：tags、tag_aliases、tag_assignments、tag_suggestions（含拒绝记录）；文档总结沿用 AIArtifact 的版本化结果并增加明确的产物类型/契约版本。总结索引增加独立任务/记录，复用当前向量模型与融合排序。

标签词条按 owner、维度、规范名称约束唯一；别名歧义显式拒绝或要求选择。标签目录和文档关联成为业务知识，进入变更日志/固定提交及备份/可读导出；重建任务和派生索引不是知识，恢复后可本地重建，绝不重放付费分析。

旧 SourceTag 是规则标签，不能回填成 AI 大模型来源，也不能冒充人工来源。旧表保留兼容读取、明确标为历史规则标签；新标签独立存储。新正式标签不经过 replace_auto_tags 的删除重建。旧 AI 结果保留原契约读取，不能通过补默认值假装已生成新总结或标签。

保留旧 tags 名称数组接口兼容，新增 tag_details、summary 字段及标签管理 API。名称数组只作展示兼容，正式筛选/关联使用 ID。API 沿用 owner 及资料权限校验，批量确认/合并事务化，使用快照版本和幂等请求键。

实施时递增本地 schema，升级前备份，按版本验证触发器，保持 v1～v3 恢复包可恢复；不覆盖用户现有知识。旧客户端不能打开新 schema 库。具体 migration 编号、表定义及 API DTO 在第一批编码前冻结，并与 Worker/Swift 共同验收。

## 5. 交付顺序

| 批次 | 具体交付 | 验收门槛 |
| --- | --- | --- |
| 1：标签基础 | 标准词条、维度、别名/简单层级、来源关联；人工标注/管理；历史规则兼容；备份/删除/迁移 | 重解析不删人工标签；同一标签两来源不重复展示；别名/层级/合并无冲突；恢复与 owner 隔离 |
| 2：AI 总结与打标 | 新契约、现有词优先/新词候选、引用；接受/拒绝与抑制；旧版保护；短文闭环后补长文归纳和检查点 | 一次手动任务产出总结和候选；确认前不生效；拒绝后不反复出现；旧版禁止确认；真实短/长文样本审查 |
| 3：检索整合 | 总结索引、标签过滤/别名解析、原文/总结混合检索、命中来源、索引重建；Mac 总结/筛选界面 | 标签/总结找文档，原文支撑引用；过期/删资料不召回；不跑 AI 也能查原文；检索对照评测 |
| 4：Agent 和问答 | 本地服务 MCP 适配、总结/标签读取、Skill、真实 Agent 引用；客户端 RAG 问答 | 至少一个真实 Agent 完整闭环；逐入口权限/撤销/删除验收；无答案不编造出处 |

并行方式：根代理负责 schema、日志、备份与共享 DTO；后端代理负责标签/AI 业务及任务；客户端代理负责展示与交互；独立测试代理负责样本和回归。先冻结共享契约，再划定文件归属，避免同时编辑 models/services/Model 等共享文件。检索代理只能在标签和总结契约固定后接入。

## 6. 评测与交付要求

冻结首轮约 20 篇有许可使用的测试资料，覆盖中文/英文、同义名称、混合主题、短笔记、长文、PDF/网页、无充分证据和正文变更。真实调用前展示资料范围与次数，使用测试数据并记录模型/提示版本/用量，不把模拟测试当作质量验收。

评测标签重复/别名归一、人工标签保留、总结事实与引用支持、长文覆盖、检索命中和权限边界。先人工逐条审查并建立基线，再冻结数值门槛，不凭空宣称准确率。工程测试覆盖事务、幂等、接受/拒绝与编辑竞争、删除晚到、索引失败、备份恢复和客户端代次。

每批交付完整回归、随包客户端及实际功能记录。主流程首先交付批次 1 和短文批次 2，然后补长文与检索；不提前承诺完整 RAG、真实 Agent 或生产额度已完成。
