# L3 客户端恢复与库切换实施记录

日期：2026-10-01。承接用户“继续推进”，本轮补齐备份恢复入口、独立恢复库的活动指针及队列切换。前一轮核心见 [备份与隔离恢复记录](./L3本地备份与隔离恢复实施记录.md)。

## 用户流程

设置“备份与恢复”提供“从备份恢复…”：选择本地备份后确认，暂停当前所属服务，恢复至全新的管理目录，使用新凭证试启动 API/Worker，成功后保存活动库指针并打开恢复库。原数据库、原件和采集队列均保留，不合并、不覆盖原库。原库无法启动时，可从故障页面进入恢复设置。

恢复库不会携带原库未入库草稿和待发送条目。模型在切换时绑定目标库自己的队列，清空阅读、PDF、证据和资料缓存，避免两个库状态串用。若当前队列可读但尚未安全保存，拒绝切换；坏队列保留原文件，不强制覆盖它。

成功后可在**本次会话**点击“回到恢复前知识库”，返回原库并读取它原有草稿、待发送原件及资料。退出重启后会打开已保存的活动库；恢复前库的返回按钮目前不跨会话保留。原库仍在原目录；多库管理及跨会话切换列表不在本轮范围。

恢复包校验、候选启动或指针写入失败时，尝试重新打开已捕获的原库。若激活后连接失败，尝试回退指针与队列；回退设置或原库本身不可用时明确显示失败，不声称已完全恢复可用。已经成功展开但未激活的候选库保留，避免自动删除恢复出的知识；后续需管理未激活库和对应凭证。

## 配置与兼容性

无数据库结构迁移，默认库目录及既有 Keychain 名称保持兼容。新增客户端持久化格式：

| 内容 | 位置或规则 |
| --- | --- |
| 默认数据 | `~/Library/Application Support/local.pka.knowledge-inbox` |
| 恢复库 | `~/Library/Application Support/local.pka.knowledge-inbox-libraries/<UUID>` |
| 活动指针 | `~/Library/Application Support/local.pka.knowledge-inbox-state/active-library.json` |
| 指针格式 | `{"version":1,"id":null}` 为默认库；恢复库 id 为 UUID |
| 恢复库缓存/日志 | 相应 `Caches` / `Logs` 下的 `local.pka.knowledge-inbox-libraries/<UUID>` |
| 恢复库凭证 | 原 Keychain 服务名加 `.library.<UUID>`，不写入指针或参数 |

指针仅存 ID，路径在客户端推导；拒绝未知版本、非法 ID/字段、符号链接及缺失数据库，不因坏指针静默创建空库。写入使用私有临时文件、`fsync` 与原子 rename；失败前旧文件保留。新库目录由后端恢复工具独占发布，原库从未被替换。

回到默认库同样通过指针表示，不搬动数据。降级到不识别该指针的旧客户端会仍打开默认库，因此使用恢复库后不建议降级；需保留最新客户端和备份。本轮未迁移用户真实数据或修改真实活动指针。

## 取消与进程边界

模型派发启动、停服、恢复和失败回退操作前捕获服务代次。`start` 在串行启动锁内核验代次，`cleanup` 仅转换匹配的代次，旧任务不能晚到启动服务或停止新一轮服务。恢复展开后再次核验代次，临时探测服务注册到所属服务，取消会停止它；探测启动也校验自己的代次。模型另有恢复代次保护活动指针发布，避免退出后的回调激活新库。

这修复了审查发现的具体竞态：单靠模型拒绝旧响应，无法阻止尚未执行的后台启动重新创建进程。定向测试覆盖旧 token 的启动、停止和恢复均拒绝、新 token 和活动指针不变；不把这些测试表述为物理断电或进程任意指令中断验收。
