# L2 后台存储故障验证记录

日期：2026-10-01。范围：采集 API 的数据库容量、原件写入和元数据提交失败路径。

## 测试方式

新增 `services/api/tests/test_storage_failures.py`，将测试夹具的合成账号、知识域和会话复制到临时 SQLite 文件，并仅为该测试覆盖数据库依赖与资产目录。测试结束后恢复依赖覆盖、关闭连接，后续测试不继承故障设置。

三项测试均在现有 API 实现上执行，没有修改生产 API、Worker、客户端、持久化格式或正式数据库，也没有迁移旧数据。

## 结果

| 场景 | 故障机制 | 验证结果 |
| --- | --- | --- |
| SQLite 容量耗尽 | 临时库设置 `max_page_count`，提交较大合成笔记，SQLite 实际返回 `database or disk is full` | HTTP 500；八类业务表计数保持，原笔记正文完整；解除容量限制后同一幂等键成功，重放返回原 ID，完整性 `ok` |
| 原件部分写入失败 | 仅对测试资产新建文件写入前三字节，随后注入 `OSError(ENOSPC)` | HTTP 500；新残片被清理、业务表不新增、原文件字节完整；解除故障后同一键成功，最终仅两个原件 |
| 元数据提交被拒绝 | 仅在临时库设置触发器，拒绝插入 `file_assets`，触发真实 SQLite 事务异常 | HTTP 500；已 flush 的新 Source 回滚，新资产被清理，原文件字节完整；移除触发器后同一键成功，重放不新增原件 |

八类计数覆盖：资料、版本、证据、个人上下文、幂等记录、文件元数据、文档解析任务及语义索引任务。此处“原件保留”仅指已有合成原件；本轮新建失败残片按现有逻辑清理。

首次单独运行三项通过。完整回归发现此前测试留下的 SQLite 空闲页也被复制，页数上限可能仍允许写入，故修正为先对**独立临时副本**执行 `VACUUM` 再限制页数。修正后完整后端及运行包工具回归 **117 项通过**，保留已有 Starlette/AnyIO 弃用提示 1 项；`git diff --check` 通过。

## 发现与待确认修复

数据回滚与原件保护在上述故障中通过，但空间不足仍返回通用 HTTP 500。Swift `API.call` 在没有结构化 `message` 时显示“后台请求失败，请检查连接与登录凭证”，无法告诉用户需要释放本机空间。

按用户提供的 AGENTS.md 第 17 条，已提出确认请求，尚未修改生产错误处理。建议只识别本地 API 的 SQLite 容量耗尽与 `ENOSPC`，返回结构化空间不足错误和可重试标记，显示释放空间后手动重试的提示；继续保留队列及原幂等键，不自动发送。其他数据库约束或未知异常不归类为空间不足。具体 HTTP 状态和错误码在获准实施时沿用现有 `ApiError` 契约确定。

## 验证边界

SQLite 页数上限真实触发数据库容量错误，原件 `ENOSPC` 为受控注入；均不代表把物理磁盘填满。没有验证 Worker 在满盘时写入解析/索引状态、操作系统配额、大文件复制中断或真实设备休眠。临时 API 测试不能替代完整客户端满盘验收；L2 未因本轮通过而标记全部完成。
