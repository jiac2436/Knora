## 1. 产品背景与核心判断

用户在工作和生活中持续遇到问题，也会在其他时间接触到有价值的方案、案例和经验。这些信息通常分散在文章、截图、文档、录音与个人笔记中，难以在真正需要时找回，更难被正在协助用户工作的 Agent 使用。

公开资料本身可以通过网络搜索获得。因此，本产品的价值必须建立在公开搜索难以提供的信息上：用户为什么收藏、与什么项目相关、适用于哪些约束、是否亲自验证，以及过去的决策和经验。

仅保存公开链接并自动摘要，不足以验证产品价值。首版应验证：加入个人上下文后，Agent 是否更容易找到适用资料、给出符合用户场景的建议，并减少重复解释。

## 2. 产品定位

### 2.1 一句话定位

帮助用户在手机和 PC 浏览器中随手保存资料和经验，沉淀个人上下文，并按需提供给工作与生活 Agent 的个人知识助手。

### 2.2 核心价值

1. **随手捕获**：通过移动端分享或 PC 浏览器插件收下资料，不强迫用户先分类。
2. **保留个人意义**：保存用户的收藏原因、关联项目、使用记录和验证结论。
3. **随任务调用**：用户或 Agent 根据当前问题检索资料与经验。
4. **有据可查**：重要结果可追溯到原文片段、图片、页码或音频时间位置。
5. **授权可控**：用户明确决定哪些知识可以被哪个 Agent 访问。

### 2.3 目标用户

首批验证用户为已经使用 Agent 的知识工作者，优先招募开发者、产品经理和设计师。生活场景保留为知识分区，不在首版同时建设多个行业专用流程。

共同特征：经常收藏资料；拥有持续推进的项目或问题；愿意补充少量个人备注；已有可使用工具调用的 Agent 客户端。

### 2.4 成功场景

用户白天遇到商品列表性能问题，晚上在手机看到一个相关案例，将链接或截图分享至 App，并可选补充“给商品管理页参考”。App 提取内容，关联该项目，注明这是一条尚未验证的外部案例。第二天，已接入知识工具的 Agent 在处理该问题时检索到案例及个人备注，核对适用条件后引用证据提出方案。用户实践后补充“已采用、具体效果及限制”，形成个人经验。

PC 场景同样是核心流程：用户工作时在浏览器中读到技术文档、案例或登录后可访问的文章，主动通过插件保存当前正文或选中片段，并补充项目备注。内容进入与手机端相同的知识库，供 App 与 Agent 后续检索。

这里的自动检索以 Agent 已配置工具和调用规则为前提。安装 Skill 或接入 MCP 不保证所有 Agent 都会自动调用，首版必须同时提供用户显式触发方式。

## 3. 首版目标、范围与非目标

### 3.1 首版目标

- 完成移动端分享、PC 浏览器剪藏两条采集路径到 Agent 检索的闭环，共享同一账户与知识库。
- 区分“外部资料”“用户判断”“AI 提炼”“已验证经验”。
- 在采集不完整时保留可用信息，并给出明确补充路径。
- 通过实际任务证明个人上下文相对于纯公开搜索的增量价值。

### 3.2 功能优先级

P0 为首版必须交付；P1 为主流程稳定后的增强；P2 为后续探索。

| 能力 | 优先级 | 首版边界 |
| --- | --- | --- |
| iOS / Android 系统分享 | P0 | 接收来源应用实际提供的文本、链接、图片和支持的文件 |
| 粘贴文字、链接与分享文案 | P0 | 从文案中提取链接，保留原始文案 |
| 图片、截图 OCR | P0 | 提取文字并保留原图；允许纠正识别文本 |
| PDF 导入 | P0 | 文本型与扫描型 PDF；保留页码，复杂版式标记局限 |
| 音频文件与录音 | P0 | 转写并保留时间位置；规格和额度经试验确定 |
| 普通公开网页解析 | P0 | 对验证通过的网站范围提供正文提取，不承诺任意网页全文 |
| 小红书、公众号、知乎链接 | P0 接收 / P1 专用解析 | 首版保证保存链接与备注；全文解析按逐站测试结果开放 |
| 个人备注、项目关联、验证记录 | P0 | 可选填写；区分用户确认与 AI 建议 |
| 知识卡、检索与带出处问答 | P0 | 围绕当前资料库，保留可追溯证据 |
| 只读 MCP 与配套 Skill | P0 | 至少在一个选定 Agent 客户端完成端到端验证 |
| 分知识域授权、撤销与删除 | P0 | 由服务端执行授权限制 |
| PC 浏览器插件 | P0 | 与移动端并列的核心入口；保存当前页面正文或选中片段、来源及个人备注 |
| Office 文件、本地视频 | P1 | 按格式逐步扩展；视频先明确音轨处理范围 |
| 网络音视频链接、关键帧理解 | P1 | 按平台与内容类型验证，不做全平台承诺 |
| Agent 建议回写经验 | P1 | 与只读权限分离，由用户确认后入库 |
| 自动同步平台收藏、复杂知识图谱 | P2 | 不作为首版成立的前提 |

### 3.3 首版非目标

- 承诺任意国内平台分享链接均可获取完整内容。
- 集中托管用户的第三方账号密码或登录 Cookie，或用共享平台账号承担批量获取。
- 建设完整阅读器、团队协作系统、公开内容社区或通用 Agent 执行平台。
- 自动把外部观点升级为用户认可或实践验证的结论。
- 对外部 Agent 的代码修改、发送消息等执行结果负责；本产品负责提供知识和证据。

## 4. 使用流程与信息结构

### 4.1 采集流程

1. 用户在来源应用分享内容，在本 App 粘贴、上传、录音，或在 PC 浏览器主动点击插件保存当前页面/选中片段。
2. App 或插件展示待保存内容，允许选填“为什么保存”、知识域和关联项目。
3. 内容先在当前设备可靠保存并显示状态，联网后上传；云端保存后在同一账户的收集箱中可见。
4. 处理成功后展示原始资料、提取内容与 AI 知识卡。
5. 处理不完整时保留已获得部分，说明缺失内容，提供补充文字、图片或文件入口。

系统分享只接收来源应用交付的数据，不代表可读取来源应用的整个页面或继承其登录状态。复制、粘贴由用户主动触发，不做无提示剪贴板监控。

PC 插件在用户触发并授予必要权限后，提取当前页面可访问的内容。登录态留在浏览器中，不向服务端上传第三方账号 Cookie。登录后能够浏览不代表插件一定能够完整提取，具体站点按样本验证。

### 4.2 个人化沉淀流程

- 用户可在保存时或之后填写“为什么保存”“关联项目”“适用条件”。
- AI 可提出关联项目或标签建议，未经用户确认不能当作用户事实。
- 使用后允许记录“未尝试 / 已尝试有效 / 部分有效 / 无效”和说明。
- 系统保留验证时间、相关项目与用户原话，避免把一次成功推广成通用规律。
- 新资料可提示与旧资料相似或观点冲突，由用户判断是否合并；不自动覆盖历史结论。

### 4.3 App 内检索与问答

用户可通过关键词、自然语言、知识域、项目和时间查找资料。结果优先展示相关证据、个人备注和验证记录，支持打开完整资料。

问答以用户资料库为默认来源。没有足够证据时明确告知；首版不静默混入公网搜索结果。后续接入联网搜索时，应明确区分个人资料与互联网来源。

### 4.4 Agent 使用流程

1. 用户创建 Agent 连接，选择允许访问的知识域，查看接入说明。
2. 用户配置 MCP，并按所用客户端加载配套 Skill 或调用说明。
3. 用户明确要求“查我的知识库”，或 Agent 按配置规则在任务相关时调用。
4. 服务端在授权范围内检索，返回证据片段、个人上下文和适用条件。
5. Agent 必要时获取更完整证据，再决定是否采用。
6. App 展示调用时间、客户端及访问资料；用户可随时撤销连接。

Skill 描述何时检索、如何引用、如何处理无结果；MCP 提供实际工具，后端负责检索和授权。Skill 文件本身不存放用户知识或密钥。

### 4.5 首版页面

| 页面 | 主要用途 |
| --- | --- |
| 收集箱 | 最近采集内容、处理进度、失败或待补充项目 |
| 知识库 | 按项目、知识域、标签查看资料与经验 |
| 搜索与提问 | 检索结果、回答、证据来源和范围筛选 |
| 资料详情 | 原始内容、提取文本、知识卡、个人备注、验证记录 |
| 连接与设置 | Agent 授权、调用记录、上传额度、导出与删除 |
| PC 插件面板 | 账户连接、页面/选中片段预览、知识域/项目选择、可选备注、保存与同步状态 |

## 5. 详细需求与验收口径

### FR-01 内容接收与保存（P0）

- 支持文本、URL、图片、PDF、音频，以及本 App 录音。
- 分享文案含多个链接时让用户选择或确认批量导入，不静默只保留首个。
- 分享入口轻量保存，OCR、转写和 AI 处理不阻塞分享界面。
- 离线时在本机保留待上传内容，联网后继续；退出重进仍可看到任务。
- 上传前显示文件类型和大小限制；限制值在试验完成后确定并配置。
- 分享文件只有临时访问权限时，先复制到 App 可管理的存储再确认已保存。

**验收**：支持格式在正常、离线、取消上传、重启等场景下不静默丢失；用户能区分本机保存与云端保存。

### FR-02 解析、完整性与补充（P0）

- 网页提取标题、作者（如可获得）、正文、图片引用及原链接。
- 图片保留原图与 OCR 文本；PDF 片段保留页码；音频片段保留起止时间。
- 仅拿到登录页、验证码页、标题或简介时，不标记为全文解析成功。
- 原始分享 URL 保留必要参数；另存规范化 URL 用于去重，避免清洗参数破坏访问能力。
- 用户可把截图、文字或文件补充到已有资料，不必新建无关联条目。
- 解析失败可重试；重复失败进入待处理，不无限请求外部站点。

**验收**：每条资料显示内容覆盖情况；失败仍保留用户原输入；不可访问资料不会被 AI 补写成“全文”。

### FR-03 个人上下文与知识卡（P0）

知识卡建议字段：标题、摘要、关键观点或步骤、涉及问题、适用条件、限制、关联项目建议、证据引用。与资料不适用的字段允许为空，不强行生成。

个人字段独立保存：收藏原因、用户备注、项目归属、验证状态、验证说明、验证时间。

- 明确标记字段由用户填写、AI 推断或来源原文提取。
- 原文片段支持回看；AI 重新处理不能覆盖用户手写备注。
- 资料默认处于未验证状态，收藏不等于认可，AI 摘要不等于事实核验。
- 编辑后保留必要版本信息，既有引用不应悄悄指向含义变化后的内容。

**验收**：用户能纠正知识卡；可区分来源观点与个人经验；核心结论有证据或明确标为个人备注。

### FR-04 搜索与资料库问答（P0）

- 检索原文、OCR、转写、个人备注及知识卡，不能只检索摘要。
- 同时考虑术语匹配、语义相关性、项目约束和验证记录。
- 用户验证过的内容可增加排序权重，但不应压过明显不相关的任务条件。
- 返回资料标题、相关片段、来源类型、项目、验证状态与引用入口。
- 证据不足、资料冲突、正文缺失时明确说明，不输出伪造引用。
- 音频可跳转到对应时间；PDF 可定位页码；图片可回到原图；文本可定位片段。

**验收**：以包含精确术语、模糊描述、项目约束及无答案问题的评测集检验；回答引用可实际打开且支持对应结论。

### FR-05 Agent 只读接入（P0）

| 工具 | 输入概念 | 返回概念 |
| --- | --- | --- |
| `search_knowledge` | 查询、可选任务上下文、可选项目/知识域过滤、结果数 | 匹配条目、证据片段、个人上下文、适用条件和来源 |
| `get_evidence` | 证据 ID、可选上下文窗口 | 原文片段、位置、资料版本、个人备注与验证状态 |
| `get_source` | 资料 ID | 标题、作者、来源链接、覆盖情况、允许访问的内容入口 |

`search_knowledge` 返回：匹配条目、证据 ID、片段、相关个人上下文、适用条件、来源和验证状态。以上为概念契约，具体协议在技术设计中定义。

- 用户身份从连接凭证解析，不能接受 Agent 自报用户 ID 作为授权依据。
- `scope` 或项目参数只可缩小已授权范围，不能扩大权限。
- 证据和资料详情接口逐次校验权限，不能仅在搜索阶段过滤。
- 首版工具不提供写入、删除、批量全库导出或执行外部动作。
- 返回片段受长度限制；完整资料按需获取，避免无差别注入上下文。
- 提供授权失效、资料不存在、解析待完成、请求过量等明确错误状态。
- 外部资料始终作为数据处理，不允许资料中的“指令”改变 Agent 权限或触发工具执行。

**验收**：至少一个目标客户端完成“检索 → 查看证据 → 引用解决任务”；撤销后新请求被拒绝；越权直接读取证据测试通过。

### FR-06 权限、删除与数据控制（P0）

- 新知识域默认不对外部 Agent 开放；用户明确授权后才可访问。
- 已授权知识域新增资料会进入其授权范围，界面必须明确说明这一继承规则。
- 标记为“仅 App 内可见”的资料不进入外部 Agent 检索与详情返回。
- 提供独立连接撤销及调用记录，不把完整工作代码、凭证或查询上下文写入常规日志。
- 删除资料后立即停止检索与读取，异步清除原文件、派生卡片、索引和缓存中的相关内容。
- 移动资料至其他知识域后按新权限生效，旧授权不能继续访问。
- 用户可导出自己的资料元数据、备注、提取内容及已有原文件；失败链接不能伪装成完整导出。
- 授权页面说明数据将返回给选定 Agent；撤销只能阻止后续读取，不能收回 Agent 已接收的内容。
- 使用云端 OCR、转写或模型时，向用户明确处理方及数据用途；具体供应商待选型。

**验收**：跨用户、跨域、移动、删除、撤销、缓存等路径均不能返回未经授权内容；删除清理具备可观察状态。

### FR-07 重复与使用反馈（P0）

- 结合来源标识、规范化 URL 和文件摘要识别重复；识别到重复时允许打开原资料或追加备注。
- 不把不同用户内容做未经授权的合并；相似观点仅提示，不能自动覆盖。
- 用户能记录一次使用结果，并将外部资料与该条个人实践记录关联。
- 统计检索后打开证据、标记有用和新增验证记录，不能把工具调用次数等同于问题已解决。

### FR-08 PC 浏览器插件采集（P0）

- 首版建议支持 Chrome / Edge，具体版本范围在 PoC 中确定；其他浏览器后续评估。
- 插件连接用户自己的产品账户，与手机端共用知识域、项目、资料和权限规则。
- 提供“保存页面正文”和“保存选中片段”两种操作；片段保留来源链接与页面标题，并标记为部分内容。
- 保存正文时提取当前页面可访问的文字和图片引用，保留标题、来源、采集时间及采集方式；用户可查看预览。
- 登录后页面以本机提取内容为准，后端不要求重新登录来源站点；不上传 Cookie、密码、表单输入或整个浏览器历史。
- 不默认采集其他标签页，不后台遍历站点，不绕过权限、验证码或付费限制。
- 折叠、分页、懒加载、受限框架和嵌入媒体可能导致内容不完整，应说明覆盖情况，允许用户展开后重新采集或补充内容。
- 图片仅得到链接时不得宣称图片已归档；下载失败保留状态，并允许补充本地图片。
- 正文无法提取时仍可保存链接与备注，不能用标题替代正文成功状态。
- 保存时可选知识域、项目及备注；重复链接遵循 FR-07，可追加片段或补充已有资料。
- 上传失败或离线时持久保存待上传任务，浏览器恢复后重试；本机暂存与云端保存清晰区分。
- 退出账户或切换账户时，原账户待上传任务不得进入新账户；同步前重新校验账户和目标知识域权限。

**验收**：在目标浏览器测试公开页面、用户已登录页面、选中片段、无正文页面、离线重启和账户切换；云端保存后手机端可见，授权 Agent 可检索且证据可回看；未授权 Agent 不可访问。

## 6. 处理状态与异常体验

处理阶段与内容覆盖情况分别保存，避免一个“成功”掩盖正文缺失。

| 维度 | 状态 |
| --- | --- |
| 上传 | 本机已保存、上传中、云端已保存、上传失败 |
| 处理 | 排队、解析中、整理中、可使用、待补充、处理失败 |
| 内容覆盖 | 仅链接、部分文本、已提取正文、含 OCR、含音频转写 |

“已提取正文”只表示技术提取结果，不保证原站内容毫无遗漏；有明确缺失时必须标注。音频转写不代表完成视频画面理解。

| 异常 | 用户体验 |
| --- | --- |
| 链接需要登录或出现验证码 | 保留链接，提示补充文字、截图或文件；不索取平台 Cookie |
| 原文删除、失效 | 已存内容仍可查看，注明来源当前不可访问 |
| OCR / 转写失败 | 保留原素材，允许重试或用户修正 |
| 文件过大、不支持或加密 | 在可检测时尽早提示，并说明处理方式 |
| AI 服务超时 | 原始内容和已解析文本可用，整理任务独立重试 |
| 上传、处理重复触发 | 幂等处理，避免重复条目与重复计费 |
| 问答无相关结果 | 明确返回无充分依据，可建议补充条件 |
| Agent 权限失效 | 返回明确授权错误，不尝试扩大范围 |

## 7. 数据模型建议

| 对象 | 主要职责 |
| --- | --- |
| 用户与知识域 | 所有权、资料范围和分类边界 |
| 项目上下文 | 用户目标、约束、背景；可关联多个资料 |
| 资料 | 原始输入、来源、文件、覆盖情况、所属知识域 |
| 内容片段 | 可检索文本、稳定 ID、版本、页码或时间位置 |
| 知识卡 | AI 提炼结果与对应证据，不替代原始资料 |
| 个人经验记录 | 用户备注、实践结果、适用项目与验证时间 |
| 处理任务 | 状态、失败原因、重试次数、耗时与资源用量 |
| Agent 连接 | 连接身份、授权范围、有效期和撤销状态 |
| 调用记录 | 调用时间、工具、返回资料标识、结果状态 |

原始资料和个人输入是可持久保存的主体；切片、向量和部分 AI 结果可重建。更新原文、人工纠正或切片规则变化时，需要保留版本对应关系。

## 8. 技术落地建议

### 8.1 最小架构

手机 App 与 PC 浏览器插件（首版并列入口）→ 业务 API → 原始文件存储与关系数据库 → 异步解析/整理任务 → 检索服务 → App 问答与 MCP。

初期采用模块化业务服务配独立任务进程，不先拆分大量微服务。账户、资料、权限与删除策略由自有业务层统一维护。

### 8.2 候选选型

| 层次 | 候选方向 | 决策依据 |
| --- | --- | --- |
| 手机端 | Flutter 或 React Native，分享扩展采用必要的原生实现 | 分享生命周期、文件上传、团队经验 |
| PC 插件 | Chrome / Edge 扩展，用户触发的页面内容提取与本地待上传队列 | 浏览器权限、页面适配、账户连接和同步恢复 |
| 业务后端 | FastAPI 或 NestJS | 团队维护能力与解析任务集成 |
| 存储 | PostgreSQL + 对象存储 | 所有权、版本、授权与原始文件管理 |
| 检索 | 中文关键词检索 + 向量检索 + 重排序 | 中文术语、代码、混合语言实际召回效果 |
| 任务处理 | 队列和独立 Worker | 幂等、重试、任务恢复、限额 |
| 文档 / 图片 | Docling、PaddleOCR 或云服务候选 | 中文、表格、截图版式与单次成本 |
| 音频 | faster-whisper 或云端转写候选 | 普通话、术语、时间戳、耗时与成本 |
| 网页 | 通用正文提取 + 按站点适配 | 获取完整性、维护成本与授权边界 |
| Agent | 远程 MCP + 授权层 + 客户端调用说明 / Skill | 客户端兼容性、权限隔离、撤销行为 |

PostgreSQL 默认全文检索不等于已经满足中文检索，需要测试中文分词或补充检索实现。模型、框架、云供应商和认证协议细节在 PoC 后确定。

### 8.3 ReMe 的角色

参考其文件可读性、混合检索、来源定位、知识演进及 Agent 接口。评估是否局部复用，不直接假定它具备移动采集、云端多用户隔离、权限和同步能力。引入前核对当前版本、许可证与依赖，并通过接口解耦。

### 8.4 必须提前覆盖的工程问题

- 用户隔离与权限过滤覆盖数据库、向量索引、缓存和文件下载链接。
- 外链抓取限制为允许的协议及公开地址，重定向后重新检查，防止访问内网资源。
- 文件类型校验、大小/时长限制、解析超时和恶意文件隔离。
- 内容及凭证分开存储，密钥不进入客户端包、Skill 文件或日志。
- 来源中的提示词注入不能修改授权、检索范围或执行指令。
- 删除与权限变化使索引、缓存同步失效；下载链接使用短期授权。
- 长任务可恢复、可取消，失败不重复消耗同一项处理额度。

## 9. 可行性与关键问题

| 问题 | 判断 | 首版措施 / 验证方式 |
| --- | --- | --- |
| 私有资料和文件解析 | 技术可行，质量因格式而异 | 固定支持清单，按真实样本验证 |
| 国内社交平台全文获取 | 不确定且需持续维护 | 链接先收下，逐站验证，提供用户补充路径 |
| PC 当前页面采集 | 可验证实现，仍受页面结构与权限限制 | 用户主动采集；测试登录页、懒加载、选中片段和图片归档，明确覆盖范围 |
| 公开搜索已经足够 | 核心产品风险 | 比较纯联网 Agent 与加入个人上下文后的任务结果 |
| 用户不愿补备注 | 可能削弱差异化 | 备注可选、语音快捷输入；测试零备注与轻备注两种路径 |
| 没有积累时价值弱 | 冷启动问题 | 新用户围绕一个正在做的项目导入少量真实资料 |
| AI 提炼错误 | 会影响后续建议 | 保留原证据，标记推断，支持修正和版本追踪 |
| 检索出相似但不适用方案 | 仅语义检索不足 | 保留约束、时间、项目和验证记录，加入反例评测 |
| Agent 不主动调用 | 取决于客户端与任务 | 提供显式调用和清晰触发规则，单独测量调用率 |
| Agent 已接收内容无法收回 | 系统边界 | 授权前告知，默认小范围只读访问 |
| 音视频处理成本高 | 随时长增长 | 先音频、后视频，设置可见额度并记录真实成本 |
| 资料过时或相互矛盾 | 长期知识库常见问题 | 显示来源时间与验证时间，保留冲突，不自动裁定 |
| 企业资料进入个人产品 | 依赖实际场景与组织政策 | 试点使用用户有权处理的资料，正式上线前确定政策和部署边界 |

平台规则、数据处理、模型服务条款及商业使用边界需在供应商和上线地区明确后专项核对。此前调研文档不构成平台授权或法律结论。

## 10. 验证计划与验收指标

以下数值是建议的试点目标，不是已测结果或服务承诺。

### 10.1 阶段 A：技术与输入验证

准备 30～50 条经授权的真实样本，覆盖普通网页、目标国内平台分享链接、截图、文本 PDF、扫描 PDF、音频、不可访问链接和重复内容；PC 插件样本须包含已登录页面、选中片段、动态加载页面及手机端重复保存同一链接的情况。

逐项记录：来源应用交付的数据、正文完整性、是否需要登录、图片/页码/时间位置是否保留、耗时、成本和失败补充步骤。

退出条件：明确 P0 支持列表及限制；移动分享和 PC 插件各有一条不依赖国内平台全文解析的完整流程可运行；不以“接口返回成功”代替内容质量验收。

### 10.2 阶段 B：最小产品闭环

交付手机采集、PC 浏览器插件、跨端同步、资料详情、个人备注/项目、检索、带引用问答、只读 MCP、知识域授权与删除。

| 指标 | 建议目标 / 测量方法 |
| --- | --- |
| 已声明支持的本地输入处理成功率 | ≥95%；用冻结样本集测试，失败原因逐项记录 |
| 部分内容和失败状态识别 | 验收集中不得把明确的登录页、错误页或标题摘要标为全文 |
| 搜索相关资料命中 | 有答案的任务集 Recall@5 ≥80%，人工标注相关证据 |
| 引用可定位 | 验收集中所有返回引用均能定位到对应资料版本 |
| 权限隔离 | 跨用户、跨域、已撤销、已删除路径零越权返回 |
| 检索接口延迟 | 小规模试点 P95 ≤3 秒，不含长文提取和模型生成；记录测试环境 |
| 采集体验 | 用户保存时不等待 AI；上传受网络和文件大小影响，显示真实进度 |
| 跨端一致性 | 插件云端保存后手机刷新可见；处理完成后授权 Agent 可检索；重复保存不产生无提示的重复资料 |
| 每条处理成本 | 分网页、图片、PDF 页数、音频分钟记录，首轮实测后制定额度 |

### 10.3 阶段 C：产品价值试点

邀请 5～10 位已有 Agent 使用习惯的用户，围绕真实项目试用约两周。重点观察：

- 是否愿意持续保存资料或个人经验。
- Agent 是否找到过用户已经忘记但实际有用的资料。
- 个人备注、约束或验证记录是否改变了方案选择。
- 是否减少重复说明项目背景、重复寻找案例的时间。

对同类任务比较三种条件：仅联网搜索；联网搜索加收藏原文；联网搜索加个人上下文。使用相同 Agent 和尽量一致的任务条件，记录结果是否被采用、约束是否满足、证据是否正确，不只比较回答长度。

建议继续投入门槛：至少半数活跃试点用户出现一次明确有价值的任务复用，并能指出个人资料或上下文产生的具体作用。若价值主要来自公开文章摘要，应重新评估定位和输入流程。

## 11. 迭代路线与待决策项

### 11.1 路线

1. **PoC**：验证手机分享、PC 插件采集与同步、引用定位、检索及一个 Agent 客户端连接。
2. **首版内测**：交付 P0，完成权限与失败流程验收，开始任务价值试点。
3. **增强版本**：根据试点需求扩展浏览器适配、更多文件类型和平台解析；评估经验回写。

具体排期取决于团队配置、平台适配试验和内测结果，本稿不预设承诺工期。

### 11.2 开发前需要确认

- 正式名称、首批目标人群及第一个要验证的工作场景。
- iOS / Android 的具体开发顺序与团队技术经验；双端为目标，交付先后待定。
- PC 插件目标浏览器版本、账户连接方式、页面适配样本与分发渠道；插件纳入首版范围。
- 首个 Agent 客户端及接入方式。
- 部署方向已于 2026-09-30 确认为本地优先、会员手动多端同步与云端 AI 增值服务；详见[已确认架构决策](../docs/架构决策-本地优先与云端增值服务.md)，同步协议见[实施设计](../docs/实施设计-本地服务同步与AI-v0.2.md)，当前阶段及原 P0 承接见[实施路线](../docs/实施路线-本地优先-v0.2.md)。本文早期流程中的联网自动上传改为用户手动云同步；浏览器向已配对本机服务的队列重试不属于云同步。Mac 阶段不代表完整 P0 交付。
- 首版文件格式、大小、页数、音频时长、存储及处理额度。
- 模型与 OCR/转写供应商、预算和数据处理区域。
- 试点资料来源、标注人员及可接受的检索质量。
- 原文件、备份、调用日志的保留期限和删除完成时限。
